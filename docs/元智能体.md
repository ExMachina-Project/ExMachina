# 元智能体

> 实验性功能：`experiments.metaAgent`（默认关闭）。本文描述元智能体的三职责、数据面、审批流与已知限制。

## 是什么

元智能体（Meta Agent）是「改进系统自身」的智能体：它不直接执行任务，而是**观测运行数据 → 提出改进提议 → 经人工审批应用**。与 Auto Agent（自主做任务）互补：Auto Agent 改变「做了什么」，Meta Agent 改变「怎么做」。

## 三职责

| 职责 | 入口 | 产出 |
| --- | --- | --- |
| 数据聚合 | 周期巡检 / 会话内 meta_observe 工具 | 按个体维度的工具统计（次数/失败率/平均耗时/最近失败）与经验要点现状（7 天窗口） |
| 改进提议 | meta_propose / meta_build 工具 | `[meta]` 前缀审批单（prompt 补段 / adaptation 经验要点 / roster 成员编成 / build 新个体） |
| 构建 | meta_build 工具 | 新个体/组定义草稿落 `[meta]` 审批单，批准后注册 |

另含**轮内元认知反思**（连续工具失败 ≥2 次时触发一次策略反思，注入 replan/redirect/compact 提示到后续循环）。

## 运行方式（双轨）

### 轨一：周期巡检（experiments.metaAgent 开启后）

```
tick（automation.metaIntervalMin，默认 60 分钟）
  → 数据快照（system_observation）
  → META_EVAL_PROMPT 自评「有没有值得改进的点」（保守：不确定 = 不提）
  → 通过则开自主会话（装 meta 工具组）：观测 → 提议（一次巡检最多 2 张单）
```

### 轨二：会话召唤

metaAgent 开启后，主智能体在任意会话内可用 meta_observe / meta_propose / meta_build 三件工具（按需即时观测与提议，无需等巡检周期）。

## 审批流（一切持久改动必须经人）

```
meta_propose / meta_build
  → [meta] <kind> <target>: <rationale> 审批单（meta_json 扩展位存完整提议）
  → 人工批准 → 按 kind 自动应用：
      prompt      组内提示词追加补段（<!-- meta: 时间戳 --> 锚点 + 旧版备份 prompts/history/）
      adaptation  save_adaptation 版本化沉淀（历史版本自动保留，最多 5 版）
      roster      两阶段（全量校验 → 逐 op 应用，中断逆序回滚；≤5 op）
      build       注册新个体（走 agent_manage create 同校验路径）
  → 拒绝 → 受阻回流，不落任何改动
```

保护不变量：

- **内置组保护**：roster/build 对内置组一律拒绝（与 agent_manage 同口径）。
- **主智能体固定**：提议不能更换主智能体（系统指定，不支持换主）。
- **同签名去重**：同 target+kind 已有未决单时拒绝新提议。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `experiments.metaAgent` | false | 总开关（关 = 工具不下发、tick 不巡检、反思钩子不触发） |
| `automation.metaIntervalMin` | 60 | 巡检周期（分钟，最小 5） |

## 已知限制

- 聚合窗口固定 7 天（不可配）。
- roster 单次上限 5 op。
- 轮内反思每轮 1 次、仅连续失败触发（步数/产出占比双阈值待数据积累后拆分）。
- 巡检行动会话限深沿用 unitMaxSteps。
- 提议质量依赖模型判断——审批人应核对 rationale 与数据依据再批准。

## 审计事件

| 事件 | 含义 |
| --- | --- |
| `meta.eval` | 巡检自评结果（ok/act/focus/why） |
| `meta.act` | 巡检行动会话结束（status done/failed） |
| `meta.reflect` | 轮内反思触发（strategy/note/consecutiveFailures） |
| `meta.applied` | 提议应用结果（ok/command） |
