# 协议与契约

面向开发者：语言规范、核心实体、编排契约、REST/WS API、存储布局与扩展点。
字段名一律 camelCase，与 WebUI / CLI / 持久化保持一致。

## 语言规范

- **陈述前缀**：每条陈述以【肯定】【否定】【疑问】【报告】【提案】【警告】【要求】【观测】之一开头；
- **证据分级**：A 直接验证 / B 多源一致 / C 单源或旁证 / D 推断——判断应附等级。

## 核心实体

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| Session | id, title, status, groupId, ledger | 会话归属交互范围（组或 single:id）；ledger = 三账 |
| ChatMessage | sessionId, role(user/orchestrator/unit/system), agentId, statements | statements = 结构化陈述数组 |
| Statement | tag, text, evidenceLevel? | 句式前缀 + 可选证据等级 |
| TaskNode | id, agentIdentifier, title, objective, acceptance, dependsOn, priority, status | DAG 节点；status ∈ pending/ready/dispatched/running/syncing/done/blocked/failed/arbitrating/cancelled |
| TaskGraph | sessionId, nodes, status | 一场会话的任务图 |
| AgentDefinition | name, identifier, domain, tier, description, capabilities, tools, modelHint? | 个体定义 = 数据文件；modelHint = 默认模型提示 |
| GroupMeta | id, name, primary, workspace?, model?, builtin | 组元数据（group.json） |
| LlmProfile | id, name, baseUrl, apiFormat, apiKey, apiKeys[], model, models[], fallback? | 提供商档案；models[] = 模型清单（model + vision/audio 能力开关，空 = 能力未知直通）；fallback = 失败回退档案 |
| SessionLedger | task / evidence / risk | 三账结构（详见下文） |

## 编排契约

### OrchestratorPlan（指挥体规划，强制校验）

```json
{
  "routeLevel": "L0|L1|L2|L3",
  "goal": "用户目标",
  "boundary": { "inScope": ["…"], "forbidden": ["…"] },
  "acceptance": ["可验证的验收口径"],
  "nodes": [{
    "id": "T1", "title": "…", "agentIdentifier": "组内子个体",
    "objective": "…", "acceptance": ["…"], "dependsOn": [], "priority": "P0|P1|P2|P3"
  }],
  "finalAnswer": [{ "tag": "报告", "text": "…" }]
}
```

- L0 = 本机直答（nodes 为空、finalAnswer 必填）；L1 单链；L2 并行；L3 含裁决；
- `agentIdentifier` 只能取自提示词注入的可调度子个体清单；
- 单体交互目标强制 L0（nodes 必须为空）。

### DispatchOrder（派发指令）

任务节点 + 边界 + 输入（上游 SyncReport 摘要 / 个体记忆 / 命中技能指令）+ 工具白名单 + 约束
（`max_steps` 与 `timeout_ms` 由 `automation.unitMaxSteps` 派生：步数 N → 超时 N×30s；
默认 16 步 / 480s，编码类长任务可按需上调）。
主智能体在自定义组内自动追加 `agent_manage` 工具。

### 工具面（function calling 下发的工具）

| 工具 | 能力 | 关键参数 |
|------|------|----------|
| `read` | 读文件（**行号 + offset/limit 分页**）或目录（类型 + 大小清单） | path, offset, limit, maxChars |
| `edit` | **精确编辑**：old_string → new_string（唯一命中校验，多命中报错并列位置） | path, old_string, new_string, replace_all |
| `grep` | 仓库检索（Rust regex，尊重 .gitignore），返回 `文件:行号:内容` | pattern, path, glob, ignoreCase, maxResults |
| `glob` | 按模式列文件路径 | pattern, path |
| `filesystem` | write（整文件）/ mkdir / list | op, path, content |
| `terminal` | 白名单 + 审批闸门；**后台长任务**（background → taskId 轮询/终止） | command, op(run/poll/kill), taskId, background, timeoutSecs |
| `web_search` | 联网搜索（tavily / brave / searxng / custom）；**未配置后端时不下发该工具** | query, maxResults |
| `web_fetch` | 抓网页正文（剥标签脚本，20s / 2MB / 8000 字） | url, maxChars |
| `schedule` | **自主排程**：create/list/remove/enable/disable（cron 或一次性 at，绑定激活组） | op, name, prompt, cron, at, id |
| `browser` | **浏览器自动化**（headless Chrome/Chromium + CDP）：导航、取渲染后正文、执行 JS、截图落盘 | op(open/text/eval/screenshot/close), url, expression, name |
| `agent_manage` | 组内编成管理（仅自定义组主智能体） | op, identifier, … |
| `mcp:<server>:*` | MCP 工具；另有合成工具 `__resource__`（resources/read）与 `__prompt__`（prompts/get） | 依服务器 schema |

**只读工具**（read / grep / glob / web_search / web_fetch）在同一轮内**并发执行**；写工具、MCP 与 browser 按原顺序串行。
工具结果超过 `security.toolOutputSpillChars`（默认 12000 字符）时全文落盘
`.exmachina/tool-output/<时间戳>-<工具>.txt`，回填摘要 + 路径，可用 read 分段回读。

**按能力就绪度动态下发**：`web_search` 在未配置搜索后端时、`browser` 在探测不到浏览器时
**不出现在下发给模型的工具表里** —— 宁可少一个工具，也不让模型调用必然失败的工具。

### 沙箱执行（`sandbox` 配置节）

三档（`sandbox.mode`）：

| 档位 | 行为 |
|------|------|
| `off` | 仅白名单 + 审批闸门（历史行为） |
| `workspace`（默认） | **子进程环境净化**：只透传 `PATH` / `SystemRoot` / `CARGO_HOME` 等运行必需变量，各类 `*_KEY` / `*_TOKEN` / `*_SECRET` 一律不外泄；`HOME` / `USERPROFILE` / `TMP` / `TEMP` 重定向到 `.exmachina/sandbox/` |
| `strict` | 净化之上：**联网类命令**（curl/wget/pip install/npm install/git fetch/clone/pull 等，`sandbox.allowNetwork` 可放行）走审批闸门；前台命令超时收紧到 60s（长活请用后台模式）；Linux/macOS 检测到 `bwrap` 且 `sandbox.useBwrap=true` 时以 bubblewrap 做系统级隔离（根只读、工作区可写、按需 `--unshare-net`） |

`sandbox.memoryMb` > 0 时限制子进程内存：Linux 经 `ulimit -v`，**Windows 经作业对象（Job Object）
的 `ProcessMemoryLimit` / `JobMemoryLimit`**。

Windows 侧另有两项作业对象级加固（`sandbox` 开启即生效，无需额外配置）：

- `sandbox.maxProcesses` > 0 时设 `ActiveProcessLimit` —— 防 fork 炸弹；
- 一律带 `KILL_ON_JOB_CLOSE`：作业句柄一关（命令结束、后台任务被终止、进程退出），
  作业内**整棵进程树**随之终止 —— 命令结束后不会留下游离的孙进程。
  句柄不可得或子进程已在别的作业里（嵌套作业不被允许时）静默降级为无作业执行，不阻断命令。

### 生命周期钩子（hooks）

`hooks.preTool` / `hooks.postTool` / `hooks.onRunEnd` 为可执行命令列表（逗号分隔），
在生效工作区内执行，环境变量注入上下文：`EXM_HOOK` / `EXM_TOOL` / `EXM_AGENT` / `EXM_ARGS`（json，截断）/
`EXM_WORKSPACE` / `EXM_TOOL_OK`（post）/ `EXM_OUTPUT`（post，截断）/ `EXM_RUN_STATUS`（runEnd）。
**preTool 非零退出 = 拦截本次工具调用**（原因回填给模型并计入审计）。

### SyncReport（子个体回流，强制校验）

```json
{
  "sourceAgent": "identifier（运行时强制校正）",
  "taskNodeId": "T1",
  "status": "done | in_progress | blocked | need_arbitration",
  "statements": [{ "tag": "报告", "text": "…", "evidenceLevel": "A" }],
  "summary": "结论摘要（上游不读原文也能决策）",
  "evidence": [{ "level": "A|B|C|D", "kind": "code|config|log|test|command|doc|userInput|reasoning", "ref": "…", "note": "…" }],
  "risks": [{ "text": "…", "severity": "low|mid|high", "revertPath": "（可选）" }],
  "blockers": [{ "reason": "…", "unblockCondition": "…" }],
  "conflicts": [{ "parties": ["a", "b"], "point": "…", "levels": { "a": "A" }, "suggestion": "…" }],
  "nextSuggestion": { "handoffTo": "（可选）", "appendNodes": "（可选）" },
  "confidence": 0.0
}
```

校验失败自动重写（≤2 次），仍失败升级裁决。`statements` 至少一条、`confidence ∈ [0,1]`、
冲突必须显式保留在 `conflicts` 而不得静默覆盖。

## REST API（前缀 /api）

| 分组 | 端点 |
|------|------|
| 会话 | GET/POST `/sessions`；GET/DELETE `/sessions/:id`；GET `/sessions/:id/messages`；POST `/sessions/:id/chat`（202 受理，WS 推流；body 可带 `images` data URL 数组 = 多模态输入）；GET `/sessions/:id/graph`；GET `/sessions/:id/evidence`；GET `/sessions/:id/events`；GET `/sessions/:id/tokens`（用量：`measured=true` 时为 provider 上报的真实 token，否则字符估算） |
| 检查点 | GET `/checkpoints`（写工具落笔前的自动快照清单）；POST `/checkpoints/restore`（`{path, date?}`，date 缺省 = 最近一份） |
| 编排 | GET `/agents`；GET/POST/DELETE `/agents/:identifier`；PUT `/agents/:identifier/model`；GET/PUT/DELETE `/agents/:identifier/persona`；POST `/agents/:id/optimize` |
| 组 | GET/POST `/groups`；GET/PUT `/groups/active`；DELETE `/groups/:id`；GET `/groups/:id/agents`；POST `/groups/:id/primary`；PUT `/groups/:id/model`；PUT `/groups/:id/workspace`；GET `/groups/:id/overview` |
| 交互目标 | GET/PUT `/target`（mode = group | single） |
| 智能体 | GET/POST `/singles`；DELETE `/singles/:id` |
| 模型 | GET/POST `/llm/profiles`；DELETE `/llm/profiles/:id`；PUT `/llm/active`；POST `/llm/test`；GET/PUT `/llm/capabilities`（全局能力槽位：speech / transcribe / visionRelay / embedding，值 = "档案ID" 或 "档案ID/模型名"） |
| 组设置 | 组级能力模型覆盖：PUT `/groups/:id/capabilities`（speech / transcribe / visionRelay / embedding，空串 = 清除该项跟随全局）；槽位解析顺序 = 组覆盖 → 全局槽位 → 出厂默认 |
| 记忆 | GET/POST `/memory`；POST `/memory/search`；GET `/memory/stats`；POST `/memory/reindex` `/memory/decay` `/memory/render`；DELETE `/memory/:id`；POST `/memory/:id/pin` |
| 平台 | GET/POST `/skills`；DELETE `/skills/:id`；GET/POST `/cron`；PUT/DELETE `/cron/:id`；POST `/cron/:id/run`；GET `/cron/runs`；GET `/approvals`；POST `/approvals/:id/approve|deny` |
| 通道 | GET/POST/PUT/DELETE `/channels`；GET `/channels/status`；POST `/channels/:id/inbound` |
| 配置 | GET/PUT `/config`；GET `/config/schema` |
| MCP | GET `/mcp`（服务器与工具清单）；POST `/mcp/refresh` |
| 语音 | POST `/voice/transcribe`（multipart 字段 audio：webm/mp3/wav → 文本）；POST `/voice/speak` `{text}` → mp3（audio/mpeg） |
| 用量 | GET `/sessions/:id/tokens`（估算与预算） |
| 其他 | GET `/health`；POST `/auth/verify` |

配置了 `authKey` 时，除 `/api/auth/verify` 与静态资源外全部要求 `X-Auth-Key`（或 Bearer）。

## WebSocket 事件（/ws?sessionId=<id>&key=<authKey>）

| 事件 | 载荷要点 |
|------|----------|
| orchestrator.token / unit.token | delta（流式增量；unit 携带 agentId） |
| graph.updated | 任务图全量 |
| dispatch.sent | nodeId, agentIdentifier, order 全量 |
| sync.received | report（summary / confidence / sourceAgent） |
| memory.recall / memory.written | 命中条目 / 写入条目数 |
| arbitration.required | 追加裁决节点 |
| ledger.updated | 三账 |
| run.finished / run.error | 终态陈述 / 错误信息 |
| approval.resolved / cron.finished | 审批与定时任务终态 |

事件同时落 `events` 溯源存储，可回放（WebUI「事件」面板）。

## 存储布局

```
.exmachina/                    # 运行状态（git 忽略）
  config.json                  # 唯一配置事实源（三端共用，热生效）
  memory.md                    # 基础记忆人读视图
  data/                        # Store + MemoryStore + CronStore
agents/                        # 编成数据（不是代码）
  group.json                   # 内置默认组元数据
  definitions/ prompts/ playbooks/ personas/ skills/
  groups/<gid>/                # 自定义组（同构布局 + group.json）
  singles/                     # 智能体（machina 预置）
webui/dist/                    # WebUI 构建产物（网关托管）
```

## 扩展点

- **新渠道**：消费同一 REST/WS 契约即可接入（WebUI / Telegram / QQ 官方机器人 / NapCat / Discord /
  Slack / Matrix / Webhook 皆此模式）。
  桥接类平台（webhook / qq / wechat）把消息 `POST /api/channels/:id/inbound`，回复走 replyWebhook 或事件流；
  telegram（长轮询）/ qqbot（开放平台 WS）/ napcat（OneBot 11 正向 WS）/ discord（Gateway WS）/
  slack（Socket Mode）/ matrix（Client-Server API /sync 长轮询）为网关内置适配器，收发直达原会话。
  通道实体含 `allowedChats[]`（会话白名单，空 = 不限）与 `config{}`（平台扩展配置：
  qqbot → appId / appSecret / sandbox；napcat → url / token；slack → appToken；
  matrix → homeserver。discord / slack / matrix 的 bot token 或 access token 走顶层 `token`）。
  **密钥脱敏**：通道接口（列表 / 创建 / 更新响应）对顶层 `token`/`secret` 与平台敏感 `config` 键
  （qqbot.appSecret、napcat.token、slack.appToken）掩码回显（`***已配置***`）；
  更新时掩码 = 沿用旧值、空 = 清除。
  **运行状态**：`GET /api/channels/status` 返回 `{ <通道ID>: { state: "ok"|"error", detail, at } }`，
  由内置适配器在连接 / 断开 / 出错时覆盖上报（桥接类无运行时不产生条目）；通道删除 / 停用即清除。
  更新通道（PUT）body 无须携带 `id`（以路径参数为准）。
  六个内置适配器共用 `platform::ChannelRun`（组绑定 → 会话键 `channel:<通道ID>:<会话键>` 复用 →
  订阅事件 → 执行 → 组还原）与 `spawn_reply`（收束陈述回帖），平台差异只在发送闭包内。
- **新模型协议**：实现 `LlmProvider` trait（`chat` + `stream`，SSE 增量经 channel 发出），
  或在 `provider.rs` 的格式分支中加一种 URL / 鉴权 / 解析规则（现含 openai / anthropic / gemini / azure）。
- **新技能包**：`agents/skills/<id>.json`（id/name/triggers/instructions），热装载，
  任务目标命中触发词即随派发注入。
- **新个体**：`agents/definitions/<identifier>.json` + `prompts/<identifier>.md`（或组内同构目录），热装载即生效。
