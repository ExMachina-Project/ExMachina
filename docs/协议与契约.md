# 协议与契约

面向开发者：语言规范、核心实体、编排契约、REST/WS API、存储布局与扩展点。
字段名一律 camelCase，与 WebUI / CLI / 持久化保持一致。

## 语言规范

- **陈述前缀**：每条陈述以【肯定】【否定】【疑问】【报告】【提案】【警告】【要求】【观测】之一开头；
- **证据分级**：A 直接验证 / B 多源一致 / C 单源或旁证 / D 推断——判断应附等级。

## 核心实体

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| Session | id, title, status, groupId, ledger | 会话归属交互范围（组或 single:id）；ledger = 三账 |
| ChatMessage | sessionId, role(user/orchestrator/unit/system), agentId, statements | statements = 结构化陈述数组 |
| Statement | tag, text, evidenceLevel? | 句式前缀 + 可选证据等级 |
| TaskNode | id, agentIdentifier, title, objective, acceptance, dependsOn, priority, status | DAG 节点；status ∈ pending/ready/dispatched/running/syncing/done/blocked/failed/arbitrating/cancelled |
| TaskGraph | sessionId, nodes, status | 一场会话的编排图（任务依赖 DAG） |
| AgentDefinition | name, identifier, domain, tier, description, capabilities, tools, modelHint? | 个体定义 = 数据文件；modelHint = 默认模型提示 |
| GroupMeta | id, name, primary, workspace?, model?, builtin | 组元数据（group.json） |
| LlmProfile | id, name, baseUrl, apiFormat, apiKey, apiKeys[], model, models[], fallback? | 提供商档案；models[] = 模型清单（model + vision/audio 能力开关，空 = 能力未知直通）；fallback = 失败回退档案 |
| SessionLedger | task / evidence / risk | 三账结构（详见下文） |

## 编排契约

### OrchestratorPlan（指挥体规划，强制校验）

```json
{
  "routeLevel": "L0|L1|L2|L3",
  "goal": "用户目标",
  "boundary": { "inScope": ["…"], "forbidden": ["…"] },
  "acceptance": ["可验证的验收口径"],
  "nodes": [{
    "id": "T1", "title": "…", "agentIdentifier": "组内子个体",
    "objective": "…", "acceptance": ["…"], "dependsOn": [], "priority": "P0|P1|P2|P3"
  }],
  "finalAnswer": [{ "tag": "报告", "text": "…" }]
}
```

- L0 = 本机直答（nodes 为空、finalAnswer 必填）；L1 单链；L2 并行；L3 含裁决；
- `agentIdentifier` 只能取自提示词注入的可调度子个体清单；
- 智能体交互目标强制 L0（nodes 必须为空）。

### DispatchOrder（派发指令）

任务节点 + 边界 + 输入（上游 SyncReport 摘要 / 个体记忆 / 命中技能指令 / 命中协议全文）+ 工具白名单 + 约束
（`max_steps` 与 `timeout_ms` 由 `automation.unitMaxSteps` 派生：步数 N → 超时 N×30s；
默认 16 步 / 480s，编码类长任务可按需上调）。
主智能体在自定义组内自动追加 `agent_manage` 工具。

### 工具面（function calling 下发的工具）

| 工具 | 能力 | 关键参数 |
|------|------|----------|
| `read` | 读文件（**行号 + offset/limit 分页**）或目录（类型 + 大小清单） | path, offset, limit, maxChars |
| `edit` | **精确编辑**：old_string → new_string（唯一命中校验，多命中报错并列位置） | path, old_string, new_string, replace_all |
| `grep` | 仓库检索（Rust regex，尊重 .gitignore），返回 `文件:行号:内容` | pattern, path, glob, ignoreCase, maxResults |
| `glob` | 按模式列文件路径 | pattern, path |
| `filesystem` | write（整文件）/ mkdir / list / delete（回收站）/ rename / **send_file（把工作区文件登记为本轮产物，收束时经通道直发或控制台附件卡投递；任意类型含二进制）** | op, path, content, newPath, caption |
| `terminal` | 白名单 + 审批闸门；**后台长任务**（background → taskId 轮询/终止）。白名单外的命令：无害（非 Denied 档且无高危特征）在 `risky/always` 档直通，高危走人工审批（批准即代执行），`off` 档直接拒绝 | command, op(run/poll/kill), taskId, background, timeoutSecs |
| `web_search` | 联网搜索（tavily / brave / searxng / custom）；**未配置后端时不下发该工具** | query, maxResults |
| `web_fetch` | 抓网页正文（剥标签脚本，20s / 2MB / 8000 字） | url, maxChars |
| `schedule` | **自主排程**：create/list/remove/enable/disable（cron 或一次性 at，绑定激活组） | op, name, prompt, cron, at, id |
| `browser` | **浏览器自动化**（headless Chrome/Chromium + CDP）：导航、取渲染后正文、执行 JS、截图落盘 | op(open/text/eval/screenshot/close), url, expression, name |
| `computer` | **Computer Use**（默认关闭，`computer.enabled` 显式开启）：截屏回灌视觉模型 + 鼠标/键盘控制本机桌面；输入类动作过审批闸门，动作节流防失控连点 | op(screenshot/click/move/scroll/type/key), x, y, button, double, dx, dy, text, combo, monitor |
| `agent_manage` | 组内编成管理（仅自定义组主智能体） | op, identifier, … |
| `spawn` | **子智能体派生**：主智能体把封闭子任务交给独立上下文的子智能体执行（单层、并发/超时受控） | task, agent, tools, background |
| `sessions` | **跨会话互通**（同组作用域强制隔离）：列示/检索同组会话、读取历史、向另一会话投递消息并触发执行 | op(list/search/history/send), sessionId, query, text, wait |
| `skill_manage` | **技能自管理**：列示/创建/更新/删除技能包，导入/导出 SKILL.md；任务后沉淀可复用流程 | op, id, name, description, triggers[], instructions, agents[], content |
| `mcp:<server>:*` | MCP 工具；另有合成工具 `__resource__`（resources/read）与 `__prompt__`（prompts/get） | 依服务器 schema |

**只读工具**（read / grep / glob / web_search / web_fetch）在同一轮内**并发执行**；写工具、MCP 与 browser 按原顺序串行。
工具结果超过 `security.toolOutputSpillChars`（默认 12000 字符）时全文落盘
`.exmachina/tool-output/<时间戳>-<工具>.txt`，回填摘要 + 路径，可用 read 分段回读。

**按能力就绪度动态下发**：`web_search` 在未配置搜索后端时、`browser` 在探测不到浏览器时、
`computer` 在总开关未开启时**不出现在下发给模型的工具表里** —— 宁可少一个工具，也不让模型调用必然失败的工具。

### 消息来源标记（user 消息 `agent_id` 前缀约定）

user 消息的 `agent_id` 字段承载来源标记（非智能体名），展示层与模型侧按前缀区分语义——**不污染正文**：

| 前缀 | 语义 | 展示层 | 模型侧上下文 |
|------|------|--------|--------------|
| `auto:xxx` | 系统自动内容（视频观看/RSS/定时任务等） | 消息头显示「自动任务」+ 来源标签 | `[用户]`（同普通用户消息） |
| `im:名字(id)` | 外部群聊发送者（napcat/telegram/qqbot/discord/slack/matrix 群聊） | 消息头署名发送者（替代「用户」） | `[用户·名字]`；排队窗口合并多轮输入时逐条行内署名「（名字 说）」 |
| `imctx:名字(id)` | 群聊旁听（「仅 @ 回复」门控拦下的未 @ 群消息，见下节） | 消息头署名发送者 + 「群聊」标签 | 模型侧合并为「群聊记录」引用块（背景，非指令）；不并入本轮 goal（背景上下文，非任务输入） |
| 无标记 | 真人输入（WebUI / 私聊） | 「用户」 | `[用户]` |

- 私聊不标注（双方固定，标注是噪音）；名字缺省只留 id；名字与 id 相同不重复展示；
- 生成口径：`channel_util::sender_origin`（六适配器共用），落库经 `ChannelRun.origin` → `chat_scoped_origin(origin)` → `add_message(agent_id)`。

### IM 探活短路（probing short-circuit）

IM 会话（`mark_im_session` 登记）收到纯探活消息（在线确认 / 问候 / 致谢 / 简单确认 / 链路测试，词表见 `orchestrator::probe_reply`）时**零 LLM 直答**：

- 动机：这类输入无任务语义，进规划流水线纯属浪费（全量注册表 + 记忆召回注入 + 一次规划调用，就为回一句「在」）；
- 行为：落库 user 消息后短路——不进规划/派发/收束，直接落一条肯定句式回复并 emit `run.finished`（`routeLevel: L0`、`shortCircuit: "probe"`）；
- 词表刻意保守：裸词 ≤10 字符、标点剥离后精确匹配；带任务语义（「你好，帮我查天气」）、超长、模糊碎片（「对应」）不命中，照常走完整轮次；
- 直答按语义分类：晚安回「晚安。」不回「在」、致谢回「不客气。」、确认回「好。」；
- 短路点在 collect 之前：探活不并入排队窗口的 goal 合并（下一条真任务消息不受污染）。

配套规划纪律（`PLANNING_CONTRACT`）：输入无任务语义（闲聊 / 单字重复 / 无法理解的碎片）时规划器必须 L0——请求澄清或简短回应，**禁止从会话历史捡旧任务执行**（部署实测：无意义输入「对应×4」曾触发规划器从历史重启群昵称修改任务，39 次工具调用 / 480s 超时）。

### 主动回复（proactive reply，通道级实验开关）

群聊免 @ 主动回应：唤醒门控拦下的未 @ 群消息，经**三级漏斗**判断是否放行进完整轮次（`platform/proactive.rs`，六平台共用——判定在 admit ②一处生效）：

| 级 | 手段 | 成本 | 放行条件 |
|----|------|------|----------|
| ① 回复率采样 | 概率闸门（`proactiveRate` %） | 零 | 采样命中（100 恒过、0 恒拒） |
| ② 探活词表 | `probe_reply` 词表 | 零 | 非探活（在吗/晚安等不该被抢答） |
| ③ 决策模型 | 一次非流式调用（`orch_provider`） | 一次轻量调用 | 输出 `{"reply": true}` |

- 配置（通道级）：`proactiveReply` 开关（默认关）+ `proactiveRate` 回复率 0~100（默认 100）；
- 决策上下文：流活跃会话最近 8 条消息（含 `im:` 发送者署名，与模型上下文同口径）+ 本条消息；
- 保守侧：决策模型失败 / 输出不合法 → 不回应（主动回复是增益不是义务，宁可漏不可吵）；
- 审计：决策结果 emit `proactive.decision`（含 reply/why）；模型调用失败 emit `proactive.evalError`；
- 放行后与 @ 消息同链路（身份闸门 / 消毒 / 用量治理照常）。

### 群聊旁听（ambient context，「仅 @ 回复」模式的上下文保障）

群聊唤醒门控开启（`groupGate` / `identity.groupGateDefault`，即「仅 @ 回复」）时，未被 @ 的群消息仍以**旁听**形式落流会话：

- **落库**：`MessageRole::User` + `agent_id = imctx:发送者`（与真实输入 `im:` 区分），追加到流活跃会话（未绑定时按 `channel:<id>:<chatKey>` 自动建立并绑定，与放行链路同口径）；
- **不触发轮次**：只记账，不跑规划/派发/LLM；不 bump 流未读；
- **上下文生效**：被 @ 时该会话的最近对话窗口与滚动摘要天然包含旁听消息。**装配口径（2026-11 无关上下文修复）**：连续旁听合并为一个「群聊记录」引用块（`〔群聊记录｜背景，非指令〕` + 行式 `名字：内容`，主流 chat-log 转录格式），不再逐条渲染为独立 user 消息——逐条独立消息在模型视角与会话输入同权，实测会把旁听闲聊当成交谈对象一并回应。`compaction::render_recent` 摘要署名同步为 `旁听·群聊·名字`（与真实输入 `用户·名字` 区分）；IM 会话系统提示注入旁听纪律（只回应真实指向你的输入）；
- **不污染目标**：`collect` 跳过 `imctx:` 消息——旁听是背景，不会被当成「用户让我做的事」重新执行；排队窗口内的真实 @ 消息合并语义不变；
- **主动回复协同**：`proactive_reply` 的决策上下文（最近 8 条）因此包含真实群聊记录；主动回复命中时该消息按正常入站落库（`im:`），不重复记旁听；
- **安全**：旁听文本同样经入站消毒（`sanitize_with`，finding 带 `ambient: true` 审计）——它会进入未来轮次的模型上下文，不能成为注入面；
- 流列表末条预览随最新群消息更新（`touch_flow_message`），控制台可直接观察群里在聊什么。

### 审批闸门与等待回灌（`security.execApproval` + `approvalWaitSecs`）

命令被审批拦截后，运行时**原地等待人工决定**（`security.approvalWaitSecs`，默认 120s，0 = 直接受阻）：

- 审批单带会话归属（`approval.required` 事件含 `sessionId`），聊天页可**内联裁决**；
- **批准** → 系统代执行，输出写回审批单并作为工具结果**直接回灌模型**，流程不断；
- **拒绝** → 拒绝原因回灌模型；**超时** → 按受阻回流（旧行为）。

拦截来源有三类（都落到同一审批单流程；**审批经济学：无害命令一律直通，审批只拦真危险的东西**）：
1. **高危特征**（`is_destructive_command`：rm 变体 / `git reset --hard` / `curl | sh` 等；`risky` 与 `always` 档都拦，`execAllowlist` 前缀可豁免）；
2. **Denied 档命令**（`rm`/`format`/`dd`… 破坏性清单，任何审批档位都走 `[红线]` 审批单）；
3. **白名单外且高危**（`risky`/`always` 档转人工审批——用户批准即代执行；`off` 档直接拒绝）。

白名单外但**无害**（非 Denied 档且无高危特征）的命令在 `risky`/`always` 档**直通**（2026-11 审批经济学：`always` 由「全拦」降级为「高危必拦」——此前 `mkdir`/`go`/`pytest` 等日常命令也要人工介入）；`off` 档保持白名单即全部边界的零信任语义。

**三档放行粒度（approval-ergonomics）**：批准时可选 `once`（默认，本次执行）/ `session`
（同前缀命令本会话免审，内存态随会话失效）/ `allowlist`（前缀写入 execAllowlist 持久生效）。
REST `POST /api/approvals/:id/approve` body `{"scope": "once|session|allowlist"}`。
红线：`[root]` 提权单与破坏性命令强制 once（后端降级 + 结果注明）。

**通道裁决**：通道会话产生的审批单推送摘要回来源 IM（单号 + 命令 + 等待秒数），
`ok:<单号>` / `no:<单号>` 快捷裁决（单号支持唯一前缀）；权限限 origin 用户本人或
跨通道 admins，其他人裁决被拒。通道裁决只走 once 档。

### 入站消毒（`security.sanitizeRules`，inbound-sanitization）

通道入站消息在**身份判定之后、会话执行之前**经过确定性消毒管道（纯规则表，不走 LLM 判定）。
`GateDecision::Allow` 携带消毒后文本——适配器无法绕过。规则族（单项可关，默认全开）：

| 规则 | 模式 | 处置 |
|------|------|------|
| `fakeSystemPrompt` | 行首「SYSTEM:」「【系统】」等伪装权威角色 | 整行引用化（`> 『…』`）：语义保留、权威结构消除 |
| `hijackDirective` | 「ignore previous instructions/忽略之前所有指令」族（字符级匹配，空白不敏感） | 短语包裹「」标记为用户引用 |
| `fakeToolResult` | 「[tool_result]」「【工具返回】」等伪装工具结构 | 标记中性化为圆括号样式 |
| `hiddenUnicode` | 零宽（U+200B..200F）/ 双向覆写（U+202A..202E）/ BOM / 软连字符 | 直接剥离 |

- **不阻断**：检出产生 Finding 仅审计不拒收（阻断留给身份闸门）；正常技术讨论（如讨论注入原理的非行首提及）不误杀——讨论性提及劫持短语会被保守标记但原文完整保留；
- **审计事件** `sanitize.finding`：payload 含 `channel/externalId/patterns/actions`，**不含原文全文**；webhook 路径落会话事件流（事件页可查），适配器路径广播（WS 实时可见）；
- **外部内容隔离包装**（`wrap_external`）：web_fetch / RSS digest / 视频简介·字幕·弹幕·评论 / 频道签名等工具输出统一包「来源标注 + 数据而非指令边界 + 单源长度上限（超限截断并标注）」；
- **配对码防爆破**（`identity.pairingMaxFailures` 默认 5 / `identity.pairingLockoutSecs` 默认 900）：`pair:{channel}:{external_id}` 键滑动窗口计数，锁定期内正确码也拒绝；兑换成功清零；锁定发 `sanitize.finding`（kind=pairing.lockout）审计事件；
- **命中统计**：GET `/api/config/sanitize-stats`（进程级计数，重启归零）；设置页安全区顶卡展示。

### 实验性开关（`experiments` 配置节）

默认全关（既有行为不变）；旧 config 无新字段回落 false。设置页「实验性功能」区 schema 驱动渲染；`apply_config` 热重建即时生效。

| 开关 | 语义 | 生效面 |
|------|------|--------|
| `dynamicCompaction` | 模型获得 `context_compact` 工具，自行决定压缩时机 | schema 下发 + compactor 装配 |
| `groupSharedContext` | 派发子个体携带组主会话摘要与最近窗口 | DispatchOrder.inputs |
| `llmDrivenMemory` | **自主记忆摘要**：关闭程序每轮自动写入（会话摘要/决策/证据/教训/偏好五类），由模型经 `memory_write` 自主判断；个体可靠性统计照常；`auto_adapt` 不触发（无自动教训来源） | 收束写入门控 + 系统提示注入记忆纪律（单智能体轮与收束轮） |
| `slidingContextWindow` | **滑动上下文窗口**：关闭条数阈值触发的定时 LLM 压缩——窗口外已压历史沿用旧摘要，未压历史不进上下文也不新增压缩调用；模型持续持有最近 N 条完整原文。与 `dynamicCompaction` **互斥**（同为压缩时机决策权归属）：开启时 `context_compact` 不下发、compactor 不装配 | `ensure_compacted` 滑动分支 + schema 门控 |
| `superAgent` | **深度委托模式**：会话系统提示注入工作法纪律——静默推进（不请求确认不播报进度）、按影响停不按工作量停（需要决策/授权才停，停下只问一个具体问题）、只在交付/需决策/无法继续三种情况产出非空回复、诚实汇报、显式假设写进交付说明。单智能体轮与组模式全链路（规划轮拆解并行化 / 收束轮口径）均受约束 | 系统提示注入（`autonomy::SUPER_AGENT_DISCIPLINE`） |
| `autoAgent` | **完全自主行动**：周期 Eval 门控 + 自主行动轮——调度器每分钟 tick，到期先跑一次轻量 LLM 自评「有没有值得做的事」（输出 JSON `{"act":bool,"task","why"}`，解析失败保守拒绝），通过才开会话执行（注入自主行动纪律 + 风险闸门：删除/外部发送/消费配额一律跳过留人）；连续无任务线性退避防空转耗 token。配套 `automation.autoAgentIntervalMinutes`（默认 30）/ `autoAgentMaxSteps`（默认 24，0=沿用派发上限）/ `autoAgentBackoffMax`（默认 8 倍封顶） | `Core::auto_agent_tick`（cron_scheduler 接线）+ `auto.eval`/`auto.act` 事件 |
| `autoMemoryDigest` | **自主记忆摘要**：低峰期（每日 04:30）把长会话历史归纳为记忆条目——消息数 ≥ `automation.memoryDigestMinTurns`（默认 20）的会话逐个走一次 LLM 单次摘要（转录每条截 400 字、最多 200 条，无工具循环），产出落 `kind=digest` 记忆（sessionId 指向来源会话）；重复归纳命中内容哈希去重（提升重要性不新建条目）。当日全库只跑一次（cron 表标记行去重） | `Core::memory_digest_session`（cron_scheduler 04:30 窗口接线）+ `memory.digest` 事件 |

`llmDrivenMemory` 注入的记忆纪律要点：值得记（稳定偏好/跨会话技术结论/明确决策/失败教训）vs 不值得记（单次任务过程/本轮复述/未确认猜测）；判定原则「下次新会话遇到类似情况会用上才写，宁可少记不可灌水」。

`superAgent` 纪律要点（源自深度委托工作法）：尽可能少占用人注意力，尽可能多交付价值；只在被要求/规则允许时行动，只在需要决策/交付/无法继续时说话；一次只问一个具体问题；信息足够就假设并推进（把显式假设写进交付说明）。组模式下规划轮把独立子任务并行拆给组内个体（nodes 无依赖即并行），收束只汇总结论与验证证据不复述过程。

`autoAgent` Eval 契约：输出 JSON `{"act": false}` 或 `{"act": true, "task": "...", "why": "..."}`；解析容错围栏/前后缀（截取首个平衡 `{...}`），非法按无任务处理（保守拒绝）；自评提示词内置「不确定 = 不做」。行动轮结束发 `auto.eval`（含判定与理由）与 `auto.act`（含任务与结果）事件，事件页可审计。

`autoMemoryDigest` 摘要契约：输出「第一行一句话主题（≤40 字）+ 随后不超过 300 字要点（目标/关键结论/决策/未决事项）」；落库正文截 600 字；每次归纳发 `memory.digest` 事件（含 entryId 与 deduped 位）；LLM 调用失败留 `ok:false` 事件不重试（下个低峰窗口自然重入）。

### 沙箱执行（`sandbox` 配置节）

三档（`sandbox.mode`）：

| 档位 | 行为 |
|------|------|
| `off` | 仅白名单 + 审批闸门（历史行为） |
| `workspace`（默认） | **子进程环境净化**：只透传 `PATH` / `SystemRoot` / `CARGO_HOME` 等运行必需变量，各类 `*_KEY` / `*_TOKEN` / `*_SECRET` 一律不外泄；`HOME` / `USERPROFILE` / `TMP` / `TEMP` 重定向到 `.exmachina/sandbox/` |
| `strict` | 净化之上：**联网类命令**（curl/wget/pip install/npm install/git fetch/clone/pull 等，`sandbox.allowNetwork` 可放行）走审批闸门；前台命令超时收紧到 60s（长活请用后台模式）；Linux/macOS 检测到 `bwrap` 且 `sandbox.useBwrap=true` 时以 bubblewrap 做系统级隔离（根只读、工作区可写、按需 `--unshare-net`） |

`sandbox.memoryMb` > 0 时限制子进程内存：Linux 经 `ulimit -v`，**Windows 经作业对象（Job Object）
的 `ProcessMemoryLimit` / `JobMemoryLimit`**。

Windows 侧另有两项作业对象级加固（`sandbox` 开启即生效，无需额外配置）：

- `sandbox.maxProcesses` > 0 时设 `ActiveProcessLimit` —— 防 fork 炸弹；
- 一律带 `KILL_ON_JOB_CLOSE`：作业句柄一关（命令结束、后台任务被终止、进程退出），
  作业内**整棵进程树**随之终止 —— 命令结束后不会留下游离的孙进程。
  句柄不可得或子进程已在别的作业里（嵌套作业不被允许时）静默降级为无作业执行，不阻断命令。

### 生命周期钩子（hooks）

`hooks.preTool` / `hooks.postTool` / `hooks.onRunEnd` 为可执行命令列表（逗号分隔），
在生效工作区内执行，环境变量注入上下文：`EXM_HOOK` / `EXM_TOOL` / `EXM_AGENT` / `EXM_ARGS`（json，截断）/
`EXM_WORKSPACE` / `EXM_TOOL_OK`（post）/ `EXM_OUTPUT`（post，截断）/ `EXM_RUN_STATUS`（runEnd）。
**preTool 非零退出 = 拦截本次工具调用**（原因回填给模型并计入审计）。

### 回收站保留（`trash` 配置节）

filesystem delete 的暂存区（`.exmachina/trash/<日期>/`）有界化，双约束并存、先到先清：

| 字段 | 默认 | 行为 |
|------|------|------|
| `trash.retentionDays` | 7 | 超期日期目录在每小时巡检时删除 |
| `trash.maxBytes` | 512MB | 超容按最旧日期目录优先淘汰，直至回到上限内 |

清理动作落审计（`GET /api/audit?tool=trash_cleanup` 可查）；配置改后下一轮巡检生效（热）。
设置页「回收站」分组暴露两字段。

### 会话内容检索（`GET /api/sessions/search`）

- 参数：`q`（必填，去空白后为空 → 400）、`limit`（缺省 20，钳制 1~50）；
- 范围：未归档会话（最多 200 个）的标题 + 各自**最近 200 条消息正文**，大小写不敏感；只读、无索引；
- 排序：标题命中优先 → 同组按会话活跃时间倒序；
- 响应：`{query, hits:[{sessionId, title, titleMatch, messageMatches, snippets, lastActiveAt}]}`；
  `snippets` 每会话最多 2 条，单条形如 `{messageId, role, text, createdAt, agentId?}`，
  `text` 截断至约 80 字符且保留关键词（`messageId` 供 WebUI 定位高亮）。

配置了 `authKey` 时，除 `/api/auth/*` 与静态资源外全部要求 `X-Auth-Key`（或 Bearer）。

首启引导：部署后首次启动且未配置 `authKey` 时，前端经 `/auth/status` 判定并展示「设置访问密钥」页（与登录门共用主题）；「下次再说」只记进程内（网关重启恢复提醒），「不再提醒」持久化 `security.keySetupDismissed`；两个动作在已配置密钥时均被拒。

```
    playbooks/                 #   组链路模板
  singles/<id>/                # 智能体（用户面）：agent.json + PROMPT.md + SOUL.md + MEMORY.md
  protocol/                    # 协议文档（绝对理性 / 证据分级 / 回流…，集群共享）
  skills/<id>/SKILL.md         # 技能包（集群共享；frontmatter + Markdown 正文）
  default-soul.md              # 共享兜底人格
  active_group                 # 激活组指针（运行时）
webui/dist/                    # WebUI 构建产物（网关托管）
desktop/                       # 桌面端（Tauri 壳：自带本地网关 / --remote 远程直连）
```

**记忆分层**：深层记忆 = MemoryStore（数据库：混合检索 / 衰减 / AI 压缩 / 经验沉淀，按组与个体隔离）；
浅层记忆 = `MEMORY.md` / `memory.md`（自动渲染的人读快照，**容量有限**，超出即截断——完整记忆永远在深层库）。
**SOUL 分层**：SOUL 仅用户面智能体持有（组主智能体 = 组根 SOUL.md；智能体 = 目录内 SOUL.md）；
子个体是执行单元，无人格层——统一智械纪律内建于各自系统提示词。
**SOUL 保护**：内置组的出厂人格随项目内容交付、运行时无副本可复原，故允许改写但**禁止重置**
（重置语义 = 删文件回落共享默认，抹掉出厂人格不可逆）；自定义组与智能体可自由改写/重置。

## 通道能力矩阵

出站能力（媒体直发 / 打字指示）按平台静态声明（`platform::caps`），与各适配器实际实现同步——
支持即直发、不支持按类型降级（图片→链接注记、文件→工作区相对路径、语音→文字摘要），不猜能力。

| 平台 | 图片 | 文件 | 语音 | 打字 | 回复上限¹ | 审批指令² | 接入形态 |
|---|---|---|---|---|---|---|---|
| telegram | ✅ | ✅ | ✅ | ✅ | 3800 字符 | ok:/no: | 内置（长轮询） |
| discord | ✅ | ✅ | ➖³ | ✅ | 1800 字符 | ok:/no: | 内置（Gateway WS） |
| slack | ✅ | ✅ | ➖⁴ | ➖⁴ | 3800 字符 | ok:/no: | 内置（Socket Mode） |
| napcat (QQ) | ✅ | ✅ | ✅ | ➖⁵ | 3500 字符 | ok:/no: | 内置（OneBot 11 正向 WS） |
| matrix | ✅ | ✅ | ✅ | ✅ | 3800 字符 | ok:/no: | 内置（/sync 长轮询） |
| qqbot (官方) | ➖⁶ | ➖⁶ | ➖⁶ | ➖ | 3500 字符 | ok:/no: + 按钮⁸ | 内置（开放平台 WS） |
| webhook / qq / wechat 桥接 | ➖⁷ | ➖⁷ | ➖⁷ | ➖ | 跟随回调 | ok:/no: | 桥接（POST inbound） |

注：
1. 回复上限 = 长回复分段的单段字符预算（`split_reply`），超限自动分段。段数封顶防 IM 刷屏：
   默认 24 段；QQ 官方机器人因被动回复每条入站消息限 ~5 次（群 5 次/5 分钟）收紧到 4 段
   （审批/计划推送共享同一额度）。触顶截断并注明「完整回复见工作台会话记录」；
   完整长文交付应走文件产物。
2. 审批指令 = 通道内快捷裁决：`ok:<单号>` 批准 / `no:<单号>` 拒绝（单号见审批通知文本）；
   全通道一致，另可经 WebUI 审批页处理。QQ 官方机器人在平台支持 markdown / 自定义键盘时
   以「批准 / 拒绝」按钮呈现（点击等价于发送对应指令；群聊点击后发送即可），失败自动回落文本。
3. discord 无原生语音条目形态，语音产物降级为文字摘要。
4. Slack 机器人无输入中指示 API（typing 降级关闭）；语音降级同 discord。
5. OneBot 11 无标准 typing 动作。
6. 官方机器人被动消息正文仅支持文本（审批消息例外：富消息三级回落——markdown + 内嵌键盘
   → 纯文本 + 键盘 → 分段纯文本；2026-04 起群/单聊自定义 markdown 已开放到所有机器人，无需
   申请模板，但仍可能被内容审核拒收，回落链保证按钮尽量保住、审批单不丢），富媒体需另走
   richmedia 上报链路（全降级）。
7. 桥接类回复能力取决于回调端实现；`send_file` / 产物投递在桥接通道走控制台附件卡交付。
8. QQ 官方机器人审批按钮：按钮为「指令按钮」——单聊点击自动发送 `ok:/no:`，群聊点击后
   填入输入框（带 @机器人）由用户发送；无需额外 interaction 回调权限。按钮 action 只用
   官方 schema 字段（type/permission/data/enter/unsupport_tips），非标字段会导致整条消息
   400 被拒。

入站能力（各通道一致）：文本 / 命令 / 图片入站（视觉模型可读）；`/stop` 停止指令全通道一致。
聊天流固定单会话（一条流恒定复用一个会话）：`/new` `/sessions` `/use` 已退役（回执说明，不改状态）；
通道 → 组绑定与会话白名单（`allowedChats[]`）同口径。

## 扩展点

- **内置工具面**：`read` / `edit` / `patch` / `grep` / `glob` / `filesystem` / `terminal` /
  `web_search` / `web_fetch` / `schedule` / `browser` / `computer` / `agent_manage` / `spawn` /
  `sessions` / `skill_manage` / `memory_read` / `memory_write` / `memory_link`。
  派发白名单 = 个体编成 JSON 的 `tools` 清单；例外：组主智能体默认追加 `agent_manage`（自定义组）、
  记忆三工具、`sessions` 与 `skill_manage`（默认授权，仍可经清单显式控制）。
  `web_search` / `browser` / `computer` 在后端能力未就绪时不下发（不承诺不存在的能力）。
  记忆三工具组隔离在工具层强制：检索与写入恒定「激活组 + 全局条目」范围，
  写入来源标注 `source=agent`，与事后归纳写入相互区分。
  `sessions` 的组隔离同样在工具层强制：目标会话必须同 `groupId` 且同 `memoryPartition`，
  跨组/跨分区不暴露存在性；投递默认异步，`wait=true` 才等待目标会话完成。
- **新渠道**：消费同一 REST/WS 契约即可接入（WebUI / Telegram / QQ 官方机器人 / NapCat / Discord /
  Slack / Matrix / Webhook 皆此模式）。
  桥接类平台（webhook / qq / wechat）把消息 `POST /api/channels/:id/inbound`，回复走 replyWebhook 或事件流；
  telegram（长轮询）/ qqbot（开放平台 WS）/ napcat（OneBot 11 正向 WS）/ discord（Gateway WS）/
  slack（Socket Mode）/ matrix（Client-Server API /sync 长轮询）为网关内置适配器，收发直达原会话。
  通道实体含 `allowedChats[]`（会话白名单，空 = 不限）与 `config{}`（平台扩展配置：
  qqbot → appId / appSecret / sandbox；napcat → url / token；slack → appToken；
  matrix → homeserver。discord / slack / matrix 的 bot token 或 access token 走顶层 `token`）。
  **密钥脱敏**：通道接口（列表 / 创建 / 更新响应）对顶层 `token`/`secret` 与平台敏感 `config` 键
  （qqbot.appSecret、napcat.token、slack.appToken）掩码回显（`***已配置***`）；
  更新时掩码 = 沿用旧值、空 = 清除。
  **运行状态**：`GET /api/channels/status` 返回 `{ <通道ID>: { state: "ok"|"error", detail, at } }`，
  由内置适配器在连接 / 断开 / 出错时覆盖上报（桥接类无运行时不产生条目）；通道删除 / 停用即清除。
  更新通道（PUT）body 无须携带 `id`（以路径参数为准）。
  六个内置适配器共用 `platform::ChannelRun`（组绑定 → 会话键 `channel:<通道ID>:<会话键>` 复用 →
  订阅事件 → 执行 → 组还原）与 `spawn_reply`（收束陈述回帖），平台差异只在发送闭包内。
  **聊天流固定单会话**：一条流（一个群 / 一个私聊）恒定复用一个活跃会话（`flow_active_session`
  绑定，失效自动重建）；流内会话切换（`/new` `/sessions` `/use` 指令与
  `GET|PUT /api/channels/flows/:id/sessions|active` 端点）已退役——旧指令仅回执说明，不改状态。
- **新模型协议**：实现 `LlmProvider` trait（`chat` + `stream`，SSE 增量经 channel 发出），
  或在 `provider.rs` 的格式分支中加一种 URL / 鉴权 / 解析规则（现含 openai / anthropic / gemini / azure）。
- **新技能包**：`entities/skills/<id>/SKILL.md`（YAML 风格 frontmatter：id/name/description/triggers/agents/source + Markdown 正文 = instructions），热装载，
  任务目标命中触发词即随派发注入；旧 `*.json` 单文件仍可读（同 id 时 SKILL.md 优先）。
  **自改进闭环**：主智能体可用 `skill_manage` 在任务后沉淀/修正技能；每次派发注入后按节点终态写
  `entities/skills/.usage.jsonl` 侧车（使用次数 / 成功次数 / 最近使用时间），`GET /api/skills`
  回读时聚合为 `useCount` / `successCount` / `lastUsedAt`。统计不写入 SKILL.md——技能文件保持
  可分享的纯内容格式，导入/导出（`POST /api/skills/import`、`GET /api/skills/:id/export`、
  `exm skill import|export`）零污染。
- **新个体**：子个体加 `groups/<gid>/agents/<id>.json` + `prompts/<id>.md`；智能体加
  `singles/<id>/`（agent.json + PROMPT.md + SOUL.md），热装载即生效。
