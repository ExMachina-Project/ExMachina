# 协议与契约

面向开发者：语言规范、核心实体、编排契约、REST/WS API、存储布局与扩展点。
字段名一律 camelCase，与 WebUI / CLI / 持久化保持一致。

## 语言规范

- **陈述前缀**：每条陈述以【肯定】【否定】【疑问】【报告】【提案】【警告】【要求】【观测】之一开头；
- **证据分级**：A 直接验证 / B 多源一致 / C 单源或旁证 / D 推断——判断应附等级。

## 核心实体

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| Session | id, title, status, groupId, ledger | 会话归属交互范围（组或 single:id）；ledger = 三账。详情接口另返回实时 `running`（不持久化） |
| ChatMessage | sessionId, role(user/orchestrator/unit/system), agentId, statements | statements = 结构化陈述数组 |
| Statement | tag, text, evidenceLevel? | 句式前缀 + 可选证据等级 |
| TaskNode | id, agentIdentifier, title, objective, acceptance, dependsOn, priority, status | DAG 节点；status ∈ pending/ready/dispatched/running/syncing/done/blocked/failed/arbitrating/cancelled |
| TaskGraph | sessionId, nodes, status | 一场会话的编排图（任务依赖 DAG） |
| AgentDefinition | name, identifier, domain, tier, description, capabilities, tools, modelHint? | 个体定义 = 数据文件；modelHint = 默认模型提示 |
| GroupMeta | id, name, primary, workspace?, model?, builtin | 组元数据（group.json） |
| LlmProfile | id, name, baseUrl, apiFormat, apiKey, apiKeys[], model, models[], fallback? | 提供商档案；models[] = 模型清单（model + vision/audio 能力开关，空 = 能力未知直通）；fallback = 失败回退档案 |
| SessionLedger | task / evidence / risk | 三账结构（详见下文） |

### 执行上下文（execution context）

`Session` 只表示用户交互和历史归属；一次实际运行必须另有版本化执行上下文，不能用一个 session 字符串同时当作预算、trace、审批来源和资源所有者。

```json
{
  "schemaVersion": 1,
  "source": "current",
  "kind": "root|child",
  "sessionId": "用户会话 ID",
  "rootExecutionId": "父级预算与授权归属",
  "executionId": "当前并发执行归属",
  "evidenceSessionId": "工具事件和证据归属",
  "parentExecutionId": "子执行的父执行 ID",
  "workspace": {
    "projectRoot": "/approved/project",
    "cacheRoot": "/approved/cache",
    "stateRoot": "/private/state"
  },
  "authorization": {
    "scope": "tools",
    "allowedTools": ["read", "edit"],
    "allowDelegation": true,
    "allowExternalWrites": false,
    "maxDelegationDepth": 1
  },
  "cancellation": { "tokenId": "opaque-token", "inherited": false },
  "budget": {
    "rootExecutionId": "父级预算归属",
    "maxSteps": 24,
    "consumedSteps": 0,
    "unlimited": false
  }
}
```

- `rootExecutionId` 只在根运行开始时建立；子任务沿用它，不能通过新 `executionId` 重置预算。
- `executionId` 用于并发和资源归属；`evidenceSessionId` 用于工具事件、产物和回流证据，两者 MUST 不复用。
- 子任务授权是父授权、子任务请求、个体能力和依赖就绪状态的交集；空工具请求只得到只读默认，且不得递归派生。
- 旧记录只按遗留上下文读取，缺失字段默认最小权限（Chat、零可用预算、无委派），不得因兼容反而扩大权限；启动新执行前 MUST 拒绝遗留上下文。

## 编排契约

### OrchestratorPlan（指挥体规划，强制校验）

```json
{
  "routeLevel": "L0|L1|L2|L3",
  "goal": "用户目标",
  "boundary": { "inScope": ["…"], "forbidden": ["…"] },
  "acceptance": ["可验证的验收口径"],
  "nodes": [{
    "id": "T1", "title": "…", "agentIdentifier": "组内子个体",
    "objective": "…", "acceptance": ["…"], "dependsOn": [], "priority": "P0|P1|P2|P3"
  }],
  "finalAnswer": [{ "tag": "报告", "text": "…" }]
}
```

- L0 = 本机直答（nodes 为空、finalAnswer 必填）；L1 单链；L2 并行；L3 含裁决；
- `agentIdentifier` 只能取自提示词注入的可调度子个体清单；
- 智能体交互目标强制 L0（nodes 必须为空）。

### DispatchOrder（派发指令）

任务节点 + 边界 + 输入（上游 SyncReport 摘要 / 个体记忆 / 命中技能指令 / 命中协议全文）+ 工具白名单 + 约束
（`max_steps` 与 `timeout_ms` 由 `automation.unitMaxSteps` 派生：步数 N → 超时 N×30s；
默认 16 步 / 480s，编码类长任务可按需上调）。
主智能体在自定义组内自动追加 `agent_manage` 工具。

**只读工具**（read / grep / glob / web_search / web_fetch）在同一轮内**并发执行**；写工具、MCP 与 browser 按原顺序串行。
工具结果超过 `security.toolOutputSpillChars`（默认 12000 字符）时全文落盘
`.exmachina/tool-output/<时间戳>-<工具>.txt`，回填摘要 + 路径，可用 read 分段回读。

**终端作业生命周期**：后台 `poll/kill/list` 均检查会话与启动项目归属，仅持有 taskId 不构成授权。
`kill` 有界等待受管进程与输出管道回收，再返回取消结果；无法确认回收时明确报错，不宣称已停止。
取消任务仍可 `poll/list`，返回「已取消」及已捕获输出，不以 exit=0 冒充完成，也不因 kill 立即删除证据。
前台与审批代执行同样在当前轮次显式取消时终止；普通轮次结束不自动终止跨轮保留的后台作业。
前台超时/取消返回失败并附终止前的 stdout/stderr 摘要。POSIX 进程组和 Windows Job Object 用于进程生命周期，
不是文件系统或网络沙箱；主动脱离进程组的程序仍需操作系统隔离约束，不得把进程分组描述为安全隔离。

后台任务每个数据根最多同时运行 4 项、保留 128 条元数据；默认单项截止 900 秒，`timeoutSecs`
可收紧、不能超过实例上限。命令长度上限 32KB；每项 stdout/stderr 分块日志应用现有文本脱敏规则，默认最多 1 MiB（含 JSONL 开销）。达到上限后丢弃最旧的块；轮转最多额外使用一个同上限的暂存文件。
会话删除会取消对应任务并移除其元数据与日志；网关收到正常关闭信号时停止后台任务并有界收尾。
重启或运行句柄丢失后，旧 `running` 记录改为 `interrupted`，保留已落盘的完整日志块，不探测/复用旧 PID，也不重放命令。

**后台输出分页**：仅传 `op=poll` 和 `taskId` 仍返回文本尾部（最多 6000 字符）。附 `cursor`、`limitBytes` 或 `waitMs` 时返回一个 JSON 对象；从 `cursor=0` 开始，随后复用 `nextCursor`。`limitBytes` 默认 4096，限制为 4–8192 字节正文，每页最多 64 个块。`waitMs` 默认 0，最多 2000 ms；仅在任务运行且游标已达当前末尾时等待新输出或终态。

| 字段 | 语义 |
|------|------|
| `taskId`, `workspace`, `status`, `exitCode`, `error` | 作业归属与状态；查询成功不代表任务成功，正常完成须同时检查 `status=exited` 和 `exitCode=0` |
| `retainedStart`, `retainedEnd` | 当前可读的半开字节区间。偏移基于解码并应用脱敏规则后的 UTF-8 文本，不是进程的原始字节 |
| `nextCursor`, `hasMore` | 下次读取位置，及当前快照中是否还有数据；任务仍运行时 `hasMore=false` 不表示任务结束 |
| `droppedBytes`, `skippedBytes`, `outputTruncated` | 尾部轮转原本缺失 `[0, retainedStart)`；若游标过旧，则从 `retainedStart` 继续，`skippedBytes` 报告本次跳过量。旧前缀日志曾截断但无字节计数时 `droppedBytes=null` |
| `chunks[]` | `sequence`、`stream`（`stdout`/`stderr`）、`startByte`、`text`；按采集顺序返回。一个块可能跨页，此时 `sequence` 不变、`startByte` 递增 |

超出末尾或位于保留区内的非 UTF-8 字符边界的游标明确报错。后台日志查询不会再次将日志复制到工作区。后置钩子失败时，JSON 页内使用 `postToolWarning`，不在 JSON 外追加文字。

**按能力就绪度动态下发**：`web_search` 在未配置搜索后端时、`browser` 在探测不到浏览器时、
`computer` 在总开关未开启时**不出现在下发给模型的工具表里** —— 宁可少一个工具，也不让模型调用必然失败的工具。

### 消息来源标记（user 消息 `agent_id` 前缀约定）

user 消息的 `agent_id` 字段承载来源标记（非智能体名），展示层与模型侧按前缀区分语义——**不污染正文**：

| 前缀 | 语义 | 展示层 | 模型侧上下文 |
|------|------|--------|--------------|
| `auto:xxx` | 系统自动内容（视频观看/RSS/定时任务等） | 消息头显示「自动任务」+ 来源标签 | `[用户]`（同普通用户消息） |
| `steer:<source>` | 运行中插入的 steering 输入（source=webui/cli/通道名） | 消息头显示「运行中引导」+ 来源标签（蓝系，刷新后仍可区分） | `[用户]`（安全检查点并入当前任务引导） |
| `im:名字(id)` | 外部群聊发送者（napcat/telegram/qqbot/discord/slack/matrix 群聊） | 消息头署名发送者（替代「用户」） | `[用户·名字]`；排队窗口合并多轮输入时逐条行内署名「（名字 说）」 |
| `imctx:名字(id)` | 群聊旁听（「仅 @ 回复」门控拦下的未 @ 群消息，见下节） | 消息头署名发送者 + 「群聊」标签 | 模型侧合并为「群聊记录」引用块（背景，非指令）；不并入本轮 goal（背景上下文，非任务输入） |
| 无标记 | 真人输入（WebUI / 私聊） | 「用户」 | `[用户]` |

- 私聊不标注（双方固定，标注是噪音）；名字缺省只留 id；名字与 id 相同不重复展示；
- 生成口径：`channel_util::sender_origin`（六适配器共用），落库经 `ChannelRun.origin` → `chat_scoped_origin(origin)` → `add_message(agent_id)`。

### IM 对话与模型可用性

IM 问候、在线确认、致谢、简单确认与普通对话统一经过真实模型。系统不根据关键词生成固定回答，也不以本地回复掩盖额度耗尽、鉴权失败或网络错误。所有已配置候选失败时，本轮以 `run.error` 和失败快照收束，系统消息记录错误，不创建正常的智能体回答。

配套规划纪律（`PLANNING_CONTRACT`）：输入无任务语义（闲聊 / 单字重复 / 无法理解的碎片）时规划器必须 L0——请求澄清或简短回应，**禁止从会话历史捡旧任务执行**（部署实测：无意义输入「对应×4」曾触发规划器从历史重启群昵称修改任务，39 次工具调用 / 480s 超时）。

### 主动回复（proactive reply，通道级实验开关）

群聊免 @ 主动回应：唤醒门控拦下的未 @ 群消息，由决策模型结合上下文判断是否放行进完整轮次（`platform/proactive.rs`，六平台共用——判定在 admit ②一处生效）：

| 级 | 手段 | 成本 | 放行条件 |
|----|------|------|----------|
| ① 回复率采样 | `proactiveRate` % 软权重 | 零 | 命中使用标准口径，未命中使用保守口径 |
| ② 决策模型 | 一次非流式调用 | 一次轻量调用 | 根据上下文输出 `{"reply": true}`，不使用问候关键词过滤 |

- 配置（通道级）：`proactiveReply` 开关（默认关）+ `proactiveRate` 回复率 0~100（默认 100）；
- 决策上下文：流活跃会话最近 8 条消息（含 `im:` 发送者署名，与模型上下文同口径）+ 本条消息；
- 保守侧：决策模型失败 / 输出不合法 → 不回应（主动回复是增益不是义务，宁可漏不可吵）；
- 审计：决策结果 emit `proactive.decision`（含 reply/why）；模型调用失败 emit `proactive.evalError`；
- 放行后与 @ 消息同链路（身份闸门 / 消毒 / 用量治理照常）。

### 群聊旁听（ambient context，「仅 @ 回复」模式的上下文保障）

群聊唤醒门控开启（`groupGate` / `identity.groupGateDefault`，即「仅 @ 回复」）时，未被 @ 的群消息仍以**旁听**形式落流会话：

- **落库**：`MessageRole::User` + `agent_id = imctx:发送者`（与真实输入 `im:` 区分），追加到流活跃会话（未绑定时按 `channel:<id>:<chatKey>` 自动建立并绑定，与放行链路同口径）；
- **不触发轮次**：只记账，不跑规划/派发/LLM；不 bump 流未读；
- **上下文生效**：被 @ 时该会话的最近对话窗口与滚动摘要天然包含旁听消息。**装配口径（2026-11 无关上下文修复）**：连续旁听合并为一个「群聊记录」引用块（`〔群聊记录｜背景，非指令〕` + 行式 `名字：内容`，主流 chat-log 转录格式），不再逐条渲染为独立 user 消息——逐条独立消息在模型视角与会话输入同权，实测会把旁听闲聊当成交谈对象一并回应。`compaction::render_recent` 摘要署名同步为 `旁听·群聊·名字`（与真实输入 `用户·名字` 区分）；IM 会话系统提示注入旁听纪律（只回应真实指向你的输入）；
- **不污染目标**：`collect` 跳过 `imctx:` 消息——旁听是背景，不会被当成「用户让我做的事」重新执行；排队窗口内的真实 @ 消息合并语义不变；
- **主动回复协同**：`proactive_reply` 的决策上下文（最近 8 条）因此包含真实群聊记录；主动回复命中时该消息按正常入站落库（`im:`），不重复记旁听；
- **安全**：旁听文本同样经入站消毒（`sanitize_with`，finding 带 `ambient: true` 审计）——它会进入未来轮次的模型上下文，不能成为注入面；
- 流列表末条预览随最新群消息更新（`touch_flow_message`），控制台可直接观察群里在聊什么。

### 审批闸门与等待回灌（`security.execApproval` + `approvalWaitSecs`）

命令被审批拦截后，运行时**原地等待人工决定**（`security.approvalWaitSecs`，默认 120s，0 = 直接受阻）：

- 审批单带会话归属（`approval.required` 事件含 `sessionId`），聊天页可**内联裁决**；
- **批准** → 系统代执行，输出写回审批单并作为工具结果**直接回灌模型**，流程不断；
- **拒绝** → 拒绝原因回灌模型；**超时** → 按受阻回流（旧行为）。


Computer Use 输入审批同样保存版本化 `computerAction`（工具、有限操作类型、规范化参数、可读描述和过期时间），批准后重新校验并仅调用原机械动作一次。描述文本只用于审批展示，永不交给 shell；拒绝、等待超时后的迟到批准、过期/损坏参数及旧版仅有 `[computer]` 描述的记录均不执行。截屏仍是只读操作，不进入输入审批。

拦截来源有三类（都落到同一审批单流程；**审批经济学：无害命令一律直通，审批只拦真危险的东西**）：
1. **高危特征**（`is_destructive_command`：rm 变体 / `git reset --hard` / `curl | sh` 等；`risky` 与 `always` 档都拦，`execAllowlist` 前缀可豁免）；
2. **Denied 档命令**（`rm`/`format`/`dd`… 破坏性清单，任何审批档位都走 `[红线]` 审批单）；
3. **白名单外且高危**（`risky`/`always` 档转人工审批——用户批准即代执行；`off` 档直接拒绝）。

白名单外但**无害**（非 Denied 档且无高危特征）的命令在 `risky`/`always` 档**直通**（2026-11 审批经济学：`always` 由「全拦」降级为「高危必拦」——此前 `mkdir`/`go`/`pytest` 等日常命令也要人工介入）；`off` 档保持白名单即全部边界的零信任语义。

**三档放行粒度（approval-ergonomics）**：批准时可选 `once`（默认，本次执行）/ `session`
（同前缀命令本会话免审，内存态随会话失效）/ `allowlist`（前缀写入 execAllowlist 持久生效）。
REST `POST /api/approvals/:id/approve` body `{"scope": "once|session|allowlist"}`。
红线：`[root]` 提权单与破坏性命令强制 once（后端降级 + 结果注明）。

**通道裁决**：通道会话产生的审批单推送摘要回来源 IM（单号 + 命令 + 等待秒数），
`ok:<单号>` / `no:<单号>` 快捷裁决（单号支持唯一前缀）；权限限 origin 用户本人或
跨通道 admins，其他人裁决被拒。通道裁决只走 once 档。

### 入站消毒（`security.sanitizeRules`，inbound-sanitization）

通道入站消息在**身份判定之后、会话执行之前**经过确定性消毒管道（纯规则表，不走 LLM 判定）。
`GateDecision::Allow` 携带消毒后文本——适配器无法绕过。规则族（单项可关，默认全开）：

| 规则 | 模式 | 处置 |
|------|------|------|
| `fakeSystemPrompt` | 行首「SYSTEM:」「【系统】」等伪装权威角色 | 整行引用化（`> 『…』`）：语义保留、权威结构消除 |
| `hijackDirective` | 「ignore previous instructions/忽略之前所有指令」族（字符级匹配，空白不敏感） | 短语包裹「」标记为用户引用 |
| `fakeToolResult` | 「[tool_result]」「【工具返回】」等伪装工具结构 | 标记中性化为圆括号样式 |
| `hiddenUnicode` | 零宽（U+200B..200F）/ 双向覆写（U+202A..202E）/ BOM / 软连字符 | 直接剥离 |

- **不阻断**：检出产生 Finding 仅审计不拒收（阻断留给身份闸门）；正常技术讨论（如讨论注入原理的非行首提及）不误杀——讨论性提及劫持短语会被保守标记但原文完整保留；
- **审计事件** `sanitize.finding`：payload 含 `channel/externalId/patterns/actions`，**不含原文全文**；webhook 路径落会话事件流（事件页可查），适配器路径广播（WS 实时可见）；
- **外部内容隔离包装**（`wrap_external`）：web_fetch / RSS digest / 视频简介·字幕·弹幕·评论 / 频道签名等工具输出统一包「来源标注 + 数据而非指令边界 + 单源长度上限（超限截断并标注）」；
- **配对码防爆破**（`identity.pairingMaxFailures` 默认 5 / `identity.pairingLockoutSecs` 默认 900）：`pair:{channel}:{external_id}` 键滑动窗口计数，锁定期内正确码也拒绝；兑换成功清零；锁定发 `sanitize.finding`（kind=pairing.lockout）审计事件；
- **命中统计**：GET `/api/config/sanitize-stats`（进程级计数，重启归零）；设置页安全区顶卡展示。

### 实验性开关（`experiments` 配置节）

默认全关（既有行为不变）；旧 config 无新字段回落 false。设置页「实验性功能」区 schema 驱动渲染；`apply_config` 热重建即时生效。

| 开关 | 语义 | 生效面 |
|------|------|--------|
| `dynamicCompaction` | 模型获得 `context_compact` 工具，自行决定压缩时机 | schema 下发 + compactor 装配 |
| `groupSharedContext` | 派发子个体携带组主会话摘要与最近窗口 | DispatchOrder.inputs |
| `llmDrivenMemory` | **自主记忆摘要**：关闭程序每轮自动写入（会话摘要/决策/证据/教训/偏好五类），由模型经 `memory_write` 自主判断；个体可靠性统计照常；`auto_adapt` 不触发（无自动教训来源） | 收束写入门控 + 系统提示注入记忆纪律（单智能体轮与收束轮） |
| `slidingContextWindow` | **滑动上下文窗口**：关闭条数阈值触发的定时 LLM 压缩——窗口外已压历史沿用旧摘要，未压历史不进上下文也不新增压缩调用；模型持续持有最近 N 条完整原文。与 `dynamicCompaction` **互斥**（同为压缩时机决策权归属）：开启时 `context_compact` 不下发、compactor 不装配 | `ensure_compacted` 滑动分支 + schema 门控 |
| `superAgent` | **深度委托模式**：会话系统提示注入工作法纪律——静默推进（不请求确认不播报进度）、按影响停不按工作量停（需要决策/授权才停，停下只问一个具体问题）、只在交付/需决策/无法继续三种情况产出非空回复、诚实汇报、显式假设写进交付说明。单智能体轮与组模式全链路（规划轮拆解并行化 / 收束轮口径）均受约束 | 系统提示注入（`autonomy::SUPER_AGENT_DISCIPLINE`） |
| `autoAgent` | **完全自主行动**：周期 Eval 门控 + 自主行动轮——调度器每分钟 tick，到期先跑一次轻量 LLM 自评「有没有值得做的事」（输出 JSON `{"act":bool,"task","why"}`，解析失败保守拒绝），通过才开会话执行（注入自主行动纪律 + 风险闸门：删除/外部发送/消费配额一律跳过留人）；连续无任务线性退避防空转耗 token。配套 `automation.autoAgentIntervalMinutes`（默认 30）/ `autoAgentMaxSteps`（默认 24，0=沿用派发上限）/ `autoAgentBackoffMax`（默认 8 倍封顶） | `Core::auto_agent_tick`（cron_scheduler 接线）+ `auto.eval`/`auto.act` 事件 |
| `autoMemoryDigest` | **自主记忆摘要**：低峰期（每日 04:30）把长会话历史归纳为记忆条目——消息数 ≥ `automation.memoryDigestMinTurns`（默认 20）的会话逐个走一次 LLM 单次摘要（转录每条截 400 字、最多 200 条，无工具循环），产出落 `kind=digest` 记忆（sessionId 指向来源会话）；重复归纳命中内容哈希去重（提升重要性不新建条目）。当日全库只跑一次（cron 表标记行去重） | `Core::memory_digest_session`（cron_scheduler 04:30 窗口接线）+ `memory.digest` 事件 |
| `deviceConnectivity.enabled` | **物理设备连接（实验性）**：默认关闭；开启后仍需用户主动发现、确认配对和逐项授权。不会后台扫描、常开摄像头或把设备当作远程 Agent。资源限制位于 `experiments.deviceConnectivity` | Core `DeviceService` 保存生命周期/授权状态；宿主硬件桥接、Gateway API 与 Agent 工具面仍按后续任务接入，当前不向 Agent 下发设备动作 |

`llmDrivenMemory` 注入的记忆纪律要点：值得记（稳定偏好/跨会话技术结论/明确决策/失败教训）vs 不值得记（单次任务过程/本轮复述/未确认猜测）；判定原则「下次新会话遇到类似情况会用上才写，宁可少记不可灌水」。

`superAgent` 纪律要点（源自深度委托工作法）：尽可能少占用人注意力，尽可能多交付价值；只在被要求/规则允许时行动，只在需要决策/交付/无法继续时说话；一次只问一个具体问题；信息足够就假设并推进（把显式假设写进交付说明）。组模式下规划轮把独立子任务并行拆给组内个体（nodes 无依赖即并行），收束只汇总结论与验证证据不复述过程。

`autoAgent` Eval 契约：输出 JSON `{"act": false}` 或 `{"act": true, "task": "...", "why": "..."}`；解析容错围栏/前后缀（截取首个平衡 `{...}`），非法按无任务处理（保守拒绝）；自评提示词内置「不确定 = 不做」。行动轮结束发 `auto.eval`（含判定与理由）与 `auto.act`（含任务与结果）事件，事件页可审计。

`autoMemoryDigest` 摘要契约：输出「第一行一句话主题（≤40 字）+ 随后不超过 300 字要点（目标/关键结论/决策/未决事项）」；落库正文截 600 字；每次归纳发 `memory.digest` 事件（含 entryId 与 deduped 位）；LLM 调用失败留 `ok:false` 事件不重试（下个低峰窗口自然重入）。

### 会话恢复与连接保活

- `GET /api/sessions/:id` 附带 `running: boolean`，表示当前网关进程是否正在执行该会话的对话轮次。
  它独立于持久化 `status` 和任务图：单智能体直答没有 DAG，也可能仍在运行。旧网关缺省该字段时客户端回退到图节点状态。
- `/ws?sessionId=<id>&key=<访问密钥>` 的应用层保活：客户端发送文本 `ping`，服务端回复文本 `pong`。
  这两种文本不是业务事件；浏览器收到 `pong` 后更新收帧时间。仅 `WebSocket.send()` 成功不代表链路仍然可达。
  协议层 Ping/Pong 保持原有语义。
- WebUI 与桌面客户端每次连接成功均重新读取消息、任务图和会话运行态，补齐 HTTP 快照到 WS 订阅之间及断线期间的缺口。
  快照请求期间若发生新事件、发送操作或会话切换，旧响应不得覆盖更新状态。
- 待审批清单通过 `/api/approvals?status=pending` 校准：删除已裁决卡片、恢复断线期间新单。
  请求乱序和审批实时事件用代际校验处理；请求失败时保留最近一次已知待审批状态。
- 发送接口拒绝或连接失败时，客户端保留该会话的输入与附件供重试，仅在请求受理后清除对应内容；
  待请求期间继续编辑的下一条草稿不得被前一次发送回调清空。

### 运行中输入语义（steering / queue / stop，capability-parity）

会话运行中收到的新输入分三种互斥语义，任何入口（IM 聊天 / WebUI / CLI / TUI / loopback 通道）必须遵守同一契约：

| 输入类型 | 触发方式 | 语义 | 回执（绝不冒充完成） |
|----------|----------|------|----------------------|
| **steering（引导）** | 普通消息（运行中） | 暂存并落库（`agent_id=steer:<source>`），在下一安全检查点引导当前任务；不停止、不排队、不等待 | `status=steering_accepted` + `running=true` + `interrupted=false`，事件 `steering.accepted`（广播+落库） |
| **queue（后续任务）** | `/queue <指令>` / WebUI「加入队列」/ `exm queue add` / REST `POST /queue` | 独立后续任务：有序号/接收时间/来源/状态，当前任务收束后按 FIFO 出队执行 | `status=queued` + `seq` + `pending`，事件 `task_queue.updated`（全量快照，广播+落库） |
| **stop（显式停止）** | `/stop` / 停止按钮 / `exm stop` | 取消令牌置位，轮次在下一检查点以停止陈述收束（`run.finished` 带 `stopped:true`）；通道管理员权限校验 | 停止回执带真实 `stoppedTools` 计数 |

硬性边界：

- **空闲会话**没有可引导的轮次：普通输入直接开新轮次，不产生虚假的排队/中断状态（`SteeringAdmission::Idle`）；
- **`auto:*` 系统来源不转向**：机器任务（视频观看/RSS/定时）保持锁排队语义，不并入真人 steering；
- **普通消息不是取消令牌**：任何入口不得把普通输入解释为 stop/cancel；
- **运行失败/超时**：剩余 queued 项迁移 `pending_recovery`（不自动连环执行），落系统提示消息 + 快照事件；**用户停止**：队列保留 `queued` 原状（停止语义覆盖自动出队，剩余意图由用户决定）；
- **steering 未消费恢复**：轮次收束时未被安全检查点消费的 steering 输入 emit `steering.pending_recovery`（含输入 id 清单），不静默丢弃。

**队列事件快照口径（回放一致性）**：所有 `task_queue.updated` 事件（add/edit/remove/move/clear/finish/pending_recovery）payload 均带全量 `{action, items, running, queued}`，经 `emit_session_event` 广播+落库——WebUI 刷新 / WS 重连从事件尾恢复队列与实时渲染走同一路径；无 `items` 的旧格式事件回放时跳过（不显示虚假空队列）。

**队列 REST 面**：`POST/GET /api/sessions/:id/queue`、`PATCH/DELETE /:qid`、`POST /:qid/move`、`DELETE /queue`（清空）；CLI `exm queue add/list/edit/remove/move/clear`（`source=cli`）；TUI panel `/queue add|list|clear`（`source=tui`）；聊天 `/queue <指令>|list`（gate ⓪' 解析，先于身份配对）。跨会话持有他人队列 id 的查询/编辑/删除一律拒绝且不泄漏正文。

**loopback 通道帧形态**：命令请求/结果以 `{type: "command.request"|"command.result", payload}` 帧包装（`exm-core` `TransportFixture::LoopbackChannel` 为协议测试夹具），五类场景（立即接收、不等待、不打断、明确入队、真实回执）的回执契约由 `loopback夹具覆盖steering与队列五类场景回执` 守护。

### 项目协作群聊（`collaboration-v1`）

实例必须开启访问密钥。以下接口携带 `X-Auth-Key`（或 Bearer）和百分号编码的 `X-Exm-Workspace` 请求头；该目录是群聊的归属项目，而非成员的执行目录。项目作用域不是独立用户权限，实例访问密钥仍是管理凭证。

| 方法与路径 | 请求 / 响应 |
|---|---|
| `GET /api/collaborations` | 当前项目的持久化群聊列表（含成员名单） |
| `POST /api/collaborations` | `{title, members:[{target, workspace}]}`；`target` 为组 ID 或 `single:<id>`，`workspace` 为网关机器上的规范化绝对目录。2–8 位固定成员，同一目录不能重复加入同一对象。201 返回群聊及成员 `sessionId` |
| `GET /api/collaborations/:id?before=...` | `{room, turns, nextBefore, activeTurnId, approvals}`。最新页或游标之前的历史，按发送顺序；最新页含成员及其派发子会话的待审批。`nextBefore` 为独占游标 |
| `POST /api/collaborations/:id/turns` | `{requestId, text?, recipients:[{sessionId,instruction?}]}`，明确选择 1–8 位成员；每位必须有公共消息或分工。202 返回 `{id}`，同一 `requestId`（规范 UUID）和同一内容可幂等重试 |
| `POST /api/collaborations/:id/turns/:turnId/stop` | `{sessionId?}`，请求停止指定轮次的指定成员或所有未完成成员；返回 `{stopped}`。不会影响后续轮次，不回滚已执行操作 |

每个成员用独立会话、项目目录和记忆分区运行；不会改动激活对象和实例工作目录。只有当轮的公共消息与对应分工进入该成员上下文，其他成员的记录不自动拼入。普通会话接口可以在成员自己的项目连接中读取其执行记录；向成员发消息或停止须通过群聊 API。批准或拒绝使用现有 `/api/approvals/:id/...`，请求头目录为**审批所属成员**的项目。重启后未完成的投递显示为 `interrupted`，不自动重试。

- `GET /api/asset?path=<工作区相对路径>&key=<authKey>`：只读资产（截图 / 工具输出），
  沙箱校验 + 扩展名白名单 + 8MB 上限；`<img>` 场景密钥走查询参数。

### 沙箱执行（`sandbox` 配置节）

三档（`sandbox.mode`）：

| 档位 | 行为 |
|------|------|
| `off` | 仅白名单 + 审批闸门（历史行为） |
| `workspace`（默认） | **子进程环境净化**：只透传 `PATH` / `SystemRoot` / `CARGO_HOME` 等运行必需变量，各类 `*_KEY` / `*_TOKEN` / `*_SECRET` 一律不外泄；`HOME` / `USERPROFILE` / `TMP` / `TEMP` 重定向到 `.exmachina/sandbox/` |
| `strict` | 净化之上：**联网类命令**（curl/wget/pip install/npm install/git fetch/clone/pull 等，`sandbox.allowNetwork` 可放行）走审批闸门；前台命令超时收紧到 60s（长活请用后台模式）；Linux/macOS 检测到 `bwrap` 且 `sandbox.useBwrap=true` 时以 bubblewrap 做系统级隔离（根只读、工作区可写、按需 `--unshare-net`） |

`sandbox.memoryMb` > 0 时限制子进程内存：Linux 经 `ulimit -v`，**Windows 经作业对象（Job Object）
的 `ProcessMemoryLimit` / `JobMemoryLimit`**。

Windows 侧另有两项作业对象级加固（`sandbox` 开启即生效，无需额外配置）：

- `sandbox.maxProcesses` > 0 时设 `ActiveProcessLimit` —— 防 fork 炸弹；
- 一律带 `KILL_ON_JOB_CLOSE`：作业句柄一关（命令结束、后台任务被终止、进程退出），
  作业内**整棵进程树**随之终止 —— 命令结束后不会留下游离的孙进程。
  句柄不可得或子进程已在别的作业里（嵌套作业不被允许时）静默降级为无作业执行，不阻断命令。

### 有界程序化工具组合（`programmatic`，capability-parity）

`programmatic` 工具把「循环读取/检索/筛选/计算」类多步工作收进**一次受限执行**：模型提交 JSON 步骤清单，系统串行执行，中间结果不回灌模型上下文，只返回逐步状态与最终摘要。

**步骤清单形态**：

```json
{"tool":"programmatic","args":{"steps":[{"tool":"read","args":{"path":"Cargo.toml"}},
  {"tool":"grep","args":{"pattern":"$1","path":"src"}}]}}
```

- 步骤间引用：`args` 字符串值里的 `$1`/`$2`… 替换为第 1/2 步输出（截断 400 字符，JSON 转义保解析）；
- **授权面**：只能使用当前任务 allowlist 内的**内置工具**；`programmatic`（递归）、`spawn`、`computer`、`agent_manage`、`skill_manage`、MCP、自定义/插件工具一律在**预检阶段拒绝**（任何调用未开始，终态 `limit_exceeded`）；
- **子调用复用全链闸门**（授权/审批/沙箱/脱敏/审计/落盘/计划拦截）：每个子调用走 `execute_named` 同一入口——脚本中的写文件、联网、发布仍按原工具效果单独判定，不因位于清单中而降级；
- **资源边界**：步骤数 ≤16、单步预览 ≤400 字符、总输出 ≤64 KiB、组合层墙钟 ≤120s；
- **终态**：`succeeded` / `partial`（某步失败即停，已完成步骤保留）/ `limit_exceeded` / `timeout` / `cancelled`——每步记录工具名、参数摘要、状态、耗时与输出预览；
- **取消收束**：每步之间检查会话取消令牌（`round_trace::is_cancelled`），取消后未开始步骤标 `skipped`，迟到结果不产生写副作用；
- **计划模式**：`programmatic` 整体视为写类——清单转入计划条目（action=batch，target=工具序列），批准回放时子调用各自走闸门。

**能力快照（capability-parity 5.1）**：`GET /api/capabilities` 除命令面外返回模型工具面逐工具状态（`tool.<key>`）——`Available`=会出现在该身份该作用域的 schema 里；`Forbidden`=作用域/编成裁剪；`MissingDependency`=后端未就绪/实验开关未开/文件记忆模式。与 runtime schema 组装链走**同一判定函数**，目录存在 ≠ 可执行。

**模型用途与媒体能力（capability-parity 5.5）**：用途目录（chat/planning/coding/review/summary/research/vision/speech/transcribe/embedding/imageGen）的候选判定消费模型清单能力标记——`vision` 对应视觉输入、`audio` 对应转写输入；未声明能力的模型不进入该用途候选（`purposes` 显式声明优先）。显式候选同样要过能力判定：不满足即候选为空、`purpose_ready=false`，解析失败保留真实原因（「没有可用模型候选」），不用其他用途结果冒充。子任务（spawn）的工具白名单与父执行授权面**求交**——请求超出父 allowlist 的工具被裁剪（只收窄不扩权）；父面未收窄（空）时保持请求原样。

**离线与否定矩阵（capability-parity 5.6）**：离线 provider=mock 通道（`use_mock`）——无 HTTP 端点也参与正常候选判定（测试通道是合法 provider）；真实档案缺 `baseUrl`/密钥时不进自动候选（不虚报可路由）。隔离进程组：terminal 子调用进程 `process_group(0)` 独立成组，取消/超时经 `stop_tree` 终止整棵进程树（不泄漏后台进程）。跨会话否定边界：程序化组合的事件/审计/审批单/计划条目都归属发起会话，另一会话（即使同 agent）看不到组合痕迹；chat 档（无工具面）不下发任何工具 schema（含 programmatic），旧工具调用路径不经组合包装。

### 会话工作流命令（goal / spec / plan，capability-parity）`/goal`、`/spec`、`/plan` 三命令族是**同一会话的共享工作流状态**，四个入口（CLI / TUI / WebUI / IM 聊天）操作同一事实源：

| 层 | 事实源 | 事件 | 入口 |
|----|--------|------|------|
| **goal（目标）** | 会话事件（跨重启恢复） | `workflow.goal.changed` | CLI `exm goal …`；TUI panel `/goal`；聊天 `/goal status\|start\|edit\|pause\|resume\|complete\|block\|clear` |
| **spec（规格）** | 会话事件（跨重启恢复） | `workflow.spec.changed` / `workflow.spec.cleared` / `workflow.spec.exported` | CLI `exm spec …`；TUI `/spec`；聊天 `/spec show\|draft\|edit\|clear`（export 走 CLI/WebUI——聊天不开工作区写） |
| **plan（方案）** | 进程级暂存（审批前有效） | `plan.enabled/disabled/item/approved/rejected/applied` | CLI `exm plan …`；TUI `/plan`；聊天 `/plan status\|start\|approve\|reject\|execute`；WebUI 计划卡片 |

**关联视图（派生，不是第二事实源）**：`GET /api/sessions/:id/workflow` 返回 `{goal?, spec?, planMode, planItems, todoPresent}`——goal/spec/plan 状态仍归各自事实源，关系仅作呈现。WebUI 聊天页顶部徽标条（🎯 goal 状态 · 📄 spec 版本+关联 · 📋 plan 模式）为只读呈现，写操作走 CLI/聊天命令；`workflow.*` / `plan.*` 事件到达后自动刷新。

**硬性边界（回归锚点）**：

- **命令文本不交给模型猜测**：聊天入口的 `/goal` `/spec` `/plan` 在 gate（⓪''/⓪''' 分支）拦截直答回执，绝不进 chat 链路——不触发轮次、不落 assistant 消息、不把命令文本混入模型上下文；
- **读面人人可用，写面管理员裁决**：聊天通道 status/show 普通成员可用；写操作（start/edit/pause/resume/complete/block/clear/draft）仅管理员（与 `/stop` `/plan approve` 同口径——共享会话的持久状态变更），未 @ 静默忽略；
- **不与 cron / todo 看板 / 任务队列混淆**：goal/spec/plan 只动 `workflow.*` / `plan.*` 事件，不产生 cron 项、不触碰 todo 快照（轮内执行进度）、不触碰 task_queue（后续任务排队）——三套机制互不相干；
- **spec 修改不自动批准 plan**：`spec_update` 只改 spec 状态，不动 plan 模式位与清单（无 `plan.approved` 副作用）；
- **goal complete 必须带真实验证证据**：空证据被拒（`required_text`），证据入档 `verification[]`；
- **plan 模式位是进程级暂存**：CLI 每次调用是独立进程，模式位不跨进程——常驻进程（网关/TUI）内三命令共享同一位。

### 分层上下文文件与来源治理（context-files）

**四层固定优先级**：`AgentPrompt < Project < User < SystemSafety`（系统安全层永远最高）。
项目层 = 会话工作区的 `AGENTS.md` / `.exmachina/context.md`；用户层 = `~/.exmachina/context.md`。
注入段带逐文件来源标签（`### 来源：<file>`）与不可信声明——**文件内容不进用户消息位、不覆盖系统规则**；
冲突语句（要求关闭审批/读密钥/自动发布）只登记不生效（`context.sources` 事件的 `conflicts` 字段，安全策略原样）。

**预算与安全**：单文件 8,000 字符、总计 24,000 字符（按层优先级花起、稳定截断）；
超限状态 `loaded_truncated` 可观察。敏感文件名（`.env`/`*secret*`/`*token*`/`*.pem`/`id_rsa` 等）
默认排除（约定清单不含 + 读取层拒绝，双重防线）。路径穿越（`..`/绝对路径/符号链接）拒绝且记录原因。

**来源可管理（6.3）**：

| 面 | 入口 | 语义 |
|----|------|------|
| REST | `GET /api/sessions/:id/context` | 四类来源（file/memory/retrieval/skills）状态 + 禁用位 + `gaps`（缺席说明：未绑定项目 / 项目目录不可用 / 用户层目录不存在） |
| REST | `POST /api/sessions/:id/context` | `{action: "disable"\|"enable"\|"refresh", key}`——禁用清单会话级持久化 + `context.sources.updated` 事件 |
| 聊天 | `/context status\|list\|detail <key>\|refresh [key]` | 读面普通成员可用（refresh 只读重读，单来源失败不影响其它来源） |
| 聊天 | `/context disable\|enable <key>` | 写面仅管理员；key 形如 `file:AGENTS.md` / `memory` / `retrieval` / `skills` |
| CLI | `exm context <session> list\|detail <key>\|refresh [key]\|disable <key>\|enable <key>` | 与 REST/聊天同一 Core 事实源；单独打印缺席说明行 |

- 禁用即恢复：`disable` 后该文件不再读内容（状态如实标 `disabled`），`enable` 恢复加载——无重启；
- 单来源独立：单来源禁用/失败不影响其他来源（e2e 锚定）；
- 缺失容错：无约定文件 = 零注入零事件，对话照常；单文件读取失败降级为 `rejected` 状态不传播。

### 学习候选与来源证据（agent-learning-loop 6.4）

**候选态先行**：任务后沉淀的可复用经验先进候选账本（`learning_candidates` jsonl），
不直接写长期技能/记忆。状态机 `pending → approved / rejected`（人工裁决一次定局，不可重复）。

**准入红线（CandidateBook::submit 全量校验）**：

- **真实证据绑定**：候选必须携带可核验证据——`artifact_file`（会话工作区内路径且本会话有成功写
  调用指向它）/ `tool_receipt`（本会话成功回执，callId 命中）/ `test_result`（同上且命令含测试
  语义）/ `session_evidence`（证据账本 A/B 级条目）。**模型自述成功（无证据引用）默认拒**；
- **敏感信息默认拒**：内容/标题含密钥/令牌/私钥/密码形态直接拒（按形态 regex，不是裸词）；
- **范围显式**：scope ∈ `global / group / agent:<id>`，非法值拒；
- **重复校验**：与既有 pending/approved 候选同 scope 且触发词重合度 ≥60% 判重复拒收；
- **触发词必填**：无触发条件的经验无法被相关性选择命中，拒。

置信度 = verified 证据占比（来源证据强度，非模型自评）。

**治理入口（同一 Core 事实源）**：

| 面 | 入口 | 语义 |
|----|------|------|
| REST | `GET /api/learning/candidates` | 清单（`?status=pending\|approved\|rejected`） |
| REST | `POST /api/learning/candidates/:id` | `{action: "approve"\|"reject", decidedBy, reason}`；回执带 `promotion{ok, refId, version, error}` |
| CLI | `exm learn list [--status <s>] [--limit <n>]` | 清单（证据/置信度/转正落点） |
| CLI | `exm learn approve <id>` / `exm learn reject <id> [原因]` | 裁决（decidedBy=`cli`） |
| 聊天 | `/learn [list [状态]]` | 读面人人（候选/证据/置信度可见） |
| 聊天 | `/learn approve <id>` / `/learn reject <id> <原因>` | 写面仅管理员 |

事件：`learning.candidate.created / approved / rejected / promoted / promote_failed`
（归属来源会话，可审计）。**批准 ≠ 生效**：转正失败不回滚用户裁决，回执 `ok=false` + error +
`promote_failed` 事件，落点不留半成品；REST/CLI/通道三处回执都如实透出。

### 记忆/技能版本与受控写入（agent-learning-loop 6.5）

**受控写入**：技能更新走 `write_skill_versioned`——校验（格式/大小 ≤30k/敏感信息标记/agents 范围）
全部通过才落盘；**拒绝时旧版本原样、不留半成品**。`skill_manage` 工具的 create/update 同链路
（模型自改进与人工治理共用一版本事实源）。

**技能版本链**：`SkillDef.version` 单调递增（每次成功更新/回滚 +1，frontmatter `version`/`updatedAt`
持久化）；旧版本归档 `<id>/.history/v<N>.md`。删除 = 停止加载 + `.deleted` 标记，历史保留可读，
回滚（=恢复）清除删除态并续接版本号。REST：`GET /api/skills/:id/versions`
（`{id, current, deleted, versions:[{version,name,description,instructions}]}`；已删除时
`current=null`）、`POST /api/skills/:id/rollback`（`{toVersion, by}`）、`GET /api/skills/deleted`
（`{skills:[{id,deletedAt}]}`，空清单 200+[]）。事件：`skill.updated / rolled_back / deleted`。

**记忆版本链**：`MemoryEntry.version`（旧数据无字段按 v1 陈述）+ 追加式
`memory/history/<id>.jsonl`（`change ∈ created|updated|rolled_back|forgotten|restored`，
行内含该版 title/body/tags/kind）。更新/回滚/恢复都只追加新版本（版本号单调 +1）；**遗忘不是硬删**：
forget 版本 +1 并追加 `forgotten` 行，内容不再召回/注入，`restore` 再 +1 回到可见；无变化的更新不
升版。同内容 `remember` 按 `content_hash(title, body, group)` 去重，返回既有条目（不新增版本）。
REST：`GET /api/memory/:id/versions`
（`{id, current, forgotten, versions:[{version,change,title,body,kind,tags,changedAt}]}`）、
`POST /api/memory/:id/rollback`（`{toVersion, by}`）、`POST /api/memory/:id/restore`（`{by}`）、
`GET /api/memory/forgotten`（`{entries}`，空清单 200+[]）。请求体字段为 **camelCase**
（`toVersion`/`by`）。事件：`memory.updated / rolled_back / forgotten / restored`。

**相关性选择与预算注入**：技能注入按触发词命中（`SkillDef::matches`），不相关技能不进入提示词；
记忆注入由任务意图/作用域/触发词选择并按正文预算裁剪。注入一律带来源与版本：技能
`[来源：技能 <id> v<N>]`（ref_id `skill:<id>#v<N>`），记忆 `[来源：记忆 <id> v<N>]`
（规划路径行首；派发 ref_id `memory:<id>#v<N>`；单次最多 3 条，多条以 `;` 连接）。

### 定时任务时区与推送（`automation.timezone`）

- `automation.timezone`：IANA 时区名（如 `Asia/Shanghai`）；空串/非法名回落 UTC（旧行为零变更）。
  cron 表达式按该时区解释——`0 8 * * *` 表示本地 8 点，而非 UTC 8 点。
- `schedule` 工具 create 可选 `notify_channels[]`（任务完成后把结果摘要推送至订阅通道）与
  `session_title`（结果回投到指定标题的会话）；缺省 = 不推送（旧行为）。
- create 回显 `nextRunAt` 按配置时区本地渲染（`%Y-%m-%d %H:%M %Z`），避免「UTC 时间当本地」误读。

### 上下文压缩阈值（`compaction` 配置节）

| 字段 | 默认 | 行为 |
|------|------|------|
| `compaction.triggerRatio` | 0.6 | 上下文窗口占比触发线（0–0.95，0 = 关闭占比判据） |

双判据取先到者：占比先到（`预算 token × triggerRatio`）或条数兜底（40/20）命中即压缩；
压缩成功发 `context.compact` 事件（trigger / beforeTokens / afterTokens / compactedMessages）。
缺省值与旧行为等价：不配置时仍按条数兜底触发。

### 搜索聚合（`search` 配置节）

- `search.backends[]`：多后端数组，元素 `{provider, endpoint, apiKey, weight}`；旧平铺字段自动迁移为单元素数组。
- `search.contentFetchN`：合排后前 N 条并发抓正文（查询词窗口截取）；`web_search` 工具可用 `includeContent` 按次开启。
- 单后端 = 旧行为等价（无聚合标注）；多后端并发 + URL 规范化去重 + 权重×排名倒数合排（多源印证加分）。

### SyncReport（子个体回流，强制校验）

```json
{
  "sourceAgent": "identifier（运行时强制校正）",
  "taskNodeId": "T1",
  "status": "done | in_progress | blocked | need_arbitration",
  "statements": [{ "tag": "报告", "text": "…", "evidenceLevel": "A" }],
  "summary": "结论摘要（上游不读原文也能决策）",
  "evidence": [{ "level": "A|B|C|D", "kind": "code|config|log|test|command|doc|userInput|reasoning", "ref": "…", "note": "…" }],
  "risks": [{ "text": "…", "severity": "low|mid|high", "revertPath": "（可选）" }],
  "blockers": [{ "reason": "…", "unblockCondition": "…" }],
  "conflicts": [{ "parties": ["a", "b"], "point": "…", "levels": { "a": "A" }, "suggestion": "…" }],
  "nextSuggestion": { "handoffTo": "（可选）", "appendNodes": "（可选）" },
  "confidence": 0.0
}
```

校验失败自动重写（≤2 次），仍失败升级裁决。`statements` 至少一条、`confidence ∈ [0,1]`、
冲突必须显式保留在 `conflicts` 而不得静默覆盖。

**受控修复（sync-report-resilience）**：结构失败原因为白名单字段
（`summary` / `confidence` / `title` / `agentIdentifier`）missing field 时，
解析层补齐后重反序列化一次：缺 `summary` → 首条 statement 截 200；缺 `confidence` → 0.5；
嵌套 `appendNodes` 别名漂移 → 空串放行（核心身份字段仍由业务校验兜住）。修复成功打
`repaired: true` 旁路标记（事件与回流可见，指挥体可识别低置信来源）。白名单外
（核心字段缺失/类型错误/业务约束失败）维持原报错，不静默修复。每次校验失败独立落
`report.rejected` 事件（首个失败字段 + 原文长度），连续失败计数语义不变。

## REST API（前缀 /api）

### 统一连接身份与登记契约（版本1）

`exm_core::connections::identity` 提供无I/O的身份/登记状态机；这些类型和关系不构成执行授权，也不表示外部成员或操作服务已经可用。

| 记录 | 序列化字段与约束 |
|---|---|
| `ConnectionRef` | `instanceId/connectionId/generation/kind`；实例及连接ID为非空规范UUID，登记代际为随机UUID v4；类型为`software/external_agent/device` |
| `SourceRef` | `kind/sourceId/scope/subresourceId/lifecycle/revision`；来源为`nexus/mcp/plugin/device/software`，只保存非秘密引用 |
| `SourceScope` | `instanceId/authorityId/accountId/projectId`；来源域不使用当前URL，账户不是显示名；无项目不是任意项目通配符 |
| `ConnectionRegistration` | `reference/source/displayName/state/revision`；登记revision为正，状态为`legacy_unresolved/disabled/enabled/deleted` |
| `RegistrationBinding` | `connection/source/registrationRevision`；仅是后续grant/审批绑定的目标快照，不是grant |
| `ConnectionRelation` | `id/kind/from/to/revision`；`embedded_in/provided_by`方向均为独立AI→软件或设备，revision用于CAS |

完整连接四元组才标识一次登记。名称从不参与匹配；来源revision是快照版本，不是生命周期证据。不同安装、来源域、账户、项目、子资源、类型及生命周期不得因远端ID相同而合并。
已知生命周期为`{"state":"known","generation":"来源代际引用"}`，新登记默认禁用；无法证明生命周期时为`{"state":"legacy_unresolved"}`，不能启用或取得新路径授权绑定。
删除保留tombstone，重新登记生成新代际；禁用再启用递增登记revision，原绑定不能复活。来源账户、端点绑定或生命周期变化须先使旧登记失效，不能原位复用批准。

所有持久结构解码执行嵌套校验并拒绝未知字段。`RegistrationSnapshot`包含`schemaVersion/instanceId/registrations`，只从受信存储恢复，恢复须传入当前实例并校验重复来源/代际及历史顺序；客户端提交快照不能获得管理权。持久层另须串行提交，不能以旧快照覆盖新状态。
`validate_binding`只证明当前身份/代际仍匹配；后续操作仍须交集检查来源、主体、项目、会话、能力、数据、根执行及批准。关系可展示禁用/未纳管对象，但不继承凭据、grant、成员资格或模型档案，也不修改旧Agent绑定边。

关系服务`ConnectionRelationService`使用FsDb的`connection_relations/state.json`单文档，仅存关系引用和删除tombstone；端点名称与来源域每次由当前登记投影，不维护第二套来源配置。
创建须`expectedRevision=0`且候选revision为1，更新须精确匹配当前revision并恰好递增1；删除也递增revision，重放已删除关系ID拒绝，新关联须新ID。服务共享同一个锁，在CAS及校验后先提交磁盘，再发布内存；失败不发布半次更新。
读取校验当前端点代际，删除重登记后旧关系不按名称复活。来源编辑委托只含`sourceKind/sourceId`，原服务根据完整来源引用重新校验账户、项目和管理权限，没有任意URL、命令或新配置保存入口。
管理调用必须在持有当前登记锁期间执行，不能用排队时旧副本；同一数据根须单个服务实例共享clone，不宣称支持独立多进程写者或额外掉电保证。关系及端点ACL仍在查询层求交。

### 统一连接能力契约（版本1.0）

`exm_core::connections::capability` 当前仅接受`version:{major:1,minor:0}`，其他版本拒绝。wire声明由`CapabilityDescriptor::from_json`先检查64KiB字节上限，再解码并校验；普通Serde解码本身不表示宿主验证或授权。

声明必含`id/revision/role/inputSchema/outputSchema/dataDestinations/limits/support`；`effects`缺省或为空时按未知处理。
角色为`resource/tool_provider/question_answerer/task_executor/collaborator/event_source/sensor/actuator`；资源不可执行，MCP工具清单不能推导任务或协作角色。
任务执行者须声明任务生命周期，协作者还须声明双向协议；实际准入需对应的独立宿主验证证据，不因声明为true而成为组成员。

- 效果集合为`read/write/publish/privacy/physical/charge/unknown`；不认识的效果字符串降为`unknown`。只有仍有效的契约与效果验证共同证明只读，才可作为只读审批候选，仍不是免授权许可。
- 宿主风险只增不减，传感能力至少包含隐私风险、实体执行至少包含物理风险；远端只读自述不能覆盖宿主判定。
- 数据目的地是`local`或`remote`的`endpointRef/accountRef`，不是任意URL。输入输出使用闭合有界JSON方言，支持null、布尔、整数、数值、按UTF-8字节限制的字符串、有限数组和闭合对象；不支持完整JSON Schema、`$ref`、组合或任意附加属性，不支持的schema字段拒绝。
- schema深度最多8、节点128、对象字段64、数组项1024；单个载荷节点最多16384。声明输入/输出最多1MiB、事件输出64KiB、超时600000ms、能力并发最多32，均须为正。操作仍取配置、来源与父执行的更严格上限，能力并发32不放宽每连接默认4。
- `support`分别声明幂等`unsupported/request_key`、取消`unsupported/request_only/confirmed`、计量`unknown/usage_report/hard_cost_limit`，及`taskLifecycle/bidirectionalCollaboration`；这些不是已强制生效的保证。

私有`CapabilitySnapshot`不从wire恢复宿主事实。只读投影分别显示声明、检测、契约/效果验证、可用性、当前调用者授权及各项保证；证据绑定完整声明、来源绑定键、检查项、观察时间与有效期。来源绑定键由宿主身份服务建立，必须覆盖安装/项目/登记代际/账户/端点及来源revision，不能由远端自报。
证据来源区分`host_inspection/isolated_fixture/product_platform`；模拟通过不能展示为真实产品或硬件已验证。检测证据不可复用为授权、取消确认或强制费用证据；更换声明即使复用revision也不能继承旧证据。
`check_admission`只做能力预检，检查当前可用性、证据、角色、目的地、输入及收紧限额；它不派发动作，也不替代当前grant、材料白名单、参数审批、根预算或设备逐次确认。过期/陈旧/禁用状态拒绝新预检。

### 本地登记、凭据引用与安全导入

`ConnectionRegistrationStore`使用受信`dataDir`下的独立FsDb文档保存安装实例、登记快照和不透明凭据引用；不读取来源、不启动连接、不解析凭据。安装实例为随机规范UUID，首次初始化必须同时写入安装文档和登记文档；缺一、损坏、未知schema、非普通文件或超限文档均拒绝打开，不能按空库继续。
凭据引用只有完整`SourceRef + credentialId + revision`，`credentialId`为非秘密UUID对象标识；不保存URL、环境变量名、密钥、token或可消费凭据。引用必须与当前登记的来源完整相等，替换/清除会使登记禁用并令旧绑定失效；删除会清除引用，重登记不继承。
本地更新在进程内锁中执行clone→校验→原子写入→发布；写失败不改变内存登记。该锁不宣称跨进程事务、抗受信目录回滚或掉电fsync，Core不能让多个进程写同一数据根。
跨实例只允许`RegistrationReferenceBundle` refs-only交换：仅含类型、来源ID、账户/项目范围等重新登记线索；不含显示名、旧连接ID/代际、凭据、生命周期证据、grant、活动租约、回调或设备确认。导入到当前安装会生成新的连接ID/代际，固定`legacy_unresolved`和禁用态，不能启用或恢复旧绑定；来源须重新核验后才可能登记。
导入拒绝未知字段和权限载荷，整批校验后才提交；冲突或写失败不写入，也不修改原来源文件。登记存储的身份检查仍不是grant，目录和操作服务必须继续执行主体、项目、会话、能力和来源授权交集。

### 连接操作观察状态（纯值契约，私有快照版本2）

`ConnectionOperation`只保存受信宿主创建的操作身份、精确远端关联、四轴状态和有界状态记录；当前模块不派发、不持久化操作账本、不实现预算/回调认证/适配器。身份至少绑定`operationId/requestId/actorRef/projectId/sessionId/rootExecutionId/executionId/memberInstanceId/evidenceSessionId/connectionRef/capabilityRevision/authorizationRevision`；`capabilityRevision`是与能力描述同口径的正整数，`authorizationRevision`是宿主授权快照的有界不透明引用，不携带或恢复grant。远端关联还绑定本地操作/执行、连接代际、远端实例、task及可选context，不能按标题、提示词或旧会话认领。

四轴彼此独立：

| 轴 | 允许的含义 |
|---|---|
| 执行 | `prepared/awaiting_approval/queued/accepted/running/awaiting_input/result_received/failed/cancelled/timed_out/unknown` |
| 验收 | `not_evaluated/pending/verified/rejected/blocked` |
| 外部效果 | `not_sent/not_applied/applied/partial/unknown` |
| 取消保证 | `local_stopped/remote_requested/remote_confirmed/unsupported` |

HTTP受理、进程退出零、非空文本、远端`claimed_done`只产生相应观察或结果状态，不自动成为verified/success；成功还须本操作关联的回执、宿主效果核验和必需验收证据。远端自述不能构造宿主事实，证据只保存有界记录引用、来源和操作/执行/证据会话绑定。
宿主在真实调用传输之前记录一次`dispatch_started`边界：排队或绑定远端标识不表示已发送；越过发送边界后效果先标未知，随后断连、超时或取消不得再显示`not_sent`。失败、取消、超时、未知和最终受阻/拒绝关闭新准入；迟到进度不能复活、回退或擦除不确定效果。远端取消请求、确认和不支持与本地停止分开，停止确认不表示回滚、无效果或费用归零。终态后的核验只能补安全记录，不能改写原失败或未知状态。
状态变更采用正整数revision的严格CAS，失败不修改对象；私有快照版本2只从完整历史重放并校验当前安装，不接受旧版本快照，不由wire字段恢复验收、效果、取消或授权。单操作状态事件最多128个，快照最多1MiB；这些是状态模型边界，不是操作服务的吞吐或持久化保证。发送前落盘、幂等、回调重放、根预算和真实执行仍须后续操作服务消费本契约。

### 目录可见性与有界查询

`CatalogService`是无I/O的目录查询服务，不是新来源仓库或执行授权。宿主从认证上下文构建`CatalogScope`，精确绑定actor、安装、项目、会话及`management/agent`消费面；管理面评估不能用于Agent，即使actor相同也必须重新求交。
来源owner每次提供当前登记和真实读取评估`HostCatalogAccess`，连接/能力/关系分别使用完整引用及各自版本。没有来源ACL时只能`deny_all`；`None`项目、`None`会话都不是通配符，不能把请求JSON或UI已登录状态当成宿主事实。

查询顺序固定为连接与来源可见性→能力自身/关系自身及两端ACL→搜索、计数、分页或一跳邻域。隐藏与不存在对象统一返回`NotFound`；不能通过私有关系、能力计数或邻接度暴露对象存在。连接可见不表示全部能力可见，能力执行授权始终未知，不能把读取评估转成grant。
目录只输出闭合安全摘要，不含凭据状态/元数据、端点、schema、数据目的地、证据绑定键或原始错误；这些不能经管理者摘要旁路泄露。全局来源revision及由其递增的登记revision不进入摘要或公开游标，避免隐藏对象变化影响可见响应。

- 搜索为有界字面量匹配，最多256字节，控制字符拒绝；不是正则或表达式。
- 默认每页50、最大200，零及超限拒绝。连接、能力、关系分别分页；邻域仅一跳并按边分页，返回邻居/边均不超过页上限，`total/truncated/nextCursor`只反映可见结果。
- 游标是随机UUID，绑定完整查询、原始limit、目标、scope、当前范围ACL revision及可见安全摘要；每次翻页重新执行ACL。隐藏变化不改变响应或有效游标，可见变化/撤权则拒绝旧游标。
- 游标有效期5分钟、最多1024项，过期/跨范围/被逐出或服务重建统一拒绝并要求重查；不把客户端时间戳当宿主时间，也不通过猜offset恢复。

当前只落领域服务；来源owner评估、HTTP/命令和页面接线仍须各自验收，不能由查询服务存在推断Agent入口或整个连接目录已交付。

Gateway的`GET /api/connections`是单独的实例管理只读入口：必须配置并提供实例管理访问密钥，拒绝带项目/会话作用域的请求；不接受Agent身份，也不把读取结果作为授权。该接口只读取本地来源投影，不刷新来源、不探测、不启动进程、不改全局目标或配置；连接、能力、来源与执行授权的状态不能由目录可见性推导。查询支持有界字面搜索、类型/来源筛选和分页；从第二页起必须携带服务端返回的`nextCursor`及对应`nextOffset`，游标绑定当前查询和快照，失效时重新查询。WebUI只调用该GET，不回退到Nexus拓扑或来源接口；分页失效时保留最近成功页并明确提示，用户显式刷新才丢弃旧游标并重新读取首屏，首屏失败也不能呈现为“空目录”。开发回归脚本为`npx tsx scripts/connection-directory-ui.ts`，使用隔离loopback夹具并拦截外网；不得连接真实账户或硬件。缺失目录路由的旧网关明确报错，不回退到宽权限操作入口。

### 来源快照的版本与失效协调

`SourceSnapshotCache`仅缓存安全登记/能力材料，不是来源配置或授权事实源；调用方自行读取来源，它不联网或恢复执行。
每次读取由当前cache签发不可反序列化的代际票据，成功结果须逐条匹配权威登记的完整引用、来源、状态和revision后一次性替换；旧票据、旧代际和半次坏批次拒绝。
来源读取失败仅将该来源最近成功数据标陈旧，保留原观察时间、首次陈旧时间和稳定错误类别，不清其他来源，也不把失败当空集合。权威确认缺失的对象保留名称和原代际并标失效；相同登记版本重新出现仍拒绝恢复，须先重验登记版本或重新登记，以免旧批准复活。
观察时再次与登记owner对账，禁用再启用、删除重建或版本变化不会恢复旧快照；旧grant/审批目标仍须由`validate_binding`及实际来源准入共同拒绝。`is_current_for_binding`只检查既有身份绑定与新鲜来源版本这一必要条件，陈旧/失效时为false，不授予执行权限。
来源分区最多128、每来源含历史最多4096个对象、每对象能力最多200；超限明确拒绝，不静默清空旧数据。对外结果还须先ACL再分页，不能将内部完整缓存直接返回给Agent。

**机器可读契约**：`GET /api/openapi.json`（OpenAPI 3.1，运行时公共面端点，无需鉴权）或离线 `exm openapi [--out <file>]`——两者同源（`exm-gateway/src/openapi.rs` 静态清单），由路由对账集成测试守护与实际路由一致（幽灵端点/漏项即红）。下表为人读摘要；schema 精度：路径/方法/鉴权/错误族全覆盖，请求体渐进补，响应 schema informational。

OpenAPI 的操作键使用标准小写方法名（`get`、`post` 等），路径参数使用 `{id}` 并在路径项中声明 `in: path`、`required: true`。例如，本文的 `/sessions/:id/chat` 在机器契约中写作 `/api/sessions/{id}/chat`；实际 HTTP 地址不变。消费旧导出文件的脚本需要同步这两种表示。

`authKey` 描述 `X-Auth-Key` 头，`bearerAuth` 描述 `Authorization: Bearer <key>`，两者任选一种。启用访问密钥时 `/health`、`/version` 同样需要鉴权；`/openapi.json` 和 `/auth/*` 为公开入口。文档提供通用 JSON 错误结构，并按操作列出相关错误响应。

**通用约定**：DELETE 幂等（D4 决议）——目标资源已不存在时返回 `{"ok":true}` 200（重复删除 = 成功）；路径参数指向的资源不存在 → 404，资源状态冲突（如处理中）→ 409，其余请求校验 → 400。

### 模型设置契约

上述模型接口的请求体、成功响应和示例在 OpenAPI `components.schemas` 中提供，运行时文档与 CLI 导出保持同源。

- 档案更新是部分更新：省略字段沿用已存值。主密钥的空串或 `***已配置***` 沿用；`__CLEAR__` 清除主密钥；`clearKeys: true` 同时清空主密钥和密钥池。密钥池支持明文、掩码哨兵和 `{ "keep": 0 }` 索引引用。读取只返回掩码。
- `clientIdentity` 省略或为 null 时沿用；传 `{ "preset": "default" }` 关闭，默认身份不能携带非空覆盖值。可用预设、ASCII 值限制与头部名称范围见 [客户端兼容身份](客户端兼容身份.md)；头名的大小写重复由服务端校验。
- `/llm/identity` 接收档案 ID 或 `baseUrl`、`apiFormat`、`model`、`clientIdentity` 草稿，返回配置协议、生效协议、路径、标识头、元数据启用状态及协议匹配状态。该操作不访问上游、不保存配置。`upstreamVerified: false` 表示预览未验证上游的客户端分类。
- `/llm/test` 接收 `{ "id": "档案ID" }`，空对象测试当前生效配置；可临时覆盖 `baseUrl`、`apiFormat`、`model` 和 `clientIdentity`，未提交的密钥沿用服务端值，草稿不落盘。它复用推理请求及响应解析：HTTP 失败、流内失败、不完整 Responses 流或空回答均以 HTTP 200 携带 `ok: false`、`status` 或 `error` 返回，档案不存在为 404；响应中的 `identity` 显示这次探测的请求格式。
- `/llm/models` 使用档案 ID 时沿用服务端的端点、密钥与协议，可带 `clientIdentity` 临时覆盖身份；没有 ID 时必须提交 `baseUrl`，可带明文 `apiKey`、`apiFormat` 和身份配置。该操作不保存配置。Azure 返回空清单与手工填写部署名的说明。
- `/llm/capabilities` 省略或为 null 的字段沿用，空串清除；响应回显四个能力槽位。
- `/llm/effort` 返回 `effort`、`reasoningTokenCap` 和 `effectiveCap`。PUT 中省略或为 null 的字段沿用；`reasoningTokenCap < 1024` 恢复默认安全网 16384，其余值设为进程级上限。`effort` 接受 low / medium / high，其他字符串归一为 medium。

### 会话内容检索（`GET /api/sessions/search`）

- 参数：`q`（必填，去空白后为空 → 400）、`limit`（缺省 20，钳制 1~50）；
- 范围：未归档会话（最多 200 个）的标题 + 各自**最近 200 条消息正文**，大小写不敏感；只读、无索引；
- 排序：标题命中优先 → 同组按会话活跃时间倒序；
- 响应：`{query, hits:[{sessionId, title, titleMatch, messageMatches, snippets, lastActiveAt}]}`；
  `snippets` 每会话最多 2 条，单条形如 `{messageId, role, text, createdAt, agentId?}`，
  `text` 截断至约 80 字符且保留关键词（`messageId` 供 WebUI 定位高亮）。

配置了 `authKey` 时，普通 `/api/*` 入口要求 `X-Auth-Key`（或 Bearer）；公开入口为 `/api/openapi.json` 与 `/api/auth/*`。事件 webhook 和配置了独立凭据的通道入站使用各自的校验方式；资产 GET 还支持查询参数 `key`，详见相应接口说明。

### 记忆条目编辑（`PUT /api/memory/:id`）

- 请求体：`{title?, body?, tags?, kind?}`——缺省字段不改动；空串视为「未提供」（清空正文不等于删除，删除走 `DELETE /memory/:id`）。
- 内容（title/body）变更时重算内容哈希并迁移去重索引、重建倒排索引；`createdAt` 不变，`updatedAt` 刷新。
- 改后与其它条目内容哈希相撞 → 400（避免覆盖对方去重索引）；id 不存在 → 404；非法 `kind` → 400。
- 成功后同步重渲染 memory.md（面板与文件记忆同源）；CLI 对应 `exm memory edit <id> --title/--body/--tags/--kind`。

首启引导：部署后首次启动且未配置 `authKey` 时，前端经 `/auth/status` 判定并展示「设置访问密钥」页（与登录门共用主题）；「下次再说」只记进程内（网关重启恢复提醒），「不再提醒」持久化 `security.keySetupDismissed`；两个动作在已配置密钥时均被拒。

## 存储布局

```
.exmachina/                    # 运行状态（git 忽略）
  config.json                  # 唯一配置事实源（三端共用，热生效）
  memory.md                    # 全局浅层记忆人读视图
  trash/<日期>/                 # 回收站（filesystem delete 暂存；保留期/容量自动清理，见 trash 配置块）
  data/                        # Store + MemoryStore + CronStore（深层记忆库）
    turn_snapshots/            #   会话轮次快照（{sessionId}:{turn}.json，undo / 编辑重发 / fork 基座）
    identities/                #   通道用户绑定（配对码换发的长期身份，admin/member）
    event_triggers/            #   事件触发器（文件监听 / webhook 事件源）
  inbox/<通道id>/              # 入站媒体落盘（图片 / 语音 / 文件，转多模态或路径注入）
  outbox/                      # 出站产物投递（filesystem write 约定目录 + send_file 登记源；收束时排空经通道直发）
entities/                      # 编成数据（不是代码）
  groups/<gid>/                # 组（内置默认组 = groups/exmachina，builtin=true，id 固定）
    group.json                 #   组元数据（primary 指向主智能体）
    SOUL.md                    #   主智能体人格（组对用户的脸面；仅用户面有 SOUL）
    MEMORY.md                  #   组浅层记忆（人读快照，容量受限；深层在记忆库）
    agents/                    #   成员定义（主智能体 + 子个体，一人一 json）
    prompts/                   #   成员系统提示词（一人一 md）
    adaptations/               #   子个体经验要点（运行时）
    playbooks/                 #   组链路模板
    protocol/                  #   组级协定与工作流程规则
  agents/<id>/                 # 智能体（用户面）：agent.json + PROMPT.md + SOUL.md + MEMORY.md
  skills/<id>/SKILL.md         # 技能包（集群共享；frontmatter + Markdown 正文）
  templates/                   # 组模板
  default-soul.md              # 共享兜底人格
  active_group                 # 激活组指针（运行时）
  active_single                # 独立智能体指针（运行时）
  active_workspace             # 当前工作区指针（运行时）
webui/dist/                    # WebUI 构建产物（网关托管）
desktop/                       # 桌面端（Tauri 壳：自带本地网关 / --remote 远程直连）
```

**记忆分层**：深层记忆 = MemoryStore（数据库：混合检索 / 衰减 / AI 压缩 / 经验沉淀，按组与个体隔离）；
浅层记忆 = `MEMORY.md` / `memory.md`（自动渲染的人读快照，**容量有限**，超出即截断——完整记忆永远在深层库）。
**SOUL 分层**：SOUL 仅用户面智能体持有（组主智能体 = 组根 SOUL.md；智能体 = 目录内 SOUL.md）；
子个体是执行单元，无人格层——统一智械纪律内建于各自系统提示词。
**SOUL 保护**：内置组的出厂人格随项目内容交付、运行时无副本可复原，故允许改写但**禁止重置**
（重置语义 = 删文件回落共享默认，抹掉出厂人格不可逆）；自定义组与智能体可自由改写/重置。

## 通道能力矩阵

出站能力（媒体直发 / 打字指示）按平台静态声明（`platform::caps`），与各适配器实际实现同步——
支持即直发、不支持按类型降级（图片→链接注记、文件→工作区相对路径、语音→文字摘要），不猜能力。

| 平台 | 图片 | 文件 | 语音 | 打字 | 回复上限¹ | 审批指令² | 接入形态 |
|---|---|---|---|---|---|---|---|
| telegram | ✅ | ✅ | ✅ | ✅ | 3800 字符 | ok:/no: | 内置（长轮询） |
| discord | ✅ | ✅ | ➖³ | ✅ | 1800 字符 | ok:/no: | 内置（Gateway WS） |
| slack | ✅ | ✅ | ➖⁴ | ➖⁴ | 3800 字符 | ok:/no: | 内置（Socket Mode） |
| napcat (QQ) | ✅ | ✅ | ✅ | ➖⁵ | 3500 字符 | ok:/no: | 内置（OneBot 11 正向 WS） |
| matrix | ✅ | ✅ | ✅ | ✅ | 3800 字符 | ok:/no: | 内置（/sync 长轮询） |
| qqbot (官方) | ➖⁶ | ➖⁶ | ➖⁶ | ➖ | 3500 字符 | ok:/no: + 按钮⁸ | 内置（开放平台 WS） |
| webhook / qq / wechat 桥接 | ➖⁷ | ➖⁷ | ➖⁷ | ➖ | 跟随回调 | ok:/no: | 桥接（POST inbound） |

注：
1. 回复上限 = 长回复分段的单段字符预算（`split_reply`），超限自动分段。段数封顶防 IM 刷屏：
   默认 24 段；QQ 官方机器人因被动回复每条入站消息限 ~5 次（群 5 次/5 分钟）收紧到 4 段
   （审批/计划推送共享同一额度）。触顶截断并注明「完整回复见工作台会话记录」；
   完整长文交付应走文件产物。
2. 审批指令 = 通道内快捷裁决：`ok:<单号>` 批准 / `no:<单号>` 拒绝（单号见审批通知文本）；
   全通道一致，另可经 WebUI 审批页处理。QQ 官方机器人在平台支持 markdown / 自定义键盘时
   以「批准 / 拒绝」按钮呈现（点击等价于发送对应指令；群聊点击后发送即可），失败自动回落文本。
3. discord 无原生语音条目形态，语音产物降级为文字摘要。
4. Slack 机器人无输入中指示 API（typing 降级关闭）；语音降级同 discord。
5. OneBot 11 无标准 typing 动作。
6. 官方机器人被动消息正文仅支持文本（审批消息例外：富消息三级回落——markdown + 内嵌键盘
   → 纯文本 + 键盘 → 分段纯文本；2026-04 起群/单聊自定义 markdown 已开放到所有机器人，无需
   申请模板，但仍可能被内容审核拒收，回落链保证按钮尽量保住、审批单不丢），富媒体需另走
   richmedia 上报链路（全降级）。
7. 桥接类回复能力取决于回调端实现；`send_file` / 产物投递在桥接通道走控制台附件卡交付。
8. QQ 官方机器人审批按钮：按钮为「指令按钮」——单聊点击自动发送 `ok:/no:`，群聊点击后
   填入输入框（带 @机器人）由用户发送；无需额外 interaction 回调权限。按钮 action 只用
   官方 schema 字段（type/permission/data/enter/unsupport_tips），非标字段会导致整条消息
   400 被拒。

入站能力（各通道一致）：文本 / 命令 / 图片入站（视觉模型可读）；`/stop` 停止指令全通道一致。
聊天流固定单会话（一条流恒定复用一个会话）：`/new` `/sessions` `/use` 已退役（回执说明，不改状态）；
通道 → 组绑定与会话白名单（`allowedChats[]`）同口径。

## 扩展点

- **内置工具面**：`read` / `edit` / `patch` / `grep` / `glob` / `filesystem` / `terminal` /
  `web_search` / `web_fetch` / `schedule` / `browser` / `computer` / `agent_manage` / `spawn` /
  `sessions` / `skill_manage` / `memory_read` / `memory_write` / `memory_link`。
  派发白名单 = 个体编成 JSON 的 `tools` 清单；例外：组主智能体默认追加 `agent_manage`（自定义组）、
  记忆三工具、`sessions` 与 `skill_manage`（默认授权，仍可经清单显式控制）。
  `web_search` / `browser` / `computer` 在后端能力未就绪时不下发（不承诺不存在的能力）。
  记忆三工具组隔离在工具层强制：检索与写入恒定「激活组 + 全局条目」范围，
  写入来源标注 `source=agent`，与事后归纳写入相互区分。
  `sessions` 的组隔离同样在工具层强制：目标会话必须同 `groupId` 且同 `memoryPartition`，
  跨组/跨分区不暴露存在性；投递默认异步，`wait=true` 才等待目标会话完成。
- **新渠道**：消费同一 REST/WS 契约即可接入（WebUI / Telegram / QQ 官方机器人 / NapCat / Discord /
  Slack / Matrix / Webhook 皆此模式）。
  桥接类平台（webhook / qq / wechat）把消息 `POST /api/channels/:id/inbound`，回复走 replyWebhook 或事件流；
  telegram（长轮询）/ qqbot（开放平台 WS）/ napcat（OneBot 11 正向 WS）/ discord（Gateway WS）/
  slack（Socket Mode）/ matrix（Client-Server API /sync 长轮询）为网关内置适配器，收发直达原会话。
  通道实体含 `allowedChats[]`（会话白名单，空 = 不限）与 `config{}`（平台扩展配置：
  qqbot → appId / appSecret / sandbox；napcat → url / token；slack → appToken；
  matrix → homeserver。discord / slack / matrix 的 bot token 或 access token 走顶层 `token`）。
  **密钥脱敏**：通道接口（列表 / 创建 / 更新响应）对顶层 `token`/`secret` 与平台敏感 `config` 键
  （qqbot.appSecret、napcat.token、slack.appToken）掩码回显（`***已配置***`）；
  更新时掩码 = 沿用旧值、空 = 清除。
  **运行状态**：`GET /api/channels/status` 返回 `{ <通道ID>: { state: "ok"|"error", detail, at } }`，
  由内置适配器在连接 / 断开 / 出错时覆盖上报（桥接类无运行时不产生条目）；通道删除 / 停用即清除。
  更新通道（PUT）body 无须携带 `id`（以路径参数为准）。
  六个内置适配器共用 `platform::ChannelRun`（组绑定 → 会话键 `channel:<通道ID>:<会话键>` 复用 →
  订阅事件 → 执行 → 组还原）与 `spawn_reply`（收束陈述回帖），平台差异只在发送闭包内。
  **聊天流固定单会话**：一条流（一个群 / 一个私聊）恒定复用一个活跃会话（`flow_active_session`
  绑定，失效自动重建）；流内会话切换（`/new` `/sessions` `/use` 指令与
  `GET|PUT /api/channels/flows/:id/sessions|active` 端点）已退役——旧指令仅回执说明，不改状态。
- **新模型协议**：实现 `LlmProvider` trait（`chat` + `stream`，SSE 增量经 channel 发出），
  或在 `provider.rs` 的格式分支中加一种 URL / 鉴权 / 解析规则（现含 openai / anthropic / gemini / azure）。
- **新技能包**：`entities/skills/<id>/SKILL.md`（YAML 风格 frontmatter：id/name/description/triggers/agents/source + Markdown 正文 = instructions），热装载，
  任务目标命中触发词即随派发注入；旧 `*.json` 单文件仍可读（同 id 时 SKILL.md 优先）。
  **自改进闭环**：主智能体可用 `skill_manage` 在任务后沉淀/修正技能；每次派发注入后按节点终态写
  `entities/skills/.usage.jsonl` 侧车（使用次数 / 成功次数 / 最近使用时间），`GET /api/skills`
  回读时聚合为 `useCount` / `successCount` / `lastUsedAt`。统计不写入 SKILL.md——技能文件保持
  可分享的纯内容格式，导入/导出（`POST /api/skills/import`、`GET /api/skills/:id/export`、
  `exm skill import|export`）零污染。
- **动态命令**：终端可用 `exm --session <id> command list` 查询当前会话；TUI `/help` 的动态区只显示可执行项。`exm --session <id> command run skill.<id> --args '{"input":"任务"}'` 或 `/skill.<id> {"input":"任务"}` 显式选择技能；命令版本为 1，正文仅注入本轮模型输入，保留技能的 `agents` 范围及原会话工具权限。
  插件在 `plugin.json` 用 `"commands": {"工具名": {"version": 1, "requires": ["tools.execute"]}}` 显式注册 `plugin.<插件id>.<工具名>`；已有模型工具不会自动转为用户命令。命令只能绑定该插件自己的工具；`version` 是命令语义版本，独立于插件包版本，脚本可通过 `command run --command-version <版本>` 校验。`requires` 只收窄宿主能力，不能授予权限；未确认的依赖、已禁用插件、缺凭据或未就绪的进程工具不显示为可执行。计划模式不直接执行效果未分类的插件工具，实际调用继续使用既有工具闸门。
- **新个体**：子个体加 `groups/<gid>/agents/<id>.json` + `prompts/<id>.md`；智能体加
  `entities/agents/<id>/`（agent.json + PROMPT.md + SOUL.md），热装载即生效。
