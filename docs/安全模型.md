# 安全模型

> 本文档描述 EXMACHINA 的安全体系分层与各层职责。配置项均可在 WebUI 设置页对应分组调整。

## 总览：纵深防御五层

```
入站消毒 → 通道身份管控 → 工具闸门（白名单/审批） → 沙箱执行（净化/隔离/限资源） → 执行身份约束（uid 降权）
   ①             ②                  ③                        ④                            ⑤
```

| 层 | 机制 | 文档锚点 |
| --- | --- | --- |
| ① 入站消毒 | 伪装系统指令/指令劫持/工具结果伪装/隐藏字符 改写与剥离 | 设置页「安全」消毒开关组 |
| ② 通道身份管控 | 白名单用户 + 对方配置才可执行（群聊门控） | 设置页「通道」 |
| ③ 工具闸门 | 命令白名单（AllowRule）+ 审批闸门（off/risky/always） | 本文 §审批闸门 |
| ④ 沙箱执行 | 环境净化（HOME/TMP 重定向）+ bwrap 系统级隔离 + ulimit/作业对象限资源 | 设置页「沙箱」 |
| ⑤ 执行身份约束 | 子进程降权到专用用户 + 工作目录路径校验 + root 提权审批 | 本文 §执行身份约束 |

## 执行身份约束（agent-exec-confinement）

### 机制

Linux 下可将 Agent 的终端子进程**降权到专用非 root 用户**执行（`security.execUser`，用户名或数字 uid），并校验工作目录处于配置路径边界内（`security.execHome`，默认 `/home/<execUser>`）：

- **降权**：网关（容器内通常 root）spawn 子进程时直接设置 uid/gid（内核级，无 su 解析面）；bwrap 同开时改用 `bwrap --uid/--gid` 原生参数。
- **路径边界**：子进程 HOME 固定 execHome；已绑定项目时 cwd 保持为该项目，但 canonicalize 后 MUST 位于 execHome 内；未绑定项目时 cwd 才使用 execHome。filesystem 工具做第二道路径校验。
- **缓存归属**：`CARGO_HOME` / `RUSTUP_HOME` 等用户级缓存同样固定在 execHome 下，不继承网关身份的缓存路径；项目目录只保存项目源码和产物。
- **权限边界分层**：文件工具显式校验项目路径；终端的实际文件访问范围由 OS 权限决定。单独设置 uid/gid、HOME 与 cwd 不等于 chroot 或 mount/network namespace，仍可访问其 OS 权限允许的其他路径；不能将其宣传为完整系统隔离。

### 子进程树与终端收尾

- 前台、后台和审批终端共用受管启动器。POSIX 每个命令拥有独立进程组；超时、所属轮次取消、后台 `kill` 及正常组长退出均终止组内残留进程，再回收直接子进程。后台网关所有者释放时同样请求清理。
- Windows 保留带 `KILL_ON_JOB_CLOSE` 的 Job Object；不可用时使用有界 `taskkill /T /F` 兜底，并明确报告无法确认的清理。
- stdout/stderr 读取与进程等待共用所有者，不分离成失去所有者的读取任务。直接子进程回收最多等待 3 秒，管道收尾最多再等待 500 毫秒；清理无法确认时返回失败说明，不把停止请求或不完整输出视为成功。
- 后台终端默认数据根并发上限 4、单任务截止 900 秒、每项脱敏日志上限 1 MiB（含 JSONL 封套）；超限时轮转保留输出尾部，游标给出当前保留范围和精确丢弃量。旧版无偏移日志的丢失量保持未知。会话删除会停止对应作业并删除其持久记录/输出。
- 正常网关关闭会停止并等待其后台作业。重启后对只有持久记录、没有进程句柄的 `running` 项标记为 `interrupted`，不按旧 PID 发信号、不重放命令；持久元数据不是可恢复的控制句柄。
- POSIX 进程组是生命周期边界，不能阻止程序显式调用 `setsid` 脱离进程组。需要更强隔离时仍须显式启用、验证 OS 隔离，不能以进程分组替代文件系统和网络安全边界。

### root 提权审批

约束开启时，提权命令（`sudo`/`su`/`doas`/`run0`/`runuser` 前缀，含链式命令中任一段）**无视白名单**直接进入人工审批：

- 审批单以 `[root] ` 前缀标识，WebUI 审批卡显示红色提权警示；
- 批准 → 系统以 root 代执行（剥离冗余 sudo 壳；`su`/`sudo -u` 切换语义保留原样）；
- 拒绝/超时 → 受阻回流。

### 配置

```json
{
  "security": {
    "execUser": "exm",          // 用户名或数字 uid；空 = 不约束（默认）
    "execHome": "/home/exm"     // 空 = 自动推导
  }
}
```

### 部署要点

- **容器**：官方镜像内建固定 uid 的 `exm` 用户（默认不启用；启用需状态卷 chown 给该 uid）。
- **裸机**：先创建专用用户（`useradd -m exm`），网关以 root 运行时子进程自动降权。
- **已知限制**：
  - supplementary groups 不清除（仅设主 uid/gid）；bwrap 叠加场景此面已覆盖；
  - 网关非 root 时无法给其他 uid 降权（目标 uid 必须等于网关自身 uid，否则终端报错）；
  - Windows 忽略此配置（无 uid 语义）。

### 审批代执行收口

普通审批单（非 `[root]`）批准后的代执行与直通执行走**同一加固路径**（execUser 降权 + 沙箱净化）——审批放行的是命令内容，不是特权。

## 审批闸门（第③层，既有）

- `execApproval`：off（白名单外直接拒绝）/ risky（高危命令转审批）/ always（全部转审批）；
- 审批等待期内批准 → 系统代执行，输出回灌模型；拒绝/超时 → 受阻回流；
- `execAllowlist`：命令前缀白名单（命中跳过审批）。

### 三档放行粒度（approval-ergonomics）

批准审批单时可选放行面（控制台审批页 / 聊天内联卡三按钮；通道 `ok:` 裁决只走 once 档）：

| 档位 | 语义 | 生命周期 |
| --- | --- | --- |
| 本次批准（once，缺省） | 只放行本单，后续同类命令仍落审批 | 单次 |
| 本会话允许（session） | 同前缀命令在本会话内自动放行 | 会话结束/删除即失效，重启清零（内存态，不落盘） |
| 加入白名单（allowlist） | 前缀写入 `security.execAllowlist` | 持久（配置文件） |

- **前缀口径**：命令名 + 首子命令（剥提权前缀），与白名单匹配口径一致——
  批准 `cargo build --release` 即放行本会话所有 `cargo build`；
- **会话授权红线**：`[root]` 提权单、`[video]`/`[plan]`/`[meta]` 特殊单与
  破坏性命令（`is_destructive_command` 命中）**永不进入**会话授权与白名单——
  越权档位自动降级 once 执行（后端校验，UI 隐藏升档按钮只是预避）；
- **执行路径不变**：会话授权直通仍走同一加固路径（execUser 降权 / 沙箱净化），
  审批放行的是命令内容不是特权。

### 通道裁决（approval-ergonomics）

审批单产生时（`approval.required` 事件）推送摘要到来源 IM 通道（单号 + 命令 + 等待秒数），
回复 `ok:<单号>` 批准 / `no:<单号>` 拒绝。QQ 官方机器人平台支持时附「批准 / 拒绝」指令按钮
（点击等价于发送对应指令；单聊自动发送，群聊点击后发送），不支持时自动回落文本。
权限口径：审批单发起用户本人，或任一通道
`admins` 清单命中（判权跟人走，跨通道）；其他人裁决被拒且单据保持 pending。

## 沙箱执行（第④层，既有）

- `sandbox.mode`：off / workspace（环境净化）/ strict（净化 + 联网类命令转审批 + 更短超时）；
- `useBwrap`：检测到 bubblewrap 时做系统级隔离（工作区可写、根只读、默认断网）；
- `memoryMb`/`maxProcesses`：子进程资源上限。

strict 模式显式要求 `useBwrap=true` 而依赖不可用时，在 spawn 前拒绝，不再静默宿主回退；
非 strict 的既有本机兼容路径不变，不能据此声称系统级隔离已验证。

## 统一连接层的独立准入

`experiments.connectionFabric.enabled` 默认关闭，只控制新路径准入，不开启来源插件或设备实验，也不自动启动外部成员或自动化规则。
所有数值限制必须为正且不超过硬上限；配置文件、程序化Core启动/保存与HTTP更新均须拒绝无效限制，不能把零视为无限。
本地目录与能力声明不是执行许可，来源账户、项目、主体与能力版本仍分别校验；来源无法证明生命周期时保持未纳管。
连接层不能用“普通HTTP请求”绕过设备配对、Agent/会话grant和可信管理面逐次采集确认。

只有本地登记引用与不含秘密的凭据引用可以持久化；原凭据仍由来源服务管理。跨实例导入必须重新解析身份及授权，不能恢复grant、运行租约或一次性票据。
能力声明/检测/验证与授权必须分开展示；外部AI自述只读、可取消或有费用上限不能代替宿主验证。
当前接入基础不改变旧执行路径，设备、外部执行和peer底座未验收时不可显示为新路径已就绪，详细限制见 [协议与契约](协议与契约.md)。

## 可插拔执行后端的授权边界

后端选择取实际任务授权、项目边界、工具效果、身份和能力的交集。可信的
`BackendAuthorization` 不可从请求 JSON 反序列化；请求不能自报批准网络、换项目、提升 uid/gid、
挂载 Docker socket 或通过符号链接逃逸。明确指定的后端失败时不改用宿主；浏览器未验证时不接管宿主浏览器。

监督器只接受已选择的启动描述，控制调用有界，断连/清理未确认保留 unknown；同一动作 ID 不重放未知写操作。
远端客户端禁用重定向/代理，URL 不含凭据，只操作本实例提交的作业。端点和适配器必须由可信服务端配置，
远端服务仍须实际实施所声明的隔离和权限，不能把声明当作隔离证据。
目前没有自动配置的容器/远端环境，也没有以此开放新的模型执行旁路。详见 [执行后端契约与自检](execution-backends.md)。
