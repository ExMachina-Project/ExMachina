# 安全模型

> 本文档描述 EXMACHINA 的安全体系分层与各层职责。配置项均可在 WebUI 设置页对应分组调整。

## 总览：纵深防御五层

```
入站消毒 → 通道身份管控 → 工具闸门（白名单/审批） → 沙箱执行（净化/隔离/限资源） → 执行身份约束（uid 圈禁）
   ①             ②                  ③                        ④                            ⑤
```

| 层 | 机制 | 文档锚点 |
| --- | --- | --- |
| ① 入站消毒 | 伪装系统指令/指令劫持/工具结果伪装/隐藏字符 改写与剥离 | 设置页「安全」消毒开关组 |
| ② 通道身份管控 | 白名单用户 + 对方配置才可执行（群聊门控） | 设置页「通道」 |
| ③ 工具闸门 | 命令白名单（AllowRule）+ 审批闸门（off/risky/always） | docs/开发规范 §审批 |
| ④ 沙箱执行 | 环境净化（HOME/TMP 重定向）+ bwrap 系统级隔离 + ulimit/作业对象限资源 | 设置页「沙箱」 |
| ⑤ 执行身份约束 | 子进程降权到专用用户 + 工作目录圈禁 + root 提权审批 | 本文 §执行身份约束 |

## 执行身份约束（agent-exec-confinement）

### 机制

Linux 下可将 Agent 的终端子进程**降权到专用非 root 用户**执行（`security.execUser`，用户名或数字 uid），并**圈禁工作目录**（`security.execHome`，默认 `/home/<execUser>`）：

- **降权**：网关（容器内通常 root）spawn 子进程时直接设置 uid/gid（内核级，无 su 解析面）；bwrap 同开时改用 `bwrap --uid/--gid` 原生参数。
- **圈禁**：子进程 cwd 与 HOME 固定 execHome；filesystem 工具做第二道路径校验（canonicalize 后必须在 execHome 内）。
- **fs 双保险**：终端路径靠内核 uid（圈禁用户写不了界外文件），fs 工具路径靠显式校验拒绝。

### root 提权审批

约束开启时，提权命令（`sudo`/`su`/`doas`/`run0`/`runuser` 前缀，含链式命令中任一段）**无视白名单**直接进入人工审批：

- 审批单以 `[root] ` 前缀标识，WebUI 审批卡显示红色提权警示；
- 批准 → 系统以 root 代执行（剥离冗余 sudo 壳；`su`/`sudo -u` 切换语义保留原样）；
- 拒绝/超时 → 受阻回流。

### 配置

```json
{
  "security": {
    "execUser": "exm",          // 用户名或数字 uid；空 = 不约束（默认）
    "execHome": "/home/exm"     // 空 = 自动推导
  }
}
```

### 部署要点

- **容器**：官方镜像内建固定 uid 的 `exm` 用户（默认不启用；启用需状态卷 chown 给该 uid）。
- **裸机**：先创建专用用户（`useradd -m exm`），网关以 root 运行时子进程自动降权。
- **已知限制**：
  - supplementary groups 不清除（仅设主 uid/gid）；bwrap 叠加场景此面已覆盖；
  - 网关非 root 时无法给其他 uid 降权（目标 uid 必须等于网关自身 uid，否则终端报错）；
  - Windows 忽略此配置（无 uid 语义）。

### 审批代执行收口

普通审批单（非 `[root]`）批准后的代执行与直通执行走**同一加固路径**（execUser 降权 + 沙箱净化）——审批放行的是命令内容，不是特权。

## 审批闸门（第③层，既有）

- `execApproval`：off（白名单外直接拒绝）/ risky（高危命令转审批）/ always（全部转审批）；
- 审批等待期内批准 → 系统代执行，输出回灌模型；拒绝/超时 → 受阻回流；
- `execAllowlist`：命令前缀白名单（命中跳过审批）。

## 沙箱执行（第④层，既有）

- `sandbox.mode`：off / workspace（环境净化）/ strict（净化 + 联网类命令转审批 + 更短超时）；
- `useBwrap`：检测到 bubblewrap 时做系统级隔离（工作区可写、根只读、默认断网）；
- `memoryMb`/`maxProcesses`：子进程资源上限。
