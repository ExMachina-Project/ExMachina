# 安装指南

从零把 EXMACHINA 跑起来：环境准备 → 安装 → 配置模型提供商 → 验证。

## 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Rust | stable（[rustup](https://rustup.rs) 安装） | 编译核心 / CLI / 网关 |
| Node.js | ≥ 22 | 仅构建 WebUI 需要 |
| Docker | 可选 | 免环境直接部署 |

Windows / Linux / macOS 均可运行。

## 方式一：源码构建（推荐）

```bash
git clone https://github.com/KurohaneKaoruko/ExMachina.git
cd ExMachina

# 1) 构建 WebUI（网关会直接托管其产物）
npm install
npm run build:webui

# 2) 安装向导：环境检查 → 模型接入 → 落盘 → 自检
cargo run -p exm-cli --release --bin exmachina -- install

# 3) 启动网关（REST + WebSocket + WebUI 单进程）
cargo run -p exm-gateway --release
#    浏览器打开 http://127.0.0.1:4173
```

`exm` 与 `exmachina` 是同一实现的两个命令名，本文统一写 `exm`。
工作区默认为当前目录，全局参数 `--workspace <dir>` 可指定其他目录作为数据与编成的根。

## 方式二：Docker

```bash
docker compose up --build
# http://localhost:4173
```

- 镜像内已含 WebUI，无需 Node 环境；
- 运行状态持久化在 `exmachina-state` 卷，`./agents` 以挂载方式同步（编成可直接编辑）；
- 环境变量 `EXM_LANG=en` 可切换英文提示词变体，`EXM_LLM_API_KEY` 等可在启动时直接注入密钥。

## 配置模型提供商

EXMACHINA 通过「模型提供商」接入大模型，支持四种协议：

| 协议 | 适用 | 说明 |
|------|------|------|
| OpenAI 兼容 | OpenAI、DeepSeek、通义、Kimi、智谱、Ollama、vLLM… | 标准 `/chat/completions` |
| Anthropic 原生 | Claude 系列 | `/v1/messages`，系统提示分离 |
| Gemini 原生 | Google Gemini | `generateContent`，Key 走 `x-goog-api-key` 头 |
| Azure OpenAI | Azure 上的 OpenAI 部署 | 部署名入 URL，`api-key` 头鉴权 |

### 方式 A：WebUI 配置（推荐）

1. 打开 `http://127.0.0.1:4173`，进入侧栏「模型提供商」；
2. 「新增提供商」→ 点击厂商预设（自动填充端点与常用模型名），或手动填写；
3. 粘贴 API Key——支持多行粘贴组成 **Key 池**（同发起方粘性使用，仅限额时切换）；
4. 点「测试」确认连通，再「设为全局默认」。

### 方式 B：CLI 配置

```bash
exm model add deepseek --name "DeepSeek 主力" \
  --base-url https://api.deepseek.com/v1 \
  --api-key sk-... --orch-model deepseek-chat --unit-model deepseek-chat
exm model use deepseek        # 设为全局默认（未单独指定模型的智能体/组跟随它）
exm model test deepseek       # 连通测试（真实发一条 1-token 请求）
exm model list                # 查看全部提供商
```

### 方式 C：环境变量（优先级最高）

| 变量 | 说明 |
|------|------|
| `EXM_LLM_BASE_URL` / `EXM_LLM_API_KEY` | 全局端点与密钥 |
| `EXM_LLM_MODEL_ORCH` / `EXM_LLM_MODEL_UNIT` | 指挥体 / 子个体模型名 |
| `EXM_AUTH_KEY` | 启用后台访问密钥（REST/WS 全量鉴权 + WebUI 登录门） |
| `EXM_LANG` | `zh`（默认）/ `en`，en 时装载英文提示词变体 |
| `EXM_DATA_DIR` / `EXM_AGENTS_DIR` / `EXM_WEBUI_DIST` | 自定义数据 / 编成 / WebUI 目录 |

所有配置最终落在工作区的 `.exmachina/config.json`，CLI / 网关 / WebUI 设置页三端共用，
修改即热生效（无需重启进程）。

## 验证安装

```bash
exm doctor                                  # 体检：配置 / 编成 / 记忆 / 通道 / WebUI
exm agents                                  # 应列出 1 指挥体 + 39 子个体
exm chat "你好，自我介绍"                    # 与指挥体对话
curl http://127.0.0.1:4173/api/health       # 网关健康检查
```

## 常见问题

- **没有密钥能跑吗？** 能。系统自动降级为本地模拟通道（确定性输出），仅用于体验流程与开发联调，
  不代表真实模型能力；正式使用请配置提供商。
- **WebUI 打不开？** 确认已执行 `npm run build:webui`（网关托管 `webui/dist`），且 4173 端口空闲
  （`exm serve --port 5000` 可换端口）。
- **密钥安全吗？** 全部配置与数据都在本机 `.exmachina/` 目录（git 已忽略），不会进入仓库；
  WebUI 配置 `authKey` 后可避免局域网内未授权访问。
- **如何升级？** 拉取新代码后重复构建步骤即可；`.exmachina/config.json` 带版本号自动迁移。
