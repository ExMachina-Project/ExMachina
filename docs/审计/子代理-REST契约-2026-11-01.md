## P0（契约破坏）—— 零

错误包络主干统一（`{"error": "..."}` + 语义化状态码），提取器拒绝已由 `normalize_rejection`（lib.rs:78-114）归一为 400 JSON。

## P1 —— 2 项

### P1-1 「目标资源不存在」的状态码矩阵分裂（404 / 400 / 500 混用）

| 场景 | 返回 | 位置 |
|---|---|---|
| GET `/sessions/:id`、POST chat、PUT `/llm/active` | 404 ✅ | sessions.rs:468-481、89-94；llm_admin.rs:355-359 |
| undo / edit / fork（会话不存在） | 400 | sessions.rs:266-272、301-307、331-336 |
| PUT `/sessions/:id/title`（会话不存在） | **500** ⚠️ | sessions.rs:141-161 → store.rs:211-216 bail |
| PUT `/sessions/:id/pin`（会话不存在） | **500** ⚠️ | sessions.rs:170-183 → store.rs:102-110 bail |
| DELETE `/groups/:id`、DELETE `/agents/:identifier`、PUT `/groups/:id/*`、PUT `/groups/active` | 400 | groups_admin.rs:97-107；agents_admin.rs:180-190；platform/groups.rs:107-160；groups_admin.rs:74-86 |
| DELETE/PUT `/channels/:id`、`/cron/:id`、`/singles/:id` | 404 | channels.rs:674-688；cron_admin.rs:195-207；singles.rs:171-186 |

「会话不存在」单一资源出现 404/400/500 三态——客户端无法统一处理。
**建议口径**：路径参数指向的资源不存在 → 404；资源状态冲突 → 409/403；其余校验 → 400。最低成本：rename/pin 先 `get_session` 预检 404；groups/agents 族对「不存在」错误串判 404（与 undo/edit 的 busy→409 判定同款）。
**验证**：`curl -X PUT .../api/sessions/不存在/title -d '{"title":"x"}'`（现 500 应 404）；`curl -X DELETE .../api/groups/不存在`（现 400 应 404）。

### P1-2 DELETE 幂等语义只统一了 skills，D4 决议未推广

- 幂等 200：sessions、skills、memory、identity 解绑/配对码
- 不存在 404：channels、cron、singles、nexus links、llm profiles、plugins、adaptation 重置
- 不存在 400：groups、agents

同一 WebUI「删除后快速重复点删」场景交互层直接可观察分裂。
**建议**：按 D4 决议统一为 `{"ok":true}` 200（`remove`/`retain` 均返回 bool，handler 忽略即可，与 skills 修法同款）；或至少统一成一种并在 `docs/协议与契约.md` 写明。
**验证**：每类资源连打两次 DELETE 均应 200；回归 WebUI 删除流。

## 共性根因与修复建议

handler 普遍把 `anyhow::Error` 整体映射到单一状态码（500 或 400），未按错误语义分类——P1-1 的 500 与 400 族都源于此。建议引入轻量错误分类（thiserror 或错误串判定辅助函数；undo/edit 已有 `contains("处理中")` 先例）一次性收敛两族问题。
