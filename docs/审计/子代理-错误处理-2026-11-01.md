## P1 —— 3 项

### P1-1 LLM Provider 全局无超时，orchestrator 规划/收束流无 deadline，整轮对话可永久挂死
- 位置：`crates/exm-core/src/provider.rs:600`（`Client::new()` 无超时）、`:1347-1351`（chat）、`:1397`（stream）、`:1172`（embed）；未兜底路径：`orchestrator.rs:1985-2013`（`call_orch_stream` 收流无 deadline）、`:2023`（acc 空回落 chat）、`compaction.rs:141/215`、`orchestrator.rs:1264`（embedding 回填）
- 场景：LLM 端点 TCP 建连后不返回（代理半开、服务商僵死）：`reqwest::Client::new()` 默认无总超时 → `rx.recv()` 永久阻塞 → run 永不收束 → 会话 run_lock 永久持有，后续输入全排队。对比 transcribe/speak（`provider.rs:1268/1311`）都显式 120s，唯独 chat/stream/embed 没加。
- 建议：① Provider 构造改 `Client::builder().timeout(...)`（默认 300s，流式放宽）；② `call_orch_stream` 收流加 deadline（复用 `runtime.rs` 的 `timeout_at + handle.abort()` 模式）；③ compaction/embedding 同理。
- 验证：mock「建连后不发数据不关流」的 SSE 端点（mock provider 加 slow-stream 变体，参照 `plugin/bridge.rs` 的超时不悬挂测试），断言时限内返回可诊断错误。

### P1-2 MCP 调用链全无超时，且注册表互斥锁跨 await 持有——单个挂死的 MCP 服务器拖死全部 MCP 调用
- 位置：`crates/exm-core/src/mcp.rs:87`（HttpClient 无超时）、`:226-231`（StdioClient `read_line` 无超时）、`:697-702`（`McpRegistry::call` 持 `conns.lock().await` 期间 await）、`:647`（`refresh_all` 同样持锁逐服务器 await）
- 场景：任一 MCP 服务器不响应 → `read_line`/`send` 永久阻塞且持有 `conns` 锁 → 所有会话所有服务器的 MCP 调用永久排队，MCP 能力整体瘫痪且无自愈。
- 建议：① `McpServerConfig` 加 `callTimeoutSecs`（默认 60）；② `call`/`refresh_all` 在 `call_raw` 外包 `tokio::time::timeout`，超时判定 Failed 并移除；③ HttpClient 构造加超时。
- 验证：mock「读入请求后 sleep 不回」的 stdio MCP 服务器，断言超时返回错误、对另一台正常服务器的调用不被阻塞。

### P1-3 定时任务会话创建 `expect` panic 杀死整个 cron 调度循环
- 位置：`crates/exm-core/src/lib.rs:1784`（`.expect("定时任务会话创建失败")`）；调用链 `cron_scheduler.rs:7`（spawn 20s tick）→ `:12` `let _ = tick_jobs` → `:32` `run_cron_job`
- 场景：磁盘满/SQLite busy（busy_timeout 5s 耗尽）时 `create_session` 失败 → panic 沿 `tick_jobs` 传播杀掉调度任务 → 所有定时任务（含心跳巡检）静默全停，无事件无日志。
- 建议：改 `?`/`match`：失败记 `CronRun{status:"failed"}` + `cron.finished` 错误事件并 continue；调度循环体外套 `catch_unwind` 兜底。
- 验证：只读目录 Store 调 `run_cron_job` 断言返回 failed 记录而非 panic；断言 scheduler 单次 tick panic 后仍继续 tick。
