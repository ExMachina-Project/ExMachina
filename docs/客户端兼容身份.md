# 提供商客户端伪装

在「模型设置 → 编辑提供商 → 客户端伪装」选择连接时使用的应用标识，保存后热生效。桌面设置窗口与 WebUI 使用同一配置。

- 默认：不添加身份请求头，保留现有连接行为。
- Claude Code、Codex CLI、OpenCode、Cline：发送带公开版本的 User-Agent、应用和会话标识。
- 自定义：填写 User-Agent 和 JSON 格式的附加客户端标识头。
- User-Agent 留空使用预设值；附加请求头按名称覆盖预设值，名称不区分大小写。
- 「恢复默认身份」清除覆盖值并关闭伪装。
- 切换客户端预设时清除旧版本、User-Agent 和附加头覆盖，避免将 OpenClaw 的 `originator` 等标识带入 Codex；编辑同一预设时仍保留已保存覆盖值。

「客户端版本」留空时使用内置公开版本：Claude Code `2.1.326`、Codex `0.169.0`、OpenCode `2.3.0`、Cline `4.1.26`。填写版本会同步更新预设 User-Agent 和版本头；User-Agent 覆盖值仍优先。

「客户端原生请求」为预设默认方式。Codex 在 OpenAI 连接上使用 `/responses`，支持文本、图片、流式输出、思考摘要、工具调用与工具结果回传；Claude Code 使用 `/v1/messages`，并带 `x-app: cli`、Claude beta、SDK 标识以及本机生成的设备/会话元数据。Azure、Gemini 保留自己的鉴权和部署协议，预览会显示与客户端协议的差异。OpenCode 与 Cline 使用提供商配置的协议。

「仅覆盖请求头」保留原来的提供商协议，不添加请求体元数据，适用于只支持 Chat Completions 等旧协议的端点。原生模式切换协议时，鉴权头随协议同步变化：Messages 使用 `x-api-key`，Responses 使用 Bearer。辅助能力继续使用提供商配置的协议。

「预览生效请求」显示真实请求构造器产生的协议、路径和标识头，不联系上游；「测试当前草稿」使用已保存提供商的服务端密钥发送短测试，验证真实响应且不保存草稿。修改表单后旧预览自动隐藏。HTTP 402/429、流内失败、不完整 Responses 流和空响应均显示失败。服务商的客户端分类需核对其日志；连通成功本身不表示服务商已确认分类，模型自称也不是请求识别结果。

支持的附加头：`originator`、`version`、`x-app`、`x-title`、`x-openrouter-title`、`x-openrouter-categories`、`http-referer`、`editor-version`、`editor-plugin-version`、`anthropic-beta`、`anthropic-dangerous-direct-browser-access`、`x-claude-code-session-id`、`x-session-id`、`x-session-affinity`、`session_id`、`x-task-id`、`x-is-multiroot`、`x-platform`、`x-platform-version`、`x-core-version`、`x-client-*`、`x-opencode-*`、`x-stainless-*`。最多 32 项，值为不超过 2048 字节的单行 ASCII 文本。禁止覆盖鉴权和传输头。

身份作用于该提供商的推理（含流式）、嵌入、转写、语音合成、图像生成、连通测试与模型清单请求。图像返回的外链下载不附加提供商身份或密钥。智能体提示词与消息正文保持原样，不读取其他客户端的账号、订阅或本地凭证。

配置示例（`.exmachina/config.json` 中的提供商档案）：

```json
{
  "id": "my-provider",
  "name": "My Provider",
  "baseUrl": "https://example.com/v1",
  "apiFormat": "openai",
  "clientIdentity": {
    "preset": "codex",
    "version": "0.169.0",
    "requestMode": "native"
  }
}
```

REST 档案接口 `POST /api/llm/profiles` 接受同一 `clientIdentity` 对象。更新时省略表示沿用；传 `{ "preset": "default" }` 关闭。`POST /api/llm/models` 可携带尚未保存的身份配置进行模型清单探测，使用已保存的档案 ID 时保留服务端密钥。

`POST /api/llm/identity` 接受提供商 ID 或草稿 `baseUrl`、`apiFormat`、`model`、`clientIdentity`，返回生效请求预览。`POST /api/llm/test` 接受同样的连接与身份覆盖值，缺省沿用已保存值；两者都不改配置。预览不返回鉴权头、URL 凭证或消息正文。

自定义 OpenClaw 标识可使用 `userAgent: "openclaw/2026.11.4"`；OpenAI 路径的附加头为 `originator: "openclaw"`、`version: "2026.11.4"`。OpenRouter 使用 `HTTP-Referer: "https://openclaw.ai"`、`X-OpenRouter-Title: "OpenClaw"`、`X-OpenRouter-Categories: "personal-agent,cli-agent"`，应按实际端点选择，见 [OpenClaw 请求归属实现](https://github.com/openclaw/openclaw/blob/main/src/agents/provider-attribution.ts)。不要将应用标识当作上游授权保证：`403 client_not_allowed` 表示服务商拒绝当前客户端，程序会保留该错误码且不按配额错误轮换密钥；需核对服务商明确允许的客户端。

实现依据：Codex 的 [默认客户端](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/default_client.rs)、OpenCode V2 的[提供商说明](https://opencode.ai/v2/docs/providers)及 [请求构造](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/model-request.ts)、Cline 的[请求头构造](https://github.com/cline/cline/blob/main/sdk/packages/llms/src/providers/request-headers.ts)。Claude Code 同时对照公开版本与 [CLIProxyAPI 的识别规则](https://github.com/router-for-me/CLIProxyAPI/blob/main/internal/runtime/executor/helps/claude_client_detection.go)。

机器契约见 `GET /api/openapi.json` 的 `components.schemas.ClientIdentity`，可通过 `exm openapi --out api.json` 离线导出。请求和响应均引用同一身份 schema；默认身份的覆盖值必须为空。模型设置的更新、密钥沿用和探测语义见 [协议与契约](协议与契约.md#模型设置契约)。

回归验证：`cargo test -p exm-gateway --test client_identity --locked`；`UI_TEST_FILTER='client identity' npm run test:ui`。
