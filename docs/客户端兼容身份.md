# 提供商客户端伪装

在「模型设置 → 编辑提供商 → 客户端伪装」选择连接时使用的应用标识，保存后热生效。桌面设置窗口与 WebUI 使用同一配置。

- 默认：不添加身份请求头，保留现有连接行为。
- Claude Code、Codex CLI、OpenCode、Cline：添加常见的 User-Agent 和应用标识头。
- 自定义：填写 User-Agent 和 JSON 格式的附加客户端标识头。
- User-Agent 留空使用预设值；附加请求头按名称覆盖预设值，名称不区分大小写。
- 「恢复默认身份」清除覆盖值并关闭伪装。

预设只描述应用标识，不固定第三方应用版本。需要特定版本字符串时填写 User-Agent 覆盖值。服务商是否按这些标识识别客户端取决于其规则。

支持的附加头：`originator`、`x-app`、`x-title`、`http-referer`、`editor-version`、`editor-plugin-version`、`x-client-*`、`x-stainless-*`。最多 32 项，值为不超过 2048 字节的单行 ASCII 文本。

身份作用于该提供商的推理（含流式）、嵌入、转写、语音合成、图像生成、连通测试与模型清单请求。图像返回的外链下载不附加提供商身份或密钥。协议、鉴权、签名与消息内容继续由原有连接配置决定。

配置示例（`.exmachina/config.json` 中的提供商档案）：

```json
{
  "id": "my-provider",
  "name": "My Provider",
  "baseUrl": "https://example.com/v1",
  "apiFormat": "openai",
  "clientIdentity": {
    "preset": "claude-code",
    "userAgent": "my-agent/1.0",
    "headers": {
      "x-app": "cli",
      "x-client-name": "my-agent"
    }
  }
}
```

REST 档案接口 `POST /api/llm/profiles` 接受同一 `clientIdentity` 对象。更新时省略表示沿用；传 `{ "preset": "default" }` 关闭。`POST /api/llm/models` 可携带尚未保存的身份配置进行模型清单探测，使用已保存的档案 ID 时保留服务端密钥。

机器契约见 `GET /api/openapi.json` 的 `components.schemas.ClientIdentity`，可通过 `exm openapi --out api.json` 离线导出。请求和响应均引用同一身份 schema；默认身份的覆盖值必须为空。模型设置的更新、密钥沿用和探测语义见 [协议与契约](协议与契约.md#模型设置契约)。

回归验证：`cargo test -p exm-gateway --test client_identity --locked`；`UI_TEST_FILTER='client identity' npm run test:ui`。
