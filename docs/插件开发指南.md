# 插件开发指南

> 插件是 ExMachina 的统一能力包：一份清单（`plugin.json`）+ 可选实现（内联声明 / 子进程 / 宿主内置），四类能力（tools / channel / watch / resources）按需声明。
> 目录：仓库根 `plugins/<id>/`。装好即用（热装载），WebUI「插件」页启停卸载。

## 一、四层形态怎么选

| 层 | 形态 | 适合 | 代码量 |
|----|------|------|--------|
| T1 | 声明式（清单内联 HTTP 工具） | 包一个现成 REST API 给模型用 | 零 |
| T2 | 进程插件（stdio JSON-RPC） | 任意语言实现复杂逻辑、本地状态、长任务 | 任意语言 |
| T3 | 内置插件（Rust trait） | 深度集成宿主（随版本发布） | Rust |
| T0 | 数据/配置（CustomTool、entities/skills） | 用户侧零散扩展 | 零（非插件目录） |

T0 已被收编为虚拟插件（`custom-tools` / `builtin-resources`），管理页可见但不可禁用。

## 二、清单（plugin.json）

```jsonc
{
  "id": "my-plugin",              // 必填：= 目录名；字母开头，字母/数字/-/_
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明",
  "exmMin": "0.5.3",              // 可选：最低宿主版本

  // 能力一：工具组（T1 直接内联；T2 留空经协议发现）
  "tools": [
    {
      "name": "lookup",           // 模型看到 my-plugin__lookup
      "description": "查询……",
      "kind": "http",             // http | shell
      "method": "GET",            // GET（参数进 query）| POST（参数作 JSON body）
      "target": "https://api.example.com/v1/q?a={a}",  // {参数} 占位 → URL 编码
      "headers": { "Authorization": "Bearer ${credentials.token}" },  // 凭据变量（见 §2b）
      "parameters": { "type": "object", "properties": { "a": { "type": "string" } }, "required": ["a"] },
      "agents": [],                // 空 = 全部个体可见
      "responseMaxChars": 4000,    // 可选：响应裁剪上限（见 §2c；缺省 8000）
      "responseSelect": "data.items"  // 可选：JSON Pointer 摘取（见 §2c）
    }
  ],

  // 能力二：通道适配（声明平台 kind 与凭据面；WebUI 通道页按此渲染）
  "channel": {
    "kinds": ["demo"],
    "credentials": [
      { "key": "token", "label": "访问令牌", "sensitive": true }
    ]
  },

  // 能力三：watcher 轮询
  "watch": { "intervalMinutes": 10 },

  // 能力四：资源注入（技能 JSON / 提示词，相对插件目录）
  "resources": ["skills/my-skill.json"],

  // T2 进程形态声明（存在即进程插件）
  "process": {
    "command": ["./run.sh"],      // 相对插件目录；裸命令名走 PATH
    "env": { "LANG": "zh" },
    "handshakeSecs": 15,          // initialize 握手超时
    "callTimeoutSecs": 60,        // 单次工具调用超时（上限 300）
    "maxConcurrency": 4           // 并发上限（超出排队）
  }
}
```

装载校验：id 与目录一致、至少声明一类能力、exmMin 满足、内联工具名合法、process.command 无 `..`。拒绝的插件在管理页带原因展示。

## 2b. 凭据变量（`${credentials.<key>}`）

T1 声明式 HTTP 工具的 `target` 与 `headers` 里可引用插件凭据，运行时替换为 WebUI/CLI 配置的真值：

- **配置入口**：WebUI 插件详情「凭据」表单（按清单 `channel.credentials` 键位渲染，敏感值掩码回显）；或 REST `PUT /api/plugins/:id/credentials`。
- **变量语法**：`${credentials.token}`——键名字母数字/`_`/`-`；解析先于 `{参数}` 插值。
- **缺键拒绝**：引用了未配置的键 → 调用直接失败并返回缺失键清单（不发出残缺请求）。
- **掩码口径**：回显一律 `********`；提交时掩码串不覆盖真值，清空 = 删除该键。
- 进程插件（T2）的凭据不走变量——握手成功后宿主主动 `config/set` 下发整组键值（见 §3 治理口径）。

## 2c. 响应裁剪（responseSelect / responseMaxChars）

API 响应先摘取再截断，两级治理防大响应污染上下文：

1. **摘取**（`responseSelect`，可选）：JSON Pointer 路径——`"data.items"` 取数组/对象子树；命中后仅该子树进入第 2 步；未命中返回原响应（API 结构变化不至于工具报废）。
2. **截断**（`responseMaxChars`，可选，缺省 8000）：超长文本截断并以「…（截断）」结尾标注。

```jsonc
// 例：只取 items 数组、上限 4000 字
{ "name": "search", "kind": "http", "method": "GET",
  "target": "https://api.example.com/search?q={q}",
  "responseSelect": "data.items", "responseMaxChars": 4000 }
```

## 2d. 安装与分发

三种来源，CLI 与 WebUI 插件目录共用同一安装流水线：

| 来源 | CLI | 说明 |
|------|-----|------|
| tar.gz 包 | `exm plugin install ./my.tgz` | 包内任意层级定位 plugin.json；根目录归一为 manifest.id；单文件 32MB/总量 128MB 上限；`..`/绝对路径条目拒绝；`./` 开头或含 `/` 的主命令保留执行位 |
| git 仓库 | `exm plugin install https://…/repo.git` | 浅克隆；`subdir` 支持子目录插件；`.git` 不随迁 |
| 索引 id | `exm plugin install my-plugin` | 查插件索引（`config plugins.indexUrl` 可自定义；官方源随仓库 `plugins/index.json` 发布） |

- 安装记录（来源 URL/类型）写入 config `plugins.installations`——`exm plugin update` / WebUI「检查更新」按此拉新版（已是最新不落盘）。
- 更新保留 `plugins/<id>/data/`（插件自管数据不丢）与启停状态。
- 索引条目可声明 `exmMin`：宿主版本不足直接拒绝安装（省得装完起不来）。
- 卸载删除插件目录与安装/凭据记录。

## 2e. 握手协商（serverInfo.exmMin）

T2 插件 `initialize` 响应可带最低宿主版本要求：

```jsonc
{ "jsonrpc": "2.0", "id": 1,
  "result": { "serverInfo": { "name": "demo", "version": "0.1.0", "exmMin": "0.5.3" } } }
```

宿主版本低于 `exmMin` → 握手失败（错误含两侧版本与升级指引），插件置错误状态不拉起；协商通过后宿主立即 `tools/list` 快照（插件详情页「进程工具快照」可见）。

## 三、T2 进程协议（stdio JSON-RPC）

子进程从 stdin 按行读请求、向 stdout 按行写响应（stderr 透传宿主日志）。协议 = MCP 工具子集 + 扩展方法：

### 生命周期

```
宿主 → initialize（超时 handshakeSecs 判失败）
宿主 → tools/list
（运行期）
宿主 → tools/call …
宿主 → config/set（凭据下发；仅内存，不得落盘）
宿主 → watcher.tick（通知，无 id）
宿主 → shutdown（宽限后 SIGKILL 兜底）
```

### 最小实现（Python 参考）

```python
import sys, json
CREDS = {}
for line in sys.stdin:
    req = json.loads(line)
    m, rid = req.get("method"), req.get("id")
    if m == "initialize":
        resp = {"jsonrpc": "2.0", "id": rid, "result": {"serverInfo": {"name": "demo"}}}
    elif m == "tools/list":
        resp = {"jsonrpc": "2.0", "id": rid, "result": {"tools": [
            {"name": "hello", "description": "问候",
             "inputSchema": {"type": "object", "properties": {"who": {"type": "string"}}}}
        ]}}
    elif m == "tools/call":
        who = (req["params"].get("arguments") or {}).get("who", "world")
        resp = {"jsonrpc": "2.0", "id": rid, "result": {"content": [{"type": "text", "text": f"hello {who}"}]}}
    elif m == "config/set":
        CREDS.update(req["params"]["config"])  # 仅内存
        resp = {"jsonrpc": "2.0", "id": rid, "result": {}}
    elif m == "shutdown":
        sys.exit(0)
    else:
        continue  # 未知通知跳过
    print(json.dumps(resp), flush=True)
```

模型侧工具名为 `demo__hello`（`<插件id>__<工具名>`）。

### 治理口径

- **崩溃重启**：意外退出按指数退避重启（1s/2s/4s…上限 60s）；连续 5 次失败置错误状态停止重试，管理页展示、人工干预后再启。
- **超时**：握手与单次调用都有超时，超时返回明确工具错误（调用方不悬挂）。
- **并发**：超过 `maxConcurrency` 的调用排队（不拒绝）。
- **文件系统边界**：插件一切文件读写限于 `plugins/<id>/data/`；`..` 与绝对路径被拒绝。需要引用宿主文件走清单 resources（装载期声明）。
- **凭据**：经 config/set 下发仅存进程内存；管理端点/日志/诊断对 sensitive 字段全掩码。
- **回收**：宿主关闭或插件禁用时发 shutdown，宽限后强制回收，无孤儿进程。

## 四、T3 内置插件（Rust）

实现 `exm_core::plugin::PluginProvider`（按能力实现 ToolProvider / ChannelProvider / WatchProvider / ResourceProvider），在 `crates/exm-gateway/src/plugins/mod.rs` 的 `spawn_all` 注册。参考实现：`VideoPlugin`（video 插件 = manifest 声明 + 既有 supervisor 生命周期）。

## 五、验收清单（开发自测）

1. `plugins/<id>/plugin.json` 放置后 WebUI 插件页出现卡片（或 `exm doctor` 的插件段）
2. 启用后工具名 `my-plugin__xxx` 出现在会话工具面（对话页可调用）
3. T2：杀掉子进程 → 自动重启；管理页禁用 → 进程回收
4. `exm doctor`：插件段无拒绝项；启停覆盖无悬空键
