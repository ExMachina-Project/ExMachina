# 架构与设计

面向开发者：EXMACHINA 的设计理念、分层架构与核心机制。

## 设计理念

1. **绝对理性**——摒弃拟人化。全员以结构化陈述说话（【肯定】【报告】【警告】等句式前缀），
   判断附证据等级（A–D），零情绪、不确定时显式说明置信度。语言纪律与协作规则定稿于协议层
   （`entities/groups/exmachina/protocol/`）；指挥体与子个体的提示词遵循同一口径，协议全文按
   frontmatter 触发词在规划与派发两处按需注入。
2. **编制即数据**——个体、链路、技能、人设全部是 `agents/` 下的数据文件而非代码；
   增删个体不改动核心，测试断言"契约完整性"而非"编成数量"。
3. **契约先行**——指挥体的规划（OrchestratorPlan）与子个体的回流（SyncReport）都有严格的
   JSON 结构契约，运行时强制校验；不合规自动重写，仍不合规升级人工/裁决。
4. **组即隔离**——会话、记忆、工作区、编成按组隔离；组是对外服务的完整单元。
5. **单进程交付**——一个网关进程同时提供 REST API、WebSocket 事件流与 WebUI 静态托管，
   部署面最小；Bus / Registry / Scheduler 均为可替换接口，未来换分布式实现上层零改动。

## 分层架构

```
渠道（WebUI / 桌面端 / CLI / QQ 官方机器人 / NapCat / Telegram / Discord / Slack / Matrix / Webhook…）
        │ REST / WebSocket（docs/协议与契约.md）
┌───────▼────────────────────────────────────────┐
│ exm-gateway   axum 接入层：路由 / 鉴权 / 静态托管  │
│   平台适配器监督循环（telegram/qqbot/napcat/      │
│                     discord/slack/matrix）       │
│               cron 调度器                        │
├────────────────────────────────────────────────┤
│ exm-core                                       │
│  Orchestrator  收拢→分解→派发→裁决→收束           │
│  Scheduler     任务 DAG 拓扑调度 + 并发池          │
│  AgentRuntime  子个体 LLM 循环 + 工具调用 + 回流    │
│  LocalRegistry 组/个体/提示词/技能（数据热装载）     │
│  MemoryStore   深层记忆：倒排检索/衰减/分组        │
│  Store         会话/消息/图/证据/事件持久化        │
│  ToolGateway   工具网关（沙箱/白名单/审批/审计）    │
│  LlmProvider   多协议模型接入 + ModelPool 档案池   │
└───────┬────────────────────────────────────────┘
        │ OpenAI 兼容 / Anthropic / Gemini / Azure
     各厂商模型端点
```

三个 crate：`exm-core`（领域核心）、`exm-gateway`（HTTP/WS 接入 + 平台调度）、
`exm-cli`（`exm` / `exmachina` 双命令，同一实现）。

## 核心机制

### 任务循环（指挥体）

1. **收拢**：用户输入写入会话，任务账记录目标；
2. **规划**：指挥体按规划契约输出 OrchestratorPlan（routeLevel L0–L3、边界、验收、节点清单），
   L0 直接作答，否则生成任务 DAG；
3. **派发**：调度器按依赖拓扑 + 并发池执行节点，DispatchOrder 携带目标、上游回流摘要、
   个体记忆、命中的技能指令与命中的协议全文；
4. **回流**：子个体以 SyncReport 契约交卷（结论/证据/阻塞/置信度），校验失败自动重写（≤2 次）；
5. **裁决**：回流冲突或受阻时动态追加裁决节点，按能力声明选路（含「裁决」「决策」优先，回退主智能体）；
6. **收束**：全节点终态后汇裁收束，更新三账、写入记忆、广播 run.finished。

### 三账（会话账本）

任务账（目标/验收/约束/禁令）、证据账（A 直接验证 – D 推断）、风险账（未决断言/影响/回退路径/阻断）。
三账随任务循环原子更新，WebUI「三账」面板可视化。

### 记忆系统

- **分层**：群体记忆（共享）与个体记忆（私有）；派发注入"个体私有 + 群体共享"，指挥体只看群体。
- **检索（混合）**：词项倒排（CJK 二元 + ASCII 词）× 重要性 × 时间衰减 × 类型加成 + **语义向量余弦加成**；
  全局档案声明 `embedModel` 时启用——写入后台回填向量、检索时计算查询向量；词项无命中时语义兜底扫描。
  未声明嵌入模型则纯词项（零外部依赖）。
- **写入**：任务结束自动写入会话摘要、边界决策、A/B 级证据（群体）与受阻教训（归属个体）；
  内容去重、可固定（pin）、按半衰期衰减。
- **进化**：个体受阻教训累计达阈值后自动提炼"行为改进要点"（版本化、可重置），注入后续派发；
  个体可靠性统计（执行/完成/受阻/置信度）反哺指挥体选路。

### 组隔离与交互目标

- 会话带 `groupId`（或 `single:<id>`），列表按当前交互目标过滤，删除级联；
- 组工作区：该组个体工具操作的根目录（相对路径挂在工作区内），组间文件互不可见；
- 主智能体获 `agent_manage` 白名单工具，可在任务中扩编组内个体（仅自定义组）；
- 切换交互目标是**会话行为**（对话页左栏），管理页不承担切换。

### 模型解析与多 Key

- 解析顺序：**个体 modelHint → 所属组 model → 全局生效档案**；提示格式 `档案ID` 或 `档案ID/模型名`；
- ModelPool：每个模型档案持有独立 Provider 实例（四种协议），档案编辑经 apply_config 热重建；
- Key 池：按发起方标识粘性选键（保留端点侧 KV 缓存），仅 429/402/配额类失败时前进下一把并粘住。
- 失败回退链：档案可声明 `fallback` 指向下一档案；请求失败且**未发出任何内容前**自动切换下一候选，
  失败档案进入 45 秒冷却（链上被跳过，保底留一）；已发出 token 的流不重试，避免重复输出；
  链尾以全局生效档案兜底，成环自动截断。

### MCP（第三方工具生态）

- 配置：`.exmachina/config.json` 的 `mcpServers[]` 段声明服务器（stdio 本地子进程 / http Streamable HTTP），
  `allowedAgents` 控制个体可见性（空 = 全体）；
- 工具以全名 `mcp:server:tool` 挂载：懒连接（首次调用 initialize 握手），工具清单缓存快照注入规划，
  原生 function calling 直达，审计与内置工具一致落库；
- 管理端点：`GET /api/mcp`（服务器与工具清单）、`POST /api/mcp/refresh`（刷新清单）；
- 连接池异步锁、快照同步锁——规划热路径永不等待网络。

### 分布式执行节点（旧设备集群）

- **形态**：淘汰笔记本 / 迷你主机 / 旧手机跑 `exm worker --url ws://hub:4173/worker`，
  以本地模型（如 Ollama）承接网关的子个体派发——中心调度全域 DAG，算力在边缘。
- **协议**：WebSocket JSON 帧（hello / dispatch / tokens / report / error）；
  鉴权复用网关 authKey（`?key=`）。
- **路由**：工作者在线即自动承接（可声明只跑特定个体）；失败/超时/离线**自动回落本地执行**，
  token 流即时回推事件总线（WebUI 实时可见远程个体的流式输出）；`remote.fallback` 事件可观测。
- **工作者侧**：完整 Core（自己的模型档案/工具网关/记忆脱网），派发在 `execute_unit` 执行，
  同一份发行包解压即成节点。

### 断点续跑（长任务可靠性）

网关启动时扫描全部会话：图仍处 Executing 且存在非终态节点（进程被杀/断电）→ 自动续跑——
已完成节点的回流从持久层（sync_reports_by_node）回填，非终态节点重置 Ready 重新派发，
跑完调度器后直接收束（run.finished 带 `resumed: true`）。重启即恢复，无悬挂会话。

### 工具面与多模态

- **工具面**（对标主流 agent 的「手」）：`read`（行号 + offset/limit 分页）、`edit`（精确替换 +
  唯一命中校验）、`grep` / `glob`（尊重 .gitignore）、`filesystem`、`terminal`（白名单 + 审批 +
  后台长任务）、`web_search`（真实后端，**未配置即不下发**）、`web_fetch`、`schedule`（自主排程）、
  `agent_manage`、`spawn`（子智能体派生）、`sessions`（跨会话互通）、`skill_manage`（技能自管理）。
  同轮**只读工具并发**、写工具串行；超限结果落盘 `.exmachina/tool-output/` 并回填路径。
- **跨会话互通**：`sessions` 让智能体在同组作用域内列示/检索会话、读取历史、把任务投递给另一条会话
  （默认异步，`wait=true` 等待完成）。组隔离在工具层强制：目标必须同 `groupId` 且同 `memoryPartition`，
  跨组/跨分区连存在性都不暴露——避免「多会话」变成「越权读全库」。
- **技能自改进闭环**：主智能体在任务后可用 `skill_manage` 沉淀/修正技能；派发命中触发词即注入指令。
  每次注入后按节点终态写 `.usage.jsonl` 侧车（使用次数/成功次数/最近使用），`GET /api/skills` 聚合回读。
  统计与内容分离：SKILL.md 保持可分享的纯格式，导入/导出与 CLI 往返零污染。
- **训练轨迹导出**：`GET /api/sessions/:id/trajectory`（或 `exm trajectory`）把会话按轮次切成稳定
  `exm.trajectory/v1` 结构，默认剥离思维链、工具参数/结果可控截断，支持 JSON / JSONL——可直接用于
  批处理、评测与微调样本生成。
- **中断改向**：`POST /api/sessions/:id/steer` 在轮次进行中置位取消令牌，把新输入排入会话串行队列；
  比「等本轮跑完再 followup」更接近人类打断——当前工具循环在检查点终止，新目标立即接续。
- **写前检查点**：写 / 编辑前自动快照到 `.exmachina/checkpoints/<日期>/`，`exm checkpoint restore`
  或 `POST /api/checkpoints/restore` 一键回滚 —— 让自主执行可逆。
- **沙箱执行**：`sandbox.mode` 三档（off / workspace / strict）。workspace = 子进程环境净化
  （白名单透传 + HOME/TMP 重定向）；strict = 加联网闸门与前台超时收紧，并在 Linux/macOS 检测到
  `bwrap` 时用 bubblewrap 做文件系统隔离。**Windows 侧另有作业对象（Job Object）加固**：
  `sandbox.memoryMb` 设 `ProcessMemoryLimit`、`sandbox.maxProcesses` 设 `ActiveProcessLimit`，
  并一律带 `KILL_ON_JOB_CLOSE` —— 句柄一关，命令拉起的整棵进程树随之终止（后台任务被终止同此路径），
  前台命令结束后也不留游离子进程。**目标不是拦死 AI，而是把爆炸半径圈住，让它敢自己动手。**
- **浏览器自动化**：`browser` 工具（headless Chrome + CDP over WebSocket，懒启动常驻）：
  open / text / eval / screenshot / close；正文取页面渲染后的 `innerText`，截图落 `.exmachina/screenshots/`。
  未探测到浏览器可执行文件时不下发该工具。
- **生命周期钩子**：`hooks.preTool`（非零退出即拦截）/ `postTool` / `onRunEnd`，环境变量注入上下文。
- **web_fetch 工具**：抓取网页并提取正文（零依赖 HTML 剥离：去 script/style/标签、压空白；
  20s 超时 + 2MB 上限 + 8000 字默认截断），按个体工具白名单放行，审计落库。
- **图片多模态输入**：对话接口可带 `images`（data URL）；渠道暂存 → 指挥体下一轮规划取走注入；
  请求映射按协议生成多模态内容（openai `image_url` / anthropic base64 `image` 块 / gemini `inline_data`）。
  **视觉转述降级**：模型清单里明确 `vision=false` 的模型不直接接图——配置了「视觉转述」能力模型时，
  逐图转成文字描述注入规划；未配置则忽略图片并在任务输入中说明。清单未标记（能力未知）保持直通。
  **能力槽位两级解析**：语音合成 / 语音识别 / 视觉转述 / 嵌入均按 **组覆盖 → 全局槽位 → 出厂默认**
  解析（每组可用不同模型栈；组级覆盖在「智能体组 → 组设置」配置，全局兜底在「模型设置」页）。

### 语音输入

对话页麦克风按钮：MediaRecorder（webm）→ `POST /api/voice/transcribe`（multipart audio）→
能力槽位「语音识别」指定的档案/模型（缺省全局生效档案 whisper-1）→ 文本入输入框。API 制转写，零本地依赖；
非 openai/azure 协议档案明确报「不支持」。

**朗读（TTS）**：消息气泡 🔊 按钮 → `POST /api/voice/speak` → 能力槽位「语音合成」指定的档案/模型
（缺省 tts-1，alloy 声线，mp3）→ 浏览器播放。会话侧栏实时显示 token 估算用量与预算（`GET /api/sessions/:id/tokens`）。

### 记忆双模式

- **深层记忆（默认开）**：数据库条目 + 词项/语义混合检索 + 自动写入 + 向量回填 + 经验优化。
- **文件记忆（`memory.enabled=false`）**：文件记忆模式——`memory.md` 是唯一记忆载体，
  每轮规划全文注入（≤8000 字符）；记忆面板变为 Markdown 直接编辑器（`GET/PUT /api/memory/md`）；
  不写数据库、不做检索——极简可靠，用户手工维护。
- **memory.md 上限与自主压缩**：`memoryMdMaxChars`（默认 5000，可配置）；保存后超限即触发
  LLM 自主压缩简略（【记忆压缩】契约），**被精简的原文自动归档**——深层开 = 存数据库
  （digest 条目，可检索），关 = 追加工作区 `memory_archive.md`；nothing is lost。

### 执行加固与预算

- **终端超时强杀**：命令经 tokio 异步执行（不阻塞运行时线程），个体派发 120s / 审批代执行 300s 上限，
  超时 Windows `taskkill /T /F` 进程树强杀（cmd 子进程不漏网）——挂死命令不再卡死节点。
- **会话 token 预算**：`maxSessionTokens`（估算口径 = 消息字符 / 4；0 = 不限）；超限会话拒绝新轮次，
  明确提示新建会话或上调预算——失控循环有硬顶。

### 通道安全与语音

- **会话白名单**：通道可声明 `allowedChats`（各平台会话键：Telegram chat id / QQ openid / OneBot 群号或 QQ 号 /
  Discord 频道 id / Slack 频道 id / Matrix 房间 id；空 = 不限）——非清单内的消息直接忽略并记录，防陌生人滥用机器人。
- **平台适配器**：telegram 长轮询、qqbot 开放平台 WS（appId+appSecret → AccessToken 缓存 →
  identify/heartbeat/resume，被动回复带 msg_id+msg_seq）、napcat 正向 WS（OneBot 11 收发）、
  discord Gateway WS（intents 含 MESSAGE_CONTENT 特权位；READY/RESUMED 与 op9 回退重新 Identify）、
  slack Socket Mode（appToken 开 socket、3 秒内 ack envelope、bot token 回帖，免公网回调）、
  matrix `/sync` 长轮询（首轮只取 next_batch 跳过历史；回复 PUT txnId 幂等）。
  六者同构：5 秒监督对账、按账号拉起/回收任务、账号绑定组内执行、收束陈述回帖；
  共用逻辑收敛在 `platform::ChannelRun` + `spawn_reply`（组绑定 / 会话键复用 / 事件订阅 / 组还原），
  适配器自身只负责「协议翻译 + 发送闭包」。
- **Telegram 语音输入**：voice 消息 → getFile 下载 ogg → 「语音识别」槽位转写（缺省 whisper-1）→ 按文本走正常流程；
  转写失败降级忽略（不影响文本消息）。

### 上下文工程三件套（压缩 / 预算 / 步数）

长会话与长任务的上下文治理，组调度与单智能体循环同口径（`compaction.rs` + `budget.rs` 共享层）：

- **滚动压缩**：历史超过阈值时旧段落折叠为滚动摘要（保留近段完整），摘要溢出即重置重建；
- **上下文预算**：`contextBudgetRatio`（默认 0.8）× 模型窗口（档案 `contextWindow`，0=未知不判定）
  为软上限；超限先截最旧消息、再截单条思维链，全程 `context.trim` 事件留痕（软着陆不崩）；
- **步数三级覆盖**：个体 `maxSteps` > ToolScope 档位（Chat 档取全局半数）> 全局 `security.chatMaxSteps`（默认 24）。

### 计划模式（plan-mode）

会话级模式位 `plan | execute`（默认 execute，进程级注册表）。plan 模式下工具网关拦截写类
调用（edit/patch/filesystem.write/terminal run/computer 输入/git 写/spawn），转为 PlanItem
累积计划清单；读取类放行。首条出现时在 approvals 通道落 `[plan]` 审批单并广播 `plan.pending`。
批准 = 清单按序回放执行 + 切 execute（`plan.approved`/`plan.applied` 事件）；拒绝 = 保留清单
（`plan.rejected`）。跨端呈现：CLI TUI 审批页、WebUI 审批单、IM 通道文本摘要 + `plan:yes/plan:no`
快捷回复（六平台经 ChannelRun 公共层一次继承）。

### 子智能体派生（subagent-spawn）

主智能体经 `spawn` 工具把封闭子任务交给独立上下文的子智能体：临时 AgentDefinition +
空历史复用 `chat_execute`（同工具网关、同审批闸门），任务书为系统提示。单层限制（子级
白名单强制剔除 spawn/agent_manage）；实例级信号量并发上限（默认 4）+ 独立超时（默认 300s，
上限 1800s）；`spawn.started/finished` 事件进主会话事件流（可观测）。

### 代码工作台（webui-code-workbench）

WebUI「代码」视图：`GET /api/workbench/tree`（.gitignore 口径过滤、深度/数量限制、
工作区边界校验）+ `GET /api/workbench/file`（read 工具同口径分页）。会话流的工具卡：
edit/patch 内联着色 diff；写动作卡片带「回滚」按钮（调既有 undo 端点联动检查点恢复）；
terminal 卡分区呈现命令/输出/退出码（长输出折叠、后台任务显 taskId）。CLI 侧对应形态为
全屏 TUI（`exm` 裸命令，ratatui 三段版式 + 审批页）。

### 安全

终端命令审批闸门（off / risky 高危拦截 / always 全拦截）+ 命令前缀白名单 + 审批代执行 + 工具审计落库；
配置 `authKey` 后 REST/WS 全量鉴权，WebUI 出登录门。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 核心语言 = Rust，WebUI = TS + React | 调度/并发/长驻进程是性能与安全关键路径；界面层生态优先，以 REST/WS 契约解耦 |
| WebUI 保持 React（评估过 WASM 方案） | 运行时本就只有 Rust 进程 + 静态文件；Yew/Leptos 重写 14 个面板成本高、中文组件生态弱，收益不成比例。React 19.3 + antd 6 为当前最新稳定栈 |
| 网络 = 系统原生 TLS（native-tls） | Windows/macOS 直接用系统 TLS 库（schannel/CFNetwork），零 C 工具链依赖；修复了此前 TLS feature 缺失导致 HTTPS 端点不可用的问题 |
| 发布档 LTO + codegen-units=1 + strip | 更小的单文件二进制与更高吞吐，面向低性能设备部署 |
| 预编译产物分发（GitHub Actions） | 淘汰设备免编译、免 Node：下载 release 包解压即用 |
| 网关 = axum（与核心同进程同运行时） | 零跨语言开销；tokio 生态下 WS 扇出天然契合事件流 |
| 存储 = 文档型 fsdb（SQLite 接口在后） | 构建环境无 C 编译器也可运行；repository 接口之后可换回 SQLite/redb |
| 编成 = 数据 | `agents/` 即事实源，热装载；一次性生成器脚本移至开发目录 |
| 双命令 `exm`/`exmachina` | 同一 crate 产出两个 bin，编译期强一致 |
| 未配置模型即报错，绝不静默降级 | 没有端点/密钥就没有回答，并由 CLI 与 WebUI 明确引导到「模型设置」；不伪造模型能力 |
| 测试替身（MockLlmProvider） | 仅单测与端到端验收使用（`EXM_LLM_MOCK=1`）；产品运行时不在任何路径上回退到它 |

## 测试策略

```bash
cargo test --workspace                  # 单测 + 冒烟（编成契约/建组切换/全链路/默认模型/审批）
cargo run -p exm-gateway --example e2e  # 网关端到端验收（REST 全端点/事件流/三账/记忆/组）
```

测试使用**确定性测试替身**（`EXM_LLM_MOCK=1`，产出合法契约 JSON），因此不依赖真实模型与网络；
真实端点联调由 `exm model test`（安装向导与提供商页均可触发）承担。

## Core 领域模块分布

codebase-refactor 后，`exm-core` 巨型文件按域拆分为「组合根 + 领域 impl 分文件」形态。
同一 struct 的 `impl` 块分散在同目录多文件（Rust 惯例），方法签名与行为零变更。
