# 生产环境验证手册（blocked-on-env 项）

本手册覆盖三个因环境受限未实跑的验证项，环境就绪后按步骤执行并录制证据。每项附 curl 断言清单。

## A. 生产镜像迁移与一键更新（update-pipeline 3.4/5.2）

### 前置条件

- 生产部署目录（如 `/root/agents/ExM-Bot/ExMachina`）当前运行旧结构（仓库源码直挂或手工 build 镜像）
- `deploy/docker-compose.yml` 模板、`entities/`、`skills/`、`.env` 就绪
- ghcr.io 镜像已发布（release 流水线 docker job），或本地 `docker tag` 替代

### 迁移步骤

1. 停旧栈：`cd <旧部署目录> && docker compose down`（保留数据卷）
2. 新建部署目录结构：
   ```
   mkdir -p /root/agents/ExMachina-prod && cd /root/agents/ExMachina-prod
   cp <仓库>/deploy/docker-compose.yml .
   cp -r <旧目录>/entities .       # 编成数据（智能体/组/技能）
   cp -r <旧目录>/skills .         # 若与 entities/skills 分离
   cp <旧目录>/.env .
   ```
3. 数据卷迁移（旧卷 → 新 named volume）：
   ```
   docker run --rm -v <旧卷或旧绑定>:/from -v exmachina-state:/to alpine cp -a /from/. /to/
   ```
4. 启动：`docker compose up -d`（需要一键更新时取消 docker.sock 注释段）

### 验收断言（curl 清单）

```bash
BASE=http://localhost:4173
# 1. 单一容器、归属新 compose 项目
docker ps --filter name=exmachina --format '{{.Names}} {{.Label "com.docker.compose.project"}}'
# 期望：exmachina exmachina（非 exmachina-dev）
# 2. 健康
curl -sf $BASE/api/health && echo OK          # 期望 200
# 3. 版本可追溯
curl -s $BASE/api/version | python3 -m json.tool
# 期望：gitHash 为发版 commit（非 "dev"）
# 4. 更新检查为镜像模式且能判更新
curl -s $BASE/api/version/check | python3 -m json.tool
# 期望：deployMode=="image"，updateAvailable 为 true/false（非 null——除非上游不可达）
# 5. 一键更新全流程
curl -s -X POST $BASE/api/version/apply | python3 -m json.tool
# 期望：202 受理（运行中再发 → 409）
# 轮询 phase 流转：
watch -n5 "curl -s $BASE/api/version/apply/status | python3 -m json.tool"
# 期望：idle → pulling → recreating → done；exitCode==0；容器重启后版本变化
# 6. 无死锁：更新完成后再查 status
curl -s $BASE/api/version/apply/status
# 期望：running==false（不恒 running）
```

### 回退

- `docker compose down && cd <旧目录> && docker compose up -d`（旧结构未删即回退）

## B. execUser 降权与提权审批（agent-exec-confinement 4.2）

### 前置条件

- Linux root 容器（生产 exmachina 容器即满足）
- `security.execUser: "exm"` 已配置（容器内 uid 911 用户已内建于镜像）

### 验收断言

```bash
# 1. 容器内 exm 用户存在
docker exec exmachina id exm
# 期望：uid=911(exm) gid=911(exm)

# 2. execUser 启用后 Agent 终端子进程降权（经 WebUI 让 Agent 跑 id -u）
#    Agent 工具循环执行 `id -u` → 回显 911（非 0）

# 3. fs 越界拒绝（Agent 尝试写 /etc/ 下文件 → 拒绝并提示 execHome 边界）

# 4. 提权命令全流程：
#    a. Agent 跑 `sudo whoami` → 落 [root] 前缀审批单（无视白名单直达审批）
curl -s $BASE/api/approvals | python3 -m json.tool
# 期望：command 以 "[root] sudo whoami" 开头
#    b. 批准
curl -s -X POST $BASE/api/approvals/<id>/approve
# 期望：status=executed，result 含 "root"（root 身份代执行）
#    c. 事件流可查 elevated 审批记录
```

### 已有自动化覆盖（无需环境）

- `cargo test -p exm-core --lib root_approval`（提权落单/su 语义/拒绝回流/代执行约束/cwd 回归，5 项）
- `cargo test -p exm-core --lib exec_identity`（身份解析 8 项）
- `cargo test -p exm-core --lib allowlist`（提权壳剥离/链式识别 18 项）

## C. 桌面端版本比对提示（long-horizon 6.2 尾项）

- 构建桌面安装包（`cargo tauri build` 或 CI desktop job 产物）
- 安装并启动，连本机网关（4174）与远程网关两种模式
- 断言：遥测条呈现「壳版本 / GW 版本」双读数；版本差异时 toast 提示（本机=建议更新/远程=仅提示）；每会话一次不重复打扰
- 断连远程 → WS 指数退避重连（2/5/10/30s）+ 链路 LED 状态显示
