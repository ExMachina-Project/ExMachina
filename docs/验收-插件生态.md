## 2g. T2 进程工具会话面全线贯通（2026-10-29 第四轮）

demo 装得上但会话里调不了——沿「装配 → 注册 → 重建 → 执行 → 协议」五层逐层剥开，共 6 个缺陷（前轮 2 个 + 本轮 4 个），全部修复并端到端验证：

- **T2 工具从未接入 ToolGateway**（f400119）：进程插件握手发现的工具仅存管理面快照，`Core` 装配只回接 T1 声明式。ToolGateway 增 `plugin_runtime_tools` 注册面（specs 随 custom_specs_for 下发、执行转发 supervisor → 子进程）。
- **纯 process 清单被装载校验拒绝**（bf30836）：`has_any_capability` 不认 process 形态（工具握手后动态发现，清单天然无静态能力声明），补 `is_process()` 判定。
- **apply_config 重建丢 T2 注册**（bf30836）：配置热更新只回接 T1。提取 `rebind_plugin_tools`（T1+T2 统一回接）。
- **set_remote 重建丢 T2 注册——启动序列真凶**（ac0e8c6）：`serve()` 工作者池注入在 spawn_all 之后调 `set_remote` → `rebuild_orchestrator` 换新 ToolGateway，启动 attach 的注册随旧实例丢弃（「已并入」日志在而诊断 False 的根因）。rebuild 路径统一走 rebind；健康检查循环每轮幂等补注册兜底（5443651）。
- **同步调用在 worker 线程 block_on panic**（3ae8eaf）：`Cannot start a runtime from within a runtime`——改 `tokio::task::block_in_place` 包裹。
- **demo 插件 tools/call 响应缺 result 包裹**（598be18）：initialize/tools/list 有 `{"result":...}` 而 tools/call 返回裸 `{"content":...}`，宿主走错误路径报「工具 hello 错误：?」。
- **诊断面**：插件详情端点增 `toolsSnapshot`/`sessionToolSurface`/`toolSurfaceRegistered`（快照有但下发面无 = 装配断链，一眼定位）；attach 加结果日志。
- **回归测试**：`t2_tool_surface.rs` 集成测试（装载→拉起→注册→machina 下发面含 t2p__hello→apply_config 后仍在——曾精准复现容器内不可见）；tools.rs 单测（注册→下发→执行→未知工具→摘除）。

## 2f. 全功能巡检（2026-10-29 第三轮）

部署实例全功能面巡检（REST 全端点 + 主链路聊天 + WS + cron 全生命周期 + 记忆检索 + 会话分叉 + 插件端到端），发现并修复 4 个缺陷：

- **索引门槛版本误拒**：CLI/网关用 `version_newer`（严格高于）判 exmMin 门槛，min 与宿主相等时误拒（demo 0.5.3 = 宿主 0.5.3 装不上）。`version_ok` pub 化统一 ≥ 语义；版本不满足状态码 422→412（422 被 axum serde 拒绝改写中间件截获，错误文案被重写成「请求体字段有误」）。
- **工具审计面读侧错配**：`list_tool_audit_filtered` 用 `db.list()`（只扫 .json 文档）读 tool_audit，而写入是 `append_line` 的 `{agentId}.jsonl`——审计面（REST /api/audit 与 WebUI 活动页）永远返回空。FsDb 增 `list_all_lines()` 跨文件枚举追加日志行。
- **官方索引 demo 条目缺 ref**：git 源不带 ref 克隆默认分支 main（无 plugins/ 目录），报「仓库内未找到子目录」。索引条目补 `"ref": "dev"`。
- **索引拉取无重试**：raw.githubusercontent.com 在部分网络间歇超时（采样 4 次 3 次 000）。fetch_index 加 3 次尝试 + 递增退避。
- **进程插件工具装配缺口（重大）**：进程插件拉起握手成功后工具仅存管理面快照，从未并入 ToolGateway——会话里智能体看不到也调不了。ToolGateway 增 `plugin_runtime_tools` 注册面（specs 随 custom_specs_for 下发、执行转发 supervisor→子进程）；两处拉起调用方回接 `attach_process_tools`。
- **部署增强**：Dockerfile 运行时增 python3（进程插件运行前提）；插件列表端点附 toolsSnapshot + WebUI 进程形态「工具 ×N」标签；新增 `scripts/healthcheck.sh` 部署巡检脚本（26 项探测）。
- 验证：demo 从官方索引安装成功 → python3 进程拉起（握手协商）→ 会话内调用 `demo__hello` 端到端通（巡检 26/26）。
