> 四场景全链路：`cargo test -p exm-core --test e2e_scenarios`（mock 模式可重复执行）。
> ① ② 的 UI 层走查分别见 `docs/验收-CLI-TUI.md` 与 `docs/验收-WebUI工作台.md`。

## 场景与验证点

### ① CLI TUI 计划模式改代码全流程
- 开启 plan 模式 → 工具网关拦截 filesystem.write 转计划条目；read 放行（不转条目）
- 首条出现时 approvals 通道落 `[plan]` 审批单（复用既有通道）
- 批准（plan_approve）→ 切 execute → 清单按序回放 → 文件真实落地
- TUI 呈现：消息流 📋 计划行 + 状态栏 PLAN 位 + 审批页可见审批单（pty 冒烟覆盖界面层）
- **结果：PASS**（`场景1_计划模式改代码全流程`）

### ② WebUI 工作台远程改代码 + 回滚
- `workbench_file` 分页读取（read 工具同口径）
- edit 工具改文件（检查点在写前登记）→ chat 轮次收束（快照挂检查点链）
- `undo_session(turn-1, restore_files)` → 检查点恢复：文件内容回到改动前（line1 复现、LINE1 消失）
- WebUI 呈现：diff 卡 + 回滚按钮（调同一 undo 端点）
- **结果：PASS**（`场景2_工作台改代码与回滚`）

### ③ spawn 派生检索子任务
- 主会话经工具面调 spawn（task=检索关键字，tools=[grep, read]，timeoutSecs=60）
- 走 Core 装配的真实执行器：临时 AgentDefinition + 空历史 → chat_execute（独立上下文）
- mock 模型完成检索轮并返回结论
- 可观测：spawn.started / spawn.finished 事件进会话事件库（留痕断言通过）
- 并发上限与超时在单测覆盖（tools.rs spawn工具_并发上限拒绝 / _子任务超时终止）
- **结果：PASS**（`场景3_spawn派生检索子任务`）

### ④ 严格审批下 git commit
- risky 档 + approval_wait_secs=0：git add 与 git commit 均受阻回流、审批单落库
- 批准（按依赖序：add → commit）→ 系统代执行（approval_decide → execute_shell_command_timed）
- 审批单状态 executed；`git log` 断言提交真实存在
- **结果：PASS**（`场景4_严格审批下git提交`）
