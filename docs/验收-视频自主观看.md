## 三、互动闸门链（`video__act`，系统侧强制）

执行顺序（智能体无绕过路径）：

1. **开关**：`comment`/`reply` 未开启 → 拒绝并告知
2. **目标核验**：回复目标必须在本会话已见评论集合内（防编造 id）
3. **清洗**：`clean_comment`（字数上限 + Markdown/装饰符号剥离）；清洗后为空 → 拒绝
4. **配额**：当日动作数达 `dailyLimit` → 拒绝（轮次继续，可仅产出观感）
5. **dry-run**：开启时只记录拟发内容，不落平台
6. **审批**（`approval=always` 时）：产 `[video]` 前缀审批单（含拟发文本），轮询裁决——批准由系统代发（Core 回调网关注入的 `VideoActExecutor`）、拒绝记录跳过、超时本轮跳过
7. **buvid 养护**：B站发送前自动补齐指纹
8. **执行**：复用 `bili_post_comment` / `yt_post_comment`

## 四、会话注入与预算

- **会话级工具注入**（`ToolGateway::inject_session_tools`）：`video__*` 仅在观看会话（ChannelRun 会话 id 为键）可见可执行，普通会话不可见（凭据不外泄）；轮次收束/超时即清理。
- **步数预算**（`set_session_step_budget`）：通道 `maxWatchSteps`（默认 8，1–32）覆盖会话步数；**软着陆**——步数耗尽注入收束提示（「不要再调工具，基于已有材料给出最终结论」）再给一轮纯文本机会，不硬截断。
- **收束窗口**：300s → **600s**（多轮工具调用需要更长时间）。
- **token 预算**：沿用全局 `maxSessionTokens`（会话粒度闸门已覆盖观看会话；不重复造通道面配置）。

## 五、提示词（新 `build_prompt`）

任务框架：候选清单（限量投喂 = `maxActionsPerRun×2`）+ 工具用法 + 产出要求（观感/互动/可跳过）+ 内容倾向与评论风格（软偏好注入）+ 步数预算提示。不复述材料、不覆盖人格（SOUL 沿用 ChannelRun 既有路径）。
