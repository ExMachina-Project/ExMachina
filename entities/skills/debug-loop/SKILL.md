id: debug-loop
name: 系统化调试
description: 假设驱动的调试循环：复现 → 定位 → 假设 → 最小验证 → 修复
triggers: [调试, debug, 排查, 不工作, 报错, 失败原因, 为什么报错]
---

禁止「猜测式修复」（随机改代码碰运气）。按循环推进：
1. **完整读错误**：错误信息与堆栈逐行读完，提取文件:行号与错误类型。
2. **复现**：找到最小复现路径（命令/输入）；不可复现时先明确复现条件。
3. **定位**：read 报错位置的代码 + grep 调用方；理解数据流与作用域。
4. **假设**：提出最可能的 1-2 个原因，按可能性排序。
5. **最小验证**：每个假设用最小代价验证（加日志 / 断点 / 二分注释），一次只验证一个。
6. **修复后回归**：跑相关测试 + 复现原命令确认修复。
证据不足时回到步骤 3。输出时明确标注当前处于哪一步、验证了什么假设。
