# Spec Delta

## Purpose

通道用户身份与访问治理：把"白名单即全权"细化为可审计的用户身份、角色与群聊唤醒门控，使外部通道接入达到可运营的权限粒度。

## ADDED Requirements

### Requirement: 配对码绑定

系统 SHALL 提供一次性、限时的配对码：管理员在控制台签发，外部用户在通道内提交配对码后，其通道账号身份与用户档案绑定并获派角色。配对码 MUST 单次有效并有过期时间；过期或已用的配对码 MUST 拒绝绑定。

#### Scenario: 成功配对

- **WHEN** 用户在通道内发送有效且未过期的配对码
- **THEN** 该通道账号完成绑定并收到确认与所获角色说明

#### Scenario: 配对码过期

- **WHEN** 用户提交已过期的配对码
- **THEN** 绑定被拒绝，提示码已失效，需管理员重新签发

### Requirement: 角色权限裁决

已绑定用户 SHALL 携带角色（admin/member）参与运行时裁决：审批类操作（破坏性命令、越权工具、computer 动作）由 admin 批准可放行，member 触发升级或拒绝；未绑定用户在启用身份管控的通道 MUST 被拒绝执行并收到配对指引。身份管控未启用时 MUST 维持现有白名单行为。

#### Scenario: member 触发破坏性命令

- **WHEN** member 角色用户触发破坏性命令审批
- **THEN** 审批请求升级至管理员（控制台或 admin 通道），member 收到等待说明

#### Scenario: 未绑定用户被拒

- **WHEN** 身份管控启用且未绑定用户发送执行类消息
- **THEN** 请求被拒绝，回复包含如何获取配对码的指引，不产生任何工具执行

### Requirement: 群聊唤醒门控

系统 SHALL 提供群聊唤醒门控：群内消息仅在被提及（@智能体）或回复其消息时触发执行；白名单内的私聊不受门控。门控 MUST 支持按通道配置关闭以保持现有行为，默认值 MUST 在配置中显式可查。

#### Scenario: 未提及不触发

- **WHEN** 群内消息未提及智能体且非回复其消息
- **THEN** 不触发任何会话处理，不计入用量

#### Scenario: 提及触发

- **WHEN** 群内消息 @提及智能体
- **THEN** 消息进入会话处理，提及部分从正文剥离

#### Scenario: 私聊不受门控

- **WHEN** 白名单内用户私聊智能体且门控开启
- **THEN** 消息照常触发处理
