# Spec Delta

## Purpose

编码工作流闭环：让智能体与用户在 WebUI 内完成"生成补丁 → 审阅工作区差异 → 修正 → 版本化"的完整循环，无需离开平台。

## ADDED Requirements

### Requirement: Patch 应用工具

系统 SHALL 提供 `patch` 工具，接收统一 diff 格式补丁并原子应用到工作区文件。应用前 MUST 校验每个目标文件存在且上下文行匹配；任一目标校验失败时 MUST 整体拒绝应用并返回逐文件冲突报告，所有文件保持不变。应用成功 MUST 触发写前检查点。

#### Scenario: 校验失败整体拒绝

- **WHEN** 补丁中第二个目标文件的上下文行与工作区内容不匹配
- **THEN** 不写入任何文件，工具返回冲突报告（逐文件列出失败原因），第一个目标文件内容不变

#### Scenario: 成功应用并留检查点

- **WHEN** 补丁对三个文件的全部上下文行校验通过
- **THEN** 三个文件按补丁顺序原子更新，检查点记录全部变更，工具返回逐文件结果摘要

### Requirement: 工作区变更对比

系统 SHALL 提供工作区级变更视图，展示相对基线（当前版本控制 HEAD 或指定检查点）的变更文件清单与逐文件差异。清单 MUST 来源于版本控制状态或检查点记录，MUST NOT 以命令轨迹推断充当。工作区不是版本控制仓库时 MUST 回退为检查点口径并明确标注来源。

#### Scenario: 基于版本控制的变更清单

- **WHEN** 用户在编码工作台打开变更视图且工作区为 git 仓库
- **THEN** 展示相对 HEAD 的修改/新增/删除文件清单，点开任一文件可见逐行差异

#### Scenario: 非版本控制仓库回退

- **WHEN** 工作区未初始化版本控制
- **THEN** 变更视图展示自最近检查点以来被写类工具触碰的文件，并标注"检查点口径"

### Requirement: 文件编辑与保存

WebUI SHALL 支持在编码工作台内编辑并保存工作区文件。保存 MUST 受路径沙箱约束（与工具同口径），写入前 MUST 落检查点并计入工具审计；越界路径 MUST 拒绝。

#### Scenario: 保存受沙箱约束

- **WHEN** 用户保存位于组工作区内的文件
- **THEN** 内容写入成功，生成检查点，变更视图与文件树刷新

#### Scenario: 越界拒绝

- **WHEN** 用户尝试保存组工作区之外的路径
- **THEN** 保存被拒绝并提示越界原因，文件内容不变

### Requirement: Git 面板

WebUI SHALL 提供 git 面板：查看仓库状态、最近提交日志、分支清单，并执行暂存、取消暂存、提交、切换分支。破坏性操作（推送、硬重置、丢弃工作区改动）MUST 经既有审批闸门；命令执行 MUST 复用终端白名单与沙箱口径。

#### Scenario: 常规操作直接执行

- **WHEN** 用户执行暂存并提交
- **THEN** 操作经白名单通道完成，面板刷新状态与日志

#### Scenario: 破坏性操作需审批

- **WHEN** 用户发起硬重置
- **THEN** 弹出既有审批卡，批准后方才执行，拒绝则工作区不变
