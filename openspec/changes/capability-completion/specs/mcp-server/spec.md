# Spec Delta

## Purpose

工具面对外暴露：让外部 MCP 客户端（其他智能体框架、脚本、IDE）能够以标准协议复用本平台的工具面，同时不绕过任何内部安全口径。

## ADDED Requirements

### Requirement: MCP 服务暴露

系统 SHALL 支持以 MCP 服务端模式对外暴露启用的内置工具（stdio 子进程方式与挂载于网关的 HTTP 方式）。暴露范围 MUST 由 ACL 控制（允许的组、会话范围与工具清单），未授权范围 MUST 对客户端不可见（不进入工具清单）。该模式 MUST 默认关闭。

#### Scenario: ACL 约束可见性

- **WHEN** 客户端以限定组范围的授权连接
- **THEN** 工具清单仅含该范围授权的工具，范围外工具不可见亦不可调用

#### Scenario: 默认关闭

- **WHEN** 配置未启用服务端模式
- **THEN** stdio 子命令与 HTTP 挂载点均不可用

### Requirement: 外部调用安全口径一致

外部客户端的工具调用 MUST 与内部执行同路径：路径沙箱、审批闸门、工具审计、速率限制全部生效；审计记录 MUST 标注来源为 MCP 服务端及客户端身份。

#### Scenario: 审批在外部调用下生效

- **WHEN** 外部客户端调用破坏性命令类工具
- **THEN** 请求进入既有审批流程，批准前调用阻塞，拒绝则返回错误

#### Scenario: 审计可归因

- **WHEN** 外部客户端完成任一工具调用
- **THEN** 审计记录包含调用来源标识与客户端身份，可与内部调用区分

### Requirement: 会话上下文亲和

携带有效会话标识的调用 SHALL 在该会话的工作区与组上下文中执行；标识缺失或无效时 MUST 拒绝执行并返回可读错误。

#### Scenario: 会话亲和执行

- **WHEN** 客户端携带有效会话标识调用文件写入工具
- **THEN** 写入发生在该会话组的工作区内，产物对该会话后续处理可见

#### Scenario: 无效标识拒绝

- **WHEN** 调用携带不存在或已关闭的会话标识
- **THEN** 调用被拒绝，返回明确错误，不产生任何执行副作用
