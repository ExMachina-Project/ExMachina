# Spec Delta

## Purpose

用量治理：为主体（通道账号/绑定用户/API key）提供速率限制与周期配额，防止单一来源耗尽预算或模型限额，管理面可见可调。

## ADDED Requirements

### Requirement: 多维速率限制

系统 SHALL 对请求主体（通道账号、绑定用户、API key 三类维度键）实施独立配置的速率限制：超过阈值的请求 MUST 被拒绝并返回包含重试提示的可读错误；拒绝 MUST 产生可观测事件；未配置阈值的维度 MUST 不限流（维持现状）。

#### Scenario: 超频拒绝

- **WHEN** 某通道账号在限制窗口内的请求数超过其阈值
- **THEN** 后续请求被拒绝，回复包含等待时长提示，产生限流事件

#### Scenario: 维度独立

- **WHEN** 用户 A 被限流而用户 B 未达阈值
- **THEN** 用户 B 的请求正常处理，互不影响

### Requirement: 周期配额

系统 SHALL 支持按主体的周期性配额（token 用量与请求数，周期可配置）：配额耗尽后 MUST 暂停该主体发起新会话与新轮次；进行中任务的处理策略（立即中断/完成当前）MUST 可配置。配额口径 MUST 复用既有 token 台账。

#### Scenario: 配额耗尽暂停

- **WHEN** 某主体当期 token 配额耗尽后发起新对话
- **THEN** 请求被拒绝并提示配额恢复时间，不产生模型调用

#### Scenario: 进行中任务按策略处理

- **WHEN** 配额耗尽时该主体存在进行中的任务且策略为"完成当前"
- **THEN** 该任务继续至完成，期间不接受新的轮次

### Requirement: 用量管理可见性

管理员 SHALL 可在控制台查看各主体的实时计数、配置阈值与周期余量，并调整限流/配额配置；配置变更 MUST 即时生效（无需重启网关）。

#### Scenario: 控制台调整阈值

- **WHEN** 管理员将某用户配额上调并保存
- **THEN** 新阈值即时生效，该用户随后的请求按新额度放行
