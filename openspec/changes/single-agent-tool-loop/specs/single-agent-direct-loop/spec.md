# Spec Delta

## Purpose

定义单体智能体的直接工具循环执行能力:单体对话轮内,系统以「职责提示词 + SOUL 人格 + 会话历史 + 个体工具面」驱动一个自主工具循环,直至产出最终文本回复。单体不产出 OrchestratorPlan/SyncReport,不感知派发语义。

## ADDED Requirements

### Requirement: 单体对话走直接工具循环

单体模式下,用户消息触发的一轮对话 MUST 以直接工具循环执行:系统提示 = 单体职责提示词 + SOUL 人格;上下文 = 会话历史窗口 + 本轮用户输入;执行 = 迭代式工具调用直至模型产出不含工具调用的最终文本。

#### Scenario: 纯问答不走工具
- **WHEN** 用户发送「用一句话介绍你自己」且无需任何工具
- **THEN** 本轮产出单条最终文本回复,且不产生任何工具调用记录

#### Scenario: 工具任务循环执行
- **WHEN** 用户要求「查看当前目录并总结文件构成」
- **THEN** 本轮可产生一次或多次工具调用与结果回灌,并在循环内收敛出最终文本回复

#### Scenario: 单体轮次不产生任务图
- **WHEN** 单体模式完成任意一轮对话
- **THEN** 不创建 OrchestratorPlan、任务图或节点派发记录;最终回复归属该单体智能体

### Requirement: 会话历史窗口化注入

直接循环 MUST 将存储中的最近会话消息映射为对话上下文(用户消息 → user, orchestrator 消息 → assistant),并 MUST 限制窗口大小以防上下文溢出;窗口外的更早历史不注入。

#### Scenario: 多轮上下文延续
- **WHEN** 用户在既有会话中追问「把刚才的结论写成文件」
- **THEN** 模型可见此前轮次内容,并能基于其执行工具完成任务

#### Scenario: 超长会话窗口收敛
- **WHEN** 会话消息数超过窗口上限
- **THEN** 仅注入最近窗口内的消息,本轮正常完成

### Requirement: 单体工具面按个体定义下发

直接循环的工具面 MUST 由该单体定义的 allowlist、对其可见的自定义工具与 MCP 工具组成;不在白名单内的工具调用 MUST 被拒绝并回灌为错误反馈。

#### Scenario: 白名单外工具被拒
- **WHEN** 模型调用一个不在该单体 allowlist 内的内置工具
- **THEN** 该调用被拒绝,错误反馈回灌循环,执行不中断

#### Scenario: 只读并发与写串行
- **WHEN** 单轮产生多个工具调用
- **THEN** 只读工具并发执行,写工具按序串行,结果按调用顺序回灌

### Requirement: 过程可观测与停止检查点

直接循环 MUST 与现有过程体验对齐:思考增量走思维轨、最终文本走可见正文;每轮结束留存思维链与工具调用轨迹及 token 用量;会话被请求停止后 MUST 在检查点终止,不再发起新的模型调用或工具执行。

#### Scenario: 停止后快速终止
- **WHEN** 循环执行中用户请求停止本轮
- **THEN** 循环在最近检查点终止,已产生的部分过程留痕,不再有新的模型或工具调用

#### Scenario: 过程与用量留痕
- **WHEN** 一轮直接执行完成
- **THEN** 最终消息附带思维链与工具调用轨迹,token 用量计入该会话统计

### Requirement: 高风险工具纪律与审批闸门沿用

直接循环中的工具执行 MUST 沿用既有安全纪律:高危命令拦截、审批等待与结果回灌、环境净化与联网闸门均与子个体执行路径一致。

#### Scenario: 高危命令触发既有闸门
- **WHEN** 单体在循环中调用被安全策略拦截的命令
- **THEN** 按既有闸门语义处理(拦截或等待审批),与子个体执行路径行为一致
