# Design

## Context

能力补齐后的平台：对话/编成/通道/自动化/治理功能面完整，且刚经历一轮实测（本变更的动机全部来自实测与代码巡检的一手证据）。技术基座：消息为 append-only JSONL（`messages/{sessionId}.jsonl`），思维链/工具轨迹目前仅在浏览器会话内组装（`run.finished` 时并入客户端消息对象，服务端 `ChatMessage` 无此字段）；工具循环在 `AgentRuntime` 逐调用执行，无外部取消通道；工具审计已落 `tool_audit/{agentId}.jsonl`；限流统计已有 `GET /api/limits/stats`；各通道适配器已有凭据与发送闭包。

## Goals / Non-Goals

**Goals:**
- 过程数据（思维链/工具轨迹）服务端留存，刷新/换端可回看
- 任意运行中轮次可被用户停止，且有审计痕迹
- 管理员无需调 API 即可查看工具审计与用量统计
- 通道与定时任务「配置即可验证、执行前可预知」
- 会话列表可搜索、可区分通道会话、可导出带走

**Non-Goals:**
- 多用户/角色体系与细粒度权限（沿用 authKey 单密钥口径）
- Web Push 通知（另行评估）
- 思维链的跨会话全局检索
- 停止能力的节点级精细化（仅到「轮次级 + 工具循环检查点」粒度）

## Decisions

**D1 过程数据随消息落盘（扩展现有消息形态，不建新集合）**
`ChatMessage` 增加可选 `thinking: String` 与 `tool_calls: Vec<ToolCallItem>` 字段（serde default，旧数据零迁移）。收束路径（run.finished 组装处）由服务端把本轮思维链与工具轨迹写入最终消息（此前仅客户端组装）。读取接口自然携带，前端收起栏直接渲染历史数据。备选「独立过程集合 + 按消息 id 关联」被否：多一次查询、生命周期与消息不同步。

**D2 停止轮次 = 会话级取消令牌 + 工具循环检查点**
Core 维护 `session_cancel: HashMap<sessionId, CancellationToken>`（chat 开始创建、结束移除）。工具循环每步执行前与每个工具调用完成后检查令牌；触发即终止本轮并以系统消息落「本轮已被用户停止（已执行 N 次工具）」+ 审计事件。派发中的子节点由调度器现有错误路径自然收敛（取消令牌同样注入 ExecCtx 检查）。REST `POST /api/sessions/:id/stop`；通道 `/stop` 指令复用同端点。空闲会话返回明确错误。备选「kill 子任务树」被否：粒度过粗且与既有后台任务机制冲突。

**D3 工具审计页复用既有存储，只读视图**
新增 `GET /api/audit?agent=&tool=&from=&to=&limit=`（聚合各个体审计分片，服务端过滤），前端在事件页（ActivityView）增加「工具审计」标签页，不做独立页面。写入路径零改动。

**D4 用量面板回归 = 消费既有 stats 接口**
`GET /api/limits/stats` 已返回快照与口径，设置页恢复用量分类（此前删除的 LimitsPanel 以精简形态重做：启用状态、口径、主体计数表），不做服务端改动。

**D5 通道连通测试探针按平台分发**
`GET /api/channels/:id/test`（POST 语义为触发，用 GET 便于卡片按钮）：逐平台实现轻量只读探针——telegram `getMe`、discord `GET /users/@me`、slack `auth.test`、napcat `getLoginInfo`、qqbot `GET /users/@me`、matrix `whoami`、webhook 类返回「无平台探针，仅回显配置」；结果分类 ok / 凭证无效 / 凭证缺失 / 网络不可达。探针只读，不发送任何消息。

**D6 cron 下次执行时间：复用既有五段匹配器**
以 `cron::cron_matches` 从当前分钟起向前逐分钟扫描（上限 366 天命中即返回）， avoiding 引入 cron 解析新依赖。模板 = 前端静态清单（每日 9 点 / 工作日 9 点 / 每小时 / 每周一），纯 UI 填充。

**D7 会话导出 = 前端生成 Markdown**
消息、工具轨迹、思维链均已在会话消息接口可用，前端遍历组装 Markdown 并触发浏览器下载（Blob）。不做服务端导出端点。channel 会话标识：标题 `channel:<通道id>:<键>` 前缀解析 + 通道清单反查平台名，过滤为纯前端状态。

**D8 `/stop` 指令在通道入站闸门层拦截**
在 `admit` 闸门最前（先于配对/门控/身份校验——停止自己会话的优先级最高，且无需绑定身份即可中止自己触发的轮次）识别 `/stop`，取该通道会话键对应的会话执行停止并回执。

## Risks / Trade-offs

- [消息新增可选字段] → serde default 兼容旧数据；前端类型同步；无迁移
- [取消令牌的检查点粒度] → 长时间 LLM 调用中的取消只能等当前调用返回（单次调用不中断）；文档如实标注
- [逐分钟扫描算 cron 下次执行] → 最坏 366 天 × 1440 分钟的匹配调用；五段匹配为纯算术，单次微秒级，可接受
- [通道探针的平台差异] → 每平台独立实现，新增平台须同步探针；测试与运行状态解耦，误报不产生影响
- [`/stop` 免身份校验] → 仅能停止该通道会话自身运行中的轮次，无越权面；白名单外会话仍受既有闸门约束

## Migration Plan

1. 消息字段为 serde default 的新增，旧会话消息读取零影响
2. 停止端点/探针/审计聚合均为新增端点，不改既有契约
3. 回滚 = 配置回退 + 镜像回退，无数据不可逆操作
