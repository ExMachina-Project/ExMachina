# Spec Delta

## Purpose

接入与自动化易用性：配置后能「一键验证」、执行前能「预知何时」——通道连通测试、cron 下次执行时间与常用模板、通道内 `/stop` 停止指令。

## ADDED Requirements

### Requirement: 通道连通测试

每个通道卡片 SHALL 提供连通测试操作：按平台语义向平台侧发起一次轻量只读校验（如取机器人身份、校验令牌），返回成功状态与平台侧标识，或返回明确的失败原因（凭证/网络/配置缺失分类）；测试不影响通道的运行状态。

#### Scenario: 凭证有效

- **WHEN** 用户对凭证正确的通道执行连通测试
- **THEN** 返回成功与平台侧身份标识（如机器人用户名）

#### Scenario: 凭证无效或缺失

- **WHEN** 凭证错误或未配置时执行测试
- **THEN** 返回失败并给出分类原因（凭证无效 / 凭证缺失 / 网络不可达）

### Requirement: cron 下次执行时间与模板

定时任务列表 SHALL 为每个启用任务显示下次执行时间（按任务时区口径计算最近一次命中）；新建/编辑任务 SHALL 提供常用 cron 模板（每日、工作日、每小时等）一键填入。

#### Scenario: 查看下次执行

- **WHEN** 启用的 cron 任务在列表中展示
- **THEN** 显示按当前时间计算的最近一次命中时间

#### Scenario: 模板填入

- **WHEN** 用户在新建任务时选择某个 cron 模板
- **THEN** 表达式字段被模板值填充，可继续手工调整

### Requirement: 通道内停止指令

通道会话（Telegram/QQ 等）SHALL 支持 `/stop` 指令：该指令不经模型执行，直接停止该通道会话当前运行中的轮次并回执确认；无运行中轮次时回执提示。

#### Scenario: 通道内停止

- **WHEN** 通道会话存在运行中轮次且用户发送 `/stop`
- **THEN** 当前轮次终止，通道收到停止确认回执

#### Scenario: 通道内无任务可停

- **WHEN** 通道会话空闲时用户发送 `/stop`
- **THEN** 通道收到「当前无运行中任务」回执
