# coding-agent-loop Specification

## Purpose
单智能体编程执行循环：会话压缩、工具步数、token 预算与流式输出的行为契约，使单个智能体在不经组调度时具备完整编程助手能力。

## Requirements

### Requirement: 单智能体会话滚动压缩
单智能体会话历史超过压缩阈值时，系统 MUST 将更早历史压缩为滚动摘要并保留最近窗口原文，且压缩口径与组调度会话一致（同一压缩器、同一窗口规则）。压缩 MUST 增量进行：已有摘要与新纳入的旧消息合并为新摘要，不重复压缩已压缩内容。压缩失败时 MUST 沿用旧摘要继续对话，不得中断会话。

#### Scenario: 历史超阈值触发压缩
- **WHEN** 单智能体会话消息数超过压缩阈值且新消息到达
- **THEN** 系统将阈值之前的旧消息并入滚动摘要，最近窗口消息保留原文注入上下文

#### Scenario: 压缩服务失败不阻断对话
- **WHEN** 压缩调用失败（模型超时或返回异常）
- **THEN** 会话继续使用旧摘要与最近窗口原文，用户无感知中断

### Requirement: 工具循环步数可配
单智能体工具循环默认步数上限为 24，个体定义与全局配置 MUST 支持覆盖该上限。达到上限时系统 MUST 以明确错误终止循环并向用户说明已执行步数与未完成原因，不得静默截断。

#### Scenario: 个体覆盖步数上限
- **WHEN** 个体定义将步数上限设为 48 且该个体连续调用工具
- **THEN** 循环允许最多 48 步工具调用

#### Scenario: 步数耗尽提示
- **WHEN** 工具循环达到步数上限仍未产出最终答复
- **THEN** 系统返回错误说明"已达最大工具步数 N"，并列出已完成的工具调用清单

### Requirement: 会话 token 预算软着陆
单智能体会话 MUST 维护 token 预算：上下文组装时若估算 token 超出模型窗口安全余量，系统 MUST 优先压缩历史、其次裁剪注入块（记忆/技能/统计），最后才截断最长消息。任何裁剪 MUST 在会话事件流中留痕（记录被裁剪的块与量级）。

#### Scenario: 超预算触发历史压缩
- **WHEN** 会话上下文估算 token 超过模型窗口的 80%
- **THEN** 系统先触发滚动压缩降低历史体积，注入块保持完整

#### Scenario: 多级裁剪留痕
- **WHEN** 压缩后仍超预算
- **THEN** 系统按注入块优先级依次裁剪，且每个被裁剪的块在会话事件流中留有记录
