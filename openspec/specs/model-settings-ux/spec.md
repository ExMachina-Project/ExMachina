# model-settings-ux Specification

## Purpose
模型设置页的体验基线：提供商档案化展示、模型能力徽章、连通性测试即时反馈与分节编辑表单，让模型配置可读可验证。

## Requirements

### Requirement: 提供商档案化展示
模型设置页 SHALL 以「连接档案」呈现每个提供商：卡头 MUST 一目了然的名称、协议标签、启用状态与「当前使用」标记；卡体 MUST 展示默认模型、端点、密钥池健康（可用密钥数 / 总数，脱敏不显示明文）、模型清单条数。关键状态 MUST 无需进入编辑表单即可见。

#### Scenario: 密钥池健康一眼可见
- **WHEN** 某提供商配置了 3 个密钥
- **THEN** 档案卡显示「密钥 3」状态位；密钥数为 0 时显示警示态（空密钥意味着该档案不可用）

#### Scenario: 默认模型识别
- **WHEN** 档案卡未配置默认模型但模型清单非空
- **THEN** 卡体明示「未设默认」提示态而非空白

### Requirement: 模型能力徽章
档案卡与编辑表单 SHALL 展示模型能力徽章：视觉（图片输入）、工具调用、嵌入、语音（转写 / 合成）——能力来源 MUST 标注（探测 / 手工指定），探测失败 MUST 与不支持区分展示。

#### Scenario: 能力徽章渲染
- **WHEN** 某模型经连通性测试探测出支持视觉与工具调用
- **THEN** 该模型条目旁显示「视觉」「工具」徽章；未探测的模型不显示徽章（而非显示空徽章）

### Requirement: 连通性测试反馈
连通性测试 SHALL 内联展示在档案卡：上次测试时间、延迟（毫秒）、结论（通过 / 失败原因摘要）。测试进行中 MUST 有加载态；失败 MUST 保留上次成功记录并显示当前失败原因。测试结果在页面刷新后 SHOULD 保留（本地留存即可）。

#### Scenario: 测试失败反馈
- **WHEN** 用户对某档案发起连通性测试且端点不可达
- **THEN** 卡片显示失败原因摘要与耗时，不弹全局错误打断其他操作

### Requirement: 编辑表单分节
提供商编辑表单 SHALL 按认知负荷分节：基础（名称 / 协议 / 端点 / 预设）常驻；密钥池独立小节（增删 / 掩码 / 三态语义说明）；模型清单独立小节；高级项（能力覆盖 / 轮转策略）默认折叠。表单 MUST 在窄屏（< 768px）下单列排布不溢出。

#### Scenario: 折叠高级项
- **WHEN** 用户打开编辑表单
- **THEN** 高级小节默认收起，展开后内容完整可达
