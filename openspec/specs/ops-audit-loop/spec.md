# ops-audit-loop Specification

## Purpose
运维审计闭环：以子代理对生产环境的真实交互（REST 走查、健康检查、文档对照）为缺陷发现源，经主智能体复核分级后驱动修复批次。审计本身是可重复的运维能力，不是一次性动作。

## Requirements

### Requirement: 审计执行

系统 MUST 支持派发独立子代理对运行中的生产环境执行审计：子代理以真实用户身份通过 REST API 与系统交互（读操作自由、写操作限 `audit-` 前缀测试资源且用后即删），并对照代码库与文档找漂移。审计过程 MUST NOT 破坏生产数据（配置、生产会话、出厂技能、历史审批单）。

#### Scenario: 只读走查
- **WHEN** 子代理审计一个生产环境
- **THEN** 它通过公开 REST 端点完成全部只读检查（个体/会话/技能/通道/cron/审批/版本面），不产生配置变更

#### Scenario: 测试资源自清理
- **WHEN** 子代理创建 `audit-` 前缀的测试会话或技能
- **THEN** 审计结束前这些资源被删除，环境回到审计前状态

### Requirement: 发现分级

审计产出 MUST 按严重度分级：P0（崩溃/数据错误/安全）、P1（功能缺陷）、P2（不一致/文档漂移），另列未完成功能清单与审计通过项。每条 P0/P1 发现 MUST 含复现步骤（可执行的请求或命令）与预期/实际对照。主智能体 MUST 复核子代理报告后才能进入修复——不可直接采信。

#### Scenario: 报告复核
- **WHEN** 子代理提交审计报告
- **THEN** 主智能体逐条复现或复核 P0/P1 项，确认属实才纳入修复批次；误报项标记排除并留痕

#### Scenario: 发现不可复现
- **WHEN** 某条 P0/P1 发现无法复现或依赖已失效的前提
- **THEN** 该项从修复批次剔除，报告归档时保留原文与排除理由

### Requirement: 修复批次收敛

已复核的发现 MUST 收敛为带验收口径的修复任务：每条任务指明复现路径、修复口径与验证方式（回归测试或生产验证步骤）。已知环境类开口项（通道验收依赖、镜像依赖缺失、历史审批单处置）MUST 在批次中显式处置——修复、挂起带理由或交用户决策，不得静默遗漏。

#### Scenario: 容器依赖缺失处置
- **WHEN** 审计确认终端白名单允许的工具（如 ffmpeg）在容器镜像中未安装导致链路失败
- **THEN** 该项进入修复批次：镜像补齐依赖 + 容器内验证工具可用 + 失败链路重验

#### Scenario: 用户决策项
- **WHEN** 某开口项的处置需要用户选择（如是否启用生产通道做验收）
- **THEN** 任务标记为待决策并给出选项，不阻塞其余修复任务推进
