# plugin-process-bridge Specification

## Purpose
进程插件桥：第三方插件以独立进程（任意语言）运行，经 stdio JSON-RPC 与宿主通信——协议定义、进程生命周期管理（启动/崩溃重启/关闭回收）与健康检查。

## Requirements

### Requirement: 进程插件声明与启动

清单声明 `process` 字段（可执行命令 + 参数 + 环境变量）时插件为进程形态。宿主 MUST 按声明拉起子进程，经 stdin/stdout 行分隔 JSON-RPC 通信，stderr 透传到宿主日志。首次启动 MUST 完成 initialize 握手（协议版本、能力协商、插件身份）后才进入可用状态。

握手响应中插件可声明 `serverInfo.exmMin`（其所需的最低宿主版本）；宿主 MUST 校验，不满足时拒绝装载并报明确错误（含两侧版本）。握手成功后宿主 SHALL 立即请求 tools/list 并将结果作为该插件的能力面真值（工具清单与健康在装载期即确定，不待首次调用）。

#### Scenario: 握手成功进入可用
- **WHEN** 进程插件被拉起且在超时内完成 initialize 握手
- **THEN** 插件状态为运行中，其能力面（经 tools/list 等发现）注册进系统

#### Scenario: 握手超时判失败
- **WHEN** 子进程启动后未在配置超时内完成握手
- **THEN** 判定启动失败，进程被回收，插件状态为错误并诊断记录

#### Scenario: 握手声明宿主版本不满足
- **WHEN** 握手响应 serverInfo.exmMin 高于当前宿主版本
- **THEN** 插件拒绝装载，错误信息含宿主与插件两侧版本

#### Scenario: 装载期能力快照
- **WHEN** 握手成功后宿主请求 tools/list
- **THEN** 插件详情与健康信息在装载期即展示完整工具清单，无需等待任何工具调用

### Requirement: 工具调用协议

进程插件工具调用走 `tools/call`（请求带调用 id、工具名、参数 JSON；响应带结果或错误）。协议对齐 MCP 工具子集语义：结果为内容块数组（文本/图片），错误含可读消息。请求超时与进程无响应由宿主侧判定并返回工具错误（不悬挂调用方）。

#### Scenario: 正常调用往返
- **WHEN** 模型调用进程插件工具，插件在超时内返回结果
- **THEN** 工具结果（含文本与图片内容块）原样进入会话，与内置工具呈现一致

#### Scenario: 进程无响应返回错误
- **WHEN** tools/call 超时未收到响应
- **THEN** 会话收到明确的工具超时错误，进程按健康检查策略处理，调用方不悬挂

### Requirement: watcher 协议通知

watch 能力的进程插件收到宿主 `watcher.tick` 通知（含通道上下文与配置快照），可返回动作结果或空。通知与工具调用共用同一进程连接，串行处理。

#### Scenario: 轮询通知触发插件逻辑
- **WHEN** 宿主按插件清单的轮询声明发出 watcher.tick
- **THEN** 插件在该轮内完成自主逻辑并返回结果摘要，宿主记录到状态面板

### Requirement: 进程生命周期管理

宿主管理子进程全生命周期：崩溃自动重启（指数退避，连续失败达上限后置为错误状态待人工干预）、宿主关闭时优雅终止（先发 shutdown 请求，超时 SIGTERM）。插件禁用同样触发优雅终止。

#### Scenario: 崩溃自动重启
- **WHEN** 插件进程意外退出且插件为启用状态
- **THEN** 宿主按退避策略自动重启；连续失败达上限后停止重试并标记错误

#### Scenario: 宿主关闭优雅回收
- **WHEN** 宿主正常关闭
- **THEN** 所有插件子进程收到 shutdown 并在宽限期内退出；未退出的被 SIGTERM，无孤儿进程

### Requirement: 凭据与配置下发

通道凭据与通道配置（config 键值）在握手后由宿主经 `config/set` 下发给进程插件；凭据不落进程侧持久文件。配置变更时重新下发。

#### Scenario: 凭据不落盘
- **WHEN** 插件收到含凭据的 config/set
- **THEN** 凭据仅存在于进程内存；宿主日志与诊断输出对凭据脱敏
